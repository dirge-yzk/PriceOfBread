# 1. ★★★ 診断（2026-08-12・現物）

## 1-1. 港の配線は「構築時に1回だけ」

```
WirePortDistances()   Simulation の BuildRegions 内        ★構築時に1回だけ
WireTransitPorts()    MultiNationSim のセットアップ内       ★構築時に1回だけ
Diplomacy.cs で NearestPortName / PortLandKm を触る行       ⚠ 0件（grep 全数確認）
```

★ この2つが `Region` に書く静的値：

| 項目 | 意味 |
|---|---|
| `NearestPortName` | ★**自国の**最寄り港州の名前 |
| `NearestPortDistanceKm` | ★大圏距離 |
| `PortLandKm` | ★陸グラフの最短路（山脈迂回込み） |
| `SeaBasin` | ★内陸州は最寄り港の海盆を継承（⚠ キエフ→ロストフ＝黒海勢が自動で出る） |
| `TransitPortName` / `TransitPort2Name` | ★**外国の**港州（⚠ **開幕に港州0の国だけ**に配線される） |

## 1-2. ★★★ 交易側は所有を確認しない

```csharp
BilateralMarket（内陸州の海の口を決める箇所）
    if (!r.IsPort && r.NearestPortName.Length > 0)
    {
        var pc = Climate.CityCoord(r.NearestPortName);   // ★名前で座標を引くだけ
        if (pc.Lat != 0 || pc.Lon != 0) { lat = pc.Lat; lon = pc.Lon; landKm = r.PortLandKm; linked = true; }
    }
```

⚠ **所有チェックが無い。**★ 対照的に、**通過港の側には所有チェックと交戦チェックが両方ある**：

```csharp
    else if (transitOn && !r.IsPort && r.TransitPortName.Length > 0)
        ...
        if (!transitPortOwner.TryGetValue(tName, out int oi)) continue;      // ★所有を引く
        if (oi != i && ... dT.IsAtWar(spT, opT)) continue;                   // ★交戦中の港は通れない
```

★★★ **つまり「他国の港を借りる」経路だけが正しく実装され、「自国の港を使う」経路は所有を見ていない。**

## 1-3. ⚠ 3つの症状

| # | 症状 | 帰結 |
|---|---|---|
| **S1** | ★**港を失った国**の内陸州は `NearestPortName` が**失った港を指したまま** | ⚠⚠ **敵に渡した港からそのまま輸出し続ける**＝**割譲が無痛** |
| **S2** | ★**港を得た国**の既存内陸州は `NearestPortName` が**古いまま** | ⚠ もっと近い港を手に入れても切り替わらない＝**征服の利得が出ない** |
| **S3** | ★**割譲された州**は `NearestPortName` が**旧宗主の港**を指したまま | ⚠ 併合した州が敵国の港経由で交易する |

⚠ **`SeaBasin` も同じ**——★ 内陸州は最寄り港の海盆を継承するので、**海盆まで古いまま**引き継がれる（封鎖・冬季閉鎖の判定が誤る）。

## 1-4. ★★ そして落ちる先が無い

```csharp
WireTransitPorts()
    if (hasPort[i]) continue;   // ★港のある国は既存の自国港3脚が担う
```

⚠ **開幕に港を持つ国には `TransitPortName` が配線されない。**
★★★ **したがって、もし S1 を直しただけなら、港を全部失った国は交易から完全に脱落する**（`linked = false`）。

⚠ **S1 の是正と通過港の再配線は、必ず同時に入れなければならない。**

# 2. ★ なぜこうなったか（★ 責めるためでなく、同じ轍を踏まないため）

★ 構築時静的にしたのは**意図的**である：

```
「Region.TransitPort*＝構築時静的の上位2候補・所有だけ四半期解決」
「NearestPortName/PortLandKm と同型＝リフレクション直列化に安全な型・
  ロード後も値がそのまま復元＝再計算不要でビット一致」
```

★★ **理由は正しい**——⚠ 陸グラフの Dijkstra は州ごとに1回走るので、毎四半期やると重い。★ 直列化に安全な `string`/`double` にしたのも合理的。

⚠ **見落とされたのは「領土は動く」という一点だけ**である。

★★★ **本書は「静的をやめる」のではなく、「領土が動いた州だけ再配線する」ことを提案する。**

# 3. ★★★ 設計 — 3つの是正

## 3-1. 是正1：領土が動いたら再配線する

★ **再配線の引き金**（⚠ **これで全部**）：

| 引き金 | どこ |
|---|---|
| ★**割譲**（境界改定・戦利品） | `CedeTerritory` の末尾 |
| ★**植民地→州の昇格** | 昇格処理の末尾 |
| ★**独立**（州が新国家になる） | 内戦分裂・植民地独立 |
| ★**州の喪失/獲得を伴う全経路** | ⚠ 上の3つ以外に `Regions` を足し引きする場所が無いことを grep で確認する（§8-1） |

★★ **再配線は「動いた州を持つ2国」だけ**でよい（⚠ 世界全体を再計算しない）。

```
ReWirePorts(loserWorld)    ★州を失った側
ReWirePorts(winnerWorld)   ★州を得た側
```

⚠ **`WirePortDistances` をそのまま呼べる**——★ 新しいメソッドを作らない。

## 3-2. 是正2：所有を確認する

★ 2つの案があり、⚠ **案Bを推す**。

| 案 | 中身 | 評価 |
|---|---|---|
| ⚠**A** | `BilateralMarket` で毎回 `NearestPortName` の所有を引く | ⚠ **毎期・全州で辞書引き**＝重い。★ しかも所有が変わった瞬間に「壊れた配線」で1期走る |
| ★★**B** | ★ **是正1で再配線されるので、配線は常に正しい。**⚠ 念のため `WirePortDistances` の候補が `r.State == Active` かつ**同じ World の州**であることだけ確認する | ★ **コストゼロ**（構築時のまま）。⚠ 是正1が漏れたら壊れる |

★★★ **案B＋「漏れが無いことをテストで縛る」**を推す（§6-4）。

## 3-3. ★★★ 是正3：港を失った国にも通過港を配る

```csharp
WireTransitPorts()
    if (hasPort[i]) continue;   // ⚠ここが「開幕に港がある国」を永久に除外している
```

★ **是正**：⚠ **`hasPort` の判定を「現在」で行い、再配線時にも走らせる。**

| 状態 | 経路 |
|---|---|
| ★港州がある | ★ 自国港（3脚：陸→港→海） |
| ⚠**港州が0** | ★★ **通過港**（⚠ 外国港・通行料 `TransitTollShare = 0.05`・交戦中の港は第2候補へ） |
| ⚠ 通過港も届かない | ★ 旧フォールバック（⚠ **鎖国はしない**＝既存の規律） |

★★★ **これが「割譲は痛いが死なない」の実体である。**

> ⚠ **史実の対照**：ボリビアは1884年に海岸を失い、★ **今もチリの港を使って生きている。**
> ★ セルビアも内陸のまま1914年を迎えた。⚠ **港の喪失は致命的だが、鎖国ではない。**

## 3-4. ★ 何を作らないか

| ⚠ 作らない | 理由 |
|---|---|
| ⚠ 新しい係数 | ★ `TransitEnabled` / `TransitTollShare` は**既に点火済み**。**足すものが無い** |
| ⚠ 「最後の港ガード」 | ★★ **通過港があるので不要。**⚠ 最後の港を守る特例は思想②に触れる |
| ⚠ 新しいメソッド | ★ `WirePortDistances` / `WireTransitPorts` を**呼ぶ場所を増やすだけ** |
| ⚠ 毎期の再計算 | ★ 領土が動いた四半期だけ。⚠ Dijkstra を毎期回さない |

# 7. ★ 却下した案（★ 記録として残す）

| 案 | 却下理由 |
|---|---|
| ⚠ **毎四半期すべて再配線** | ★ 州ごとに Dijkstra が走る。⚠ **領土が動かない四半期が大半**なので無駄 |
| ⚠ **`BilateralMarket` で毎回所有を引く**（案A） | ⚠ 毎期・全州の辞書引き。★ しかも**壊れた配線で1期走る**（所有が変わった瞬間） |
| ⚠ **「最後の港は割譲できない」ガード** | ★★ **通過港があるので不要。**⚠ 特例を1つ足すと「最後の資源州」「最後の首都」…と際限がない（思想②） |
| ⚠ **港を失ったら自動で講和** | ⚠⚠ **台本**（思想①）。★ 痛みは通行料と陸路で表す |
| ⚠ **`NearestPortName` を廃して毎回最短探索** | ★ 直列化に安全な静的値という既存設計の利点（★ ロード後に再計算不要）を捨てる |

# 9. ★ 未決

| # | 論点 |
|---|---|
| **9a** | ⚠ **`SeaBasin` の継承をどう扱うか**。★ 内陸州は最寄り港の海盆を継ぐが、⚠ **港が変われば海盆も変わる**（キエフ→ロストフ＝黒海／もし黒海の港を失えばバルトへ）。★ 再配線で自動的に追随するはずだが、**封鎖・冬季閉鎖の判定が期中に切り替わる**影響を観測すること |
| **9b** | ⚠ **通過港の再配線コスト**。★ `WireTransitPorts` は全国の港を候補に Dijkstra を回す。⚠ **割譲のたびに全国分を回すのは重い**——★ 港州0になった国**だけ**を回す形に絞れるか |
| **9c** | ⚠ **属国の扱い**。★ 属国化（`SetDependency`）では州が動かないので再配線は不要のはずだが、⚠ **宗主の港を使えるべきか**は別の設計判断 |
| **9d** | ⚠ **カスピ海に海ノードが無い**。★ バクーの最寄り海ノードは**1,104km 先の「黒海東」**で、⚠ **バクーは黒海の港として扱われている**。★ 偶然にもバクー油田→バトゥーミ（1883年〜）の実際の輸出路と一致するが、**1,104kmの海路が無料で生えている**。⚠ `sea_nodes.json` の話であり本書の範囲外だが、**W4 の観測で目に入るはず** |
