# 3. ★★ 正確な機序（★ なぜ名前ごとに当たり外れが出るか）

⚠ **UTF-8 のバイト列を cp932 として読むと、★ 3バイト文字の【3バイト目】の運命が3つに割れる。**

| ⚠ 3バイト目 | ★ cp932 での扱い | ⚠ 結果 |
|---|---|---|
| ★ `A1`–`DF` | ★ 半角カナ1文字（自己完結） | ★ **安全**（★ 例：`へ` `表`） |
| ⚠ `80`–`9F` / `E0`–`FC` | ⚠ **先行バイト**＝**次の1バイトを飲み込む** | ⚠ 次が ASCII の `.` や数字（`0x40` 未満）なら**破綻** |
| ⚠ `A0` | ⚠⚠ **cp932 に存在しない** | ⚠⚠ **無条件で破綻**（★ 例：`ム`） |

★★★ **しかも判定はファイル名の先頭からの【累積】で決まる。**
⚠ 前の文字が1バイトずれると、後ろの全部の当たり外れが変わる。

```
⚠ とにかく.md → OK      ★「か」が次の「く」の先頭バイトを飲んで、たまたま辻褄が合う
⚠ 完全作業リスト.md → 破綻  ★「ト」(E3 83 88) の 88 が '.'(2E) を飲もうとして失敗
```

★★ **＝ どの命名規則を選んでも「たまたま」で3割壊れる。**⚠ **形式は対策にならない。**

# 5. ★★★ 再発防止 — 環境で塞ぐ

## ★ これ1本

```bash
PYTHONUTF8=1
```

★★ **恒久化**（★ どちらか一方でよい）:

```powershell

```

⚠ 効果：★ `open()`・`subprocess`・`sys.stdout` の既定が全て UTF-8 になる。
★★★ **指定漏れのある使い捨てスクリプトを書いても壊れない。**
