# 海ノード吸着の是正（接ぎ木の「出港の一歩目」に予算を持たせる）

2026-08-16 ／ 係数 `SeaStitchLeadBudgetMult`（**休眠＝既定0で厳密ビット恒等**）
触った実体：`PriceOfBread.SimCore\SeaGraph.cs`・`Coefficients.cs`・`PriceOfBread.Tests\SeaStitchBudgetTests.cs`（新規）

## 1. 診断（本日の調査・計器＝`dotnet run -- mapedges [四半期]`）

作者報告「陸地を横断する海路が地図に描かれている」の正体。

`SeaGraph.StitchCrossesLand`（港→海ノードの接ぎ木が陸を横切るかの判定）は
**「出港の一歩目（連続する陸）を数えない」** 規則を持つ。港は水際の町なので、`Landmask`（地図SVGを焼いた0.1°格子・
海岸線を1マス内側へ収縮）の上では港自身が陸のマスに乗る——その1マスぶんを免除する意図の規則である。

⚠**その免除に距離の上限が無かった。** 「一度も水に出ない線」は最後まで“出港の一歩目”のままなので、
**線の全部が陸でも合格する**。近い海ノードが半島に阻まれて棄却されると、この非対称のせいで
`NearestSeaNode` が**大陸の反対側のノードを合格させる**。

実測（`mapedges 0`・係数OFF）：

| 症状 | 実測 |
| --- | --- |
| トリエステ(45.65,13.77) の吸着先 | 最寄りの**アドリア海北(179km)** はイストリア半島で棄却され、**1,045km先のバルト南西(55.0,14.0)** を採用（陸上880km＝中欧を縦断する線） |
| トリエステの `SeaBasin` | **Baltic**（オーストリアが地中海勢でなくバルト海勢） |
| トリエステ→ヴェネツィア | **9,960km**（実際150km＝**×66**） |
| トリエステ→ナポリ／イスタンブール | ×7.3／×5.3 |
| 同型の吸着 | **港州92件中21件**（ハノイ1,036km・バンコク837・カナダ595・ブーシェフル476・ラプラタ440・サイゴン380・杭州361・ケルン352・マンチェスター310・リガ214 ほか） |

接ぎ木の距離は `SeaGraph.SeaDistanceKm` にそのまま加算され（`BilateralMarket.cs:145` が運賃の物差しに引く）、
海盆も採用ノードから継ぐ（`Simulation.cs:598` の `BasinAt`）ので、**表示だけの問題ではない**。

## 2. 実装

`Coefficients.SeaStitchLeadBudgetMult`（既定 **0.0** ＝休眠）。

* **形**：出港の免除に**予算**を持たせる。予算 ＝ `SeaStitchLeadBudgetMult` ×「**その地点が水に出るまでの実測距離**」。
  それを超えた先の陸は**横断**とみなす（`StitchCrossesLand` の中で `total×t <= 予算` を否定形で判定）。
* **実測距離**＝陸マスクの最寄り「海のマス」までの大圏距離（`SeaGraph.DepartureKm`）。トリエステで約5km、
  ケルン78km、ハノイ52km＝`mapedges` の「港州から海までの距離」列と同じ量。
  **固定kmのマジックナンバーを置かない**（作者の流儀「固定値でなく既存の較正済み量に絡める」）＝**規模中立**＝
  河口や内海の港（水まで遠い町）の免除は自動的に長く、水際の港（トリエステ）の免除は自動的に短い。
  * 走査の上限は「**素の最寄り海ノードまでの距離**」＝海ノードは定義上水の上にあるので、水がそれより遠いことはない
    ＝新しい半径の数値を置かずに走査が必ず終わる（外周＝チェビシェフ距離の輪を内から順に見て、最初に水を見つけた輪の1つ外まで）。
  * 下限は格子1マス（11.1km）＝`Landmask` が海岸線を1マス内側へ収縮させてあるぶんの不確かさ（新しい調整値ではなく格子の粗さの補正）。
* **退避**：どのノードも通らなければ**素の最寄りへ退避**する既存の規則がそのまま受ける。トリエステはアドリア海北(179km)に落ち着く
  ＝**正しい海に出る**（湾を出るとイストリア半島に当たるので、トリエステはどのノードへも水だけでは出られない＝退避が答えを出す経路）。
* **決定論**：`NearestSeaNode` の0.1°量子化キャッシュに**係数も1/1000量子化して鍵へ入れる**。
  予算も鍵の量子化値（qlat/qlon/qmult）から計算する＝**キーが量子化なら値も量子化入力から計算する**（2026-08-04に決定論を破った不変条件）。
* **配線**：`SeaGraph` は完全静的な地理データ層で `Coefficients` を配線する経路が構造的に無い（`World` も `Simulation` も知らない）ので、
  **プロセス既定値を1度だけ読む**（`POB_COEF` の上書きも同じ経路で効く）。テストは `internal` の多重定義（係数を明示で渡す）を呼び、
  プロセス既定を汚さずに ON/OFF を同一プロセスで比べる。
* **0で厳密恒等**：新しい実測（陸マスクの走査）は1回も走らず、判定の右辺も短絡で評価されない。
  実証＝`mapedges 0` の出力が**基線とバイト単位で同一**。

⚠**新しい状態（フィールド）は増やしていない**（`SaveGame` の形は不変）。海の**辺**（`Edges`／`CrossesLand`）には触れていない＝
係数は接ぎ木だけを動かす。

## 4. 残る構造課題（この係数では直らない・OFFでも同じ）

「最寄りが棄却されると、**遠方の純水ノード**が繰り上がる」形は残る。実測：

* OFF：江戸→日本南方沖768km（最寄りは相模湾）・長崎→黄海702km（最寄りは対馬海峡）・台北→ルソン海峡504km
* 1.0：ポルト→アゾレス沖1,695km・ハノイ→フィリピン海2,344km・タンジェ→マデイラ沖1,135km
* 0.5：バサイン→ホルムズ外1,696km・マンガロール→アラビア海中央1,406km

根＝直線の陸判定は「岬を回れば水で行ける」を表現できない（ポルトは岸を回れば最寄りノードに着く／トリエステは
どう回っても着かない——直線判定はこの2つを区別できない）。本格的に解くなら**陸マスク上の水の連結性（塗りつぶし）**で
「水だけで到達できる最寄りノード」を採る。ここでは範囲外＝次ラウンドの候補として記録する。

## 5. 点火A/B手順（親がバッチで測る）

海路距離が動く＝**較正非中立**（運賃→貿易→財政→国力の順に波及する）。

```bash
# A（基線・OFF）
bash measure.sh /tmp/seastitch_off.txt selfplay-batch 10
# B（点火・同一バイナリ／同一ソースハッシュ）
POB_COEF="SeaStitchLeadBudgetMult=1"   bash measure.sh /tmp/seastitch_on1.txt  selfplay-batch 10
POB_COEF="SeaStitchLeadBudgetMult=0.5" bash measure.sh /tmp/seastitch_on05.txt selfplay-batch 10
```

* ⚠`measure.sh` の隔離先は既定が共有なので、他セッションと並行するときは `SNAP_DIR=...` を分ける。
* ヘッダー（`★係数の上書き（POB_COEF）:` 行）を突き合わせてから数字を読む（掛けたつもりの実験が素通りしていないか）。
* **見る帯**＝①貿易/GDP（第一次グローバリゼーションの不在＝別途の課題なので、悪化していないかを見る）
  ②領土・列強（海運距離は植民地維持費と遠征に効く）③破綻0・保存則（`leakhunt`）④総政変。
* 採否の判定順序は作者裁定どおり **破綻しない ＞ 正しい挙動 ＞ バランス**。帯の悪化だけでは差し戻さない（ただし記録必須）。
* 点火するときは `Coefficients.SeaStitchLeadBudgetMult` の既定値を書き換え、番人テストの宣言行を更新する（差分が意図的であることの宣言）。
  併せて係数名で全域 grep し、「休眠」と名乗っているコメントを一巡させる。
  → **実施済み（2026-08-16に0.5で点火／2026-08-17に一巡）**：番人は
  `SeaStitchBudgetTests.明示0は旧規則とビット恒等であり既定は点火値0_5である` へ改名し、
  旧挙動の側は**引数で明示的に0を渡す**（既定に寄りかからない）形へ、既定側は「0.5でliveである」ことを固定する形へ直した。
