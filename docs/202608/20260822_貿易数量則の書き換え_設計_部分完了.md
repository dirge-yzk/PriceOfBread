## 1. 数量則の新式

### 1-1 前提＝価格法則の輸出反映（案D′：案D「輸出需要を需要として一本化」の価格法則版）

☆輸入は在庫と供給の**両方**に載る（`BilateralMarket.cs:461 m.Stock+=q; m.LastImport+=q` → `MarketFlow.cs:27`）が、輸出は在庫にしか載らない（`:460`）。対称化＝flow 項の需要側に輸出を足す（TargetStock `:24` には入れない＝在庫目標は国内需要のまま）。

```
MarketFlow.cs:68（ON 経路のみ）
  double eD = (totalDemand + (coef.PriceLawSeesExports > 0 ? m.LastExport : 0.0)) * Pow(dev, -ε);
```
- 休眠0＝`+0.0` を**足さない**分岐（`if` で旧式を逐語に通す）＝ビット恒等。
- 静止点（gap=0）：輸出州 P*=rp·(D+X)/S → X=S−D で P*=rp（潰れない）。輸入州は不変。
- 月次清算（案B）が前提：四半期清算のままだと `LastExport` は `EconomyStep.cs:234` のゼロ化で3ヶ月のうち30日しか見えない（パルス）。
- ◇これが立つと `:549 profitFactor`・`:361 rentR=Price−mc`（LaborRentWeight 点火時）が輸出需要を読む＝案Dの「重みの一本化」が価格経由で自動成立（0822設計 doc `:229-230` の方針と整合）。

### 1-2 買い手の数量 X（輸入州 t・財 g・着値 d）

記号（全て金建て・既存量）：ε=`PriceElasticity`(0.5・`Coefficients.cs:22`)、rp_t=`RefPrice×PriceLevel_t×exRate_t`（`MarketFlow.cs:63`・`BilateralMarket.cs:41,261`）、D=`LastDemand`（`EconomyStep.cs:1344`）、P=`LastProduced`（`:1516`）、I=`LastImport`（live・清算中に `:461` で増える）、A=`TargetStock`（`MarketFlow.cs:24`）、B=`Stock`（live）、d=`deliver`（`:375` の式そのまま＝運賃マージン・関税/穀物法/方針 wedge・封鎖バイアス込み）。

```
X_price(d) = D·(rp_t/d)^(2ε) − (P + I)        // 価格法則の flow 項が d で静止する輸入量（ε=0.5 なら D·rp/d − P − I）
X_need     = A + D − P − B                      // 来月の需要と在庫目標を満たす物理量（在庫が目標超なら自動で減る）
X(d)       = access_t × max(0, min(X_price(d), X_need)) [× LeakFraction（アヘン禁輸 :431 のまま）]
```
- **なぜ2腕か（審査の致命点2つへの答え）**：X_price 単独は d<0.574·rp で静止点が存在せず（☆gap=−1 でも価格が d に留まらない＝在庫→∞・腐敗 `EconomyStep.cs:227`）、増分形は純輸入州で閉じない。X_need が物理で蓋をし、X_price が「着値が高いとき（d>rp）需要側が縮む」を担う。どちらも水準式＝定常で解ける。
- 定常の挙動（☆）：d<rp なら X=D−P（不足分を毎月埋める）・lp→rp 近傍・裁定差 rp−d は売り手（unit≥Price_s）と商人の取り分。d>rp なら X=D·rp/d−P<不足分・lp→d・消費が価格で縮む。**「価格差が閉じる」＝lp が d へ単調に寄る**（閉じ切らない側は rp アンカーの構造＝価格法則の設計・裁定点7-3）。
- TradeSpeed は ON 経路で読まない（λ≡1）。λ<1 を掛けると定常で lp/d≈1/λ の楔（純輸入国：I=λ·D·rp/d → lp=d/λ）。

### 1-3 売り手の数量 Y（輸出州 s・受取単価 u）

```
Y_price(u) = S_s·u/rp_s − D_s − X_s            // 案D′の静止点：(D_s+X)·(u/rp)^−ε = S_s·(u/rp)^ε。S_s=P_s+I_s、X_s=LastExport（live・:460 で増える）
Y_stock    = Stock_s − TargetStock_s            // 地元1ヶ月分を残す物理上限
Y(u)       = sellAcc_s × max(0, min(Y_price(u), Y_stock))   // sellAcc＝:301-302 のまま（軍需アクセス・禁輸漏れ）
```
- ☆固定点：現在価格 Price_s=rp_s·(D_s+X0)/S_s なら Y_price(Price_s)=X0（今の輸出率を維持）。u↑で Y↑（世界が高く買えば地元を絞る）。
- `left[s]` の Flow 腕（`:327 min(Stock,Flow)`・TradeSpeed 蓋）は ON で消える。

## 2. 容量の制約化（案C）

### 2-1 同期制約
- Step 冒頭 `capLeft[t] = cap_t`（`:130` の合成そのまま。`TransportEnabled=false` なら ∞）。成約ごとに `q ≤ min(capLeft[t],capLeft[sn])/W_g`、両端減算（`volLoad :462` と同じ両端計上規約＝較正継続・裁定点7-5）。
- `:139-140` の `natAccess×throttle` は ON で外す（同じ容量が遅延乗数と同期制約で2回効く二重拘束の回避）。`access=natAccess` のみ。
- 単位＝「cap は**1清算（=1ヶ月）に動かせる重量**」。☆`:498 Math.Min(1,cap/potential)` が既に暗黙に置いている比を据え置くだけ＝換算定数を新設しない。旧 `Trade.cs:63-64 factor=min(1,cap/volume)`（同月比較）の原義へ戻す。⚠現行は四半期フロー÷月次ストックなので、月次化で実効3倍緩む較正変化（★英の余裕×2.90→≈×8.7 で当たる・docs/20260821:132-134,212）。

### 2-2 州への配分（審査の「ロンドンは英容量の1/16」への答え）
- 現行 `:84 share=1/activeCount`（均等割り・非ネットワーク）。ON＝`share_r = LastTradePotential_r / Σ_active LastTradePotential`（前清算値・既存フィールド）、Σ≤0 か非有限なら均等割りへ倒す（否定形ガード）。船は荷のある港へ行く＝新定数なし。
- 内陸州：`:130 min(inlandRail, shipEff)` で鉄道0（`RailTechOnset 0.35` 前・`Transport.cs:39-40`）なら cap=0。☆現行は `:496` の `access>1e-12 ? … : 1.0` で **2清算周期のリミットサイクル**（t期全開→θ=0→t+1期0→volLoad=0→θ=1.0）＝時間平均50%。同期制約にすると「容量ゼロは運べない」（`:135-137`・`Trade.cs:26` の作者指示「鉄道0なら0」）が文字どおりになる＝鉄道前の内陸州が**完全に外れる**較正変化。代替＝`Baseline×share` を内陸にも読む（`min(inlandRail+Baseline·share, shipEff)`）。裁定点7-4・S4-0 の影計測で州数と量を出してから決める。

### 2-3 潜在量と θ（T4 の錨）
- `potential` は 1-4 の `pot·W` を両端に積む。capLeft が尽きた買い手は次善へ回らず break、尽きた売り手は走査から外す＋残 `avail·W` を1回だけ計上＝**売り手数で膨らまない**（審査指摘）。
- `LastTradeThrottle = min(1, cap/potential)`（potential≥volLoad）、`LastThrottleBinding` は `:500` のまま。読み手 `StepPorts`（`MultiNationSim.cs:912` θ<0.9）・`Transport.cs:35` 混雑項・UI（`GameViewModel.Fiscal.cs:539`）はそのまま生きる＝港湾投資の死ループ（θ≡1）とリミットサイクルが自然に消える。
- 検算用＝同じコード経路を `capLeft=∞` で**空走（dry）**させた volLoad（厳密な potential）を probe で並べ、近似の誤差を測る（S4-0）。
- T4 点火：`TransportPotentialWeight=1.0`（0/1 の構造値）。目標＝Σ potential×`TransportPotentialHeadroom`(1.2)。⚠1.2 は休眠の未較正定数＝裁定点7-5。容量は潜在重量を追うストックになり、単位は自動で揃う。
