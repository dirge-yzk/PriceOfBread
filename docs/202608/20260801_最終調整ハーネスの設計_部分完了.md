# 0-2. ★★ 作者の裁定（2026-08-01・**確定**）

## 裁定①　6次元50%ゲートは終了コードに畳まない。**終了コードを3値にする**

```
0 = 硬性ゲート全緑 かつ 6次元がゲート対象の全次元で50%以上
1 = 硬性ゲートが赤          ← ★差し戻しの理由になる唯一の値
2 = 硬性ゲート緑・6次元が未達 ← ★記録して進む。差し戻しの理由にならない
```

★ 根拠＝2026-08-01の判定順序（**破綻しない ＞ 正しい挙動 ＞ バランス**）が終了コードの大小にそのまま写る。
⚠ 同じ裁定が「**帯が悪化しただけでは差し戻さない**」と言っている以上、**6次元が exit 1 を出してはならない。**
⚠ 一方で「**記録を欠いた採用は認めない**」を機械化するには印字のみでも足りない。★ 3値なら「`rc==1` で止める・`rc==2` は記録して進む」が運用規約1行で書ける。

**付帯条件**
1. ★ **ゲートに載せるのは参照エントリが十分な次元だけ**（§5-3）。現状で報告のみに留めるのは **`PopGrowthOk`（7件）** の1本。
2. ★ **前回値との差分を必ず併記する**——exit 2 は「未達」であって「悪化」ではないので、悪化は差分でしか出ない。

★ 反映先＝§4-2・§5-3。

## 裁定②　`WarNeedsReach` の閾値は**選ばない**（`DefendProjectionMin = 0.2` を据え置き）

⚠ **「ほぼ効いていない」という診断は半分だけ正しい。** 効かない理由は距離だけではない。

```csharp
Diplomacy.cs   if (c.WarNeedsReach > 0
                   && Projection(a,b,c) < c.DefendProjectionMin && Projection(b,a,c) < c.DefendProjectionMin) return false;
Projection     = 1/(1 + DistanceWarDecay × km/DistanceNormKm)  × （海越えなら SeaControl）
```

★ **陸の半分は確かに死んでいる**：0.2 → km 40,000 ＝ **大圏最大 20,037km の2倍**＝地球上に該当ペアが存在しない。
★★★ **しかし海側が効かない理由は別で、`SeaControl(a,b) + SeaControl(b,a) = 1` だからである。** どちらか一方は必ず 0.5 以上あるので、**AND の両側が閾値を割るのは「両国とも海軍がほぼゼロ」（0/0 のガード経路）のときだけ。** ハイデラバード×マレーが止まったのはこの経路である。

★★★ **この構造のせいで閾値はナイフエッジになっている**（距離1万km・decay=0.5 の場合）：

| 閾値 | 挙動 |
|---|---|
| **0.2**（現状） | ★双方海軍ゼロのペアだけ止める |
| 0.3 | 制海権が6割未満の側が絡む海戦を止め始める |
| **0.5** | ⚠⚠ **`SeaControl ≥ 1.0` が要求される＝海を越える戦争が全部止まる** |

⚠ **「何も止めない」から「海の戦争を全部止める」まで、0.25〜0.5 の狭い区間で反転する。** ★ これは掃討基準の**C級（不連続を作る切替＝値でなく形が壊す）**そのもので、軍の改修が3回目に失敗した型と同じである。**この上に載った閾値を較正で選ぶことはできない。**

★★ **本命の直し方は閾値ではなく `DistanceWarDecay` の時代関数化である**（新係数ゼロ）。
- 陸が死んでいるのは閾値が低いからではなく `1/(1+km/10000)` が**ほとんど減衰しない**から（パリ⇔北京 8,200km で 0.55）
- ★ これは `20260801_導出方法の精査.md` が **A級**に分類した係数であり、『理想の軍隊の形』§9 も「行和が20を超え内点の均衡が存在しない」として同じ理由で案を却下している
- ★ `freightRevolution`（前線技術の連続関数・史実の実測系列に係留）の模範形を当てれば、**0.2 を動かさないまま閾値が陸でも意味を持つ世界になる**——1783年のハイデラバードはマレーに届かず、1913年なら届く

★ **短期は据え置きでよい。** 反復開戦が残るなら、それは到達ではなく**講和後の再点火**の問題であり、`MinTruceYears = 4` ／ `TruceYearsPerFullVictory = 10` 側を見る。

★ 反映先＝§13-7。

## 裁定③　`FleetStockPerNavalGauge` は**選ばない**（2条件で一意に決まる）

⚠⚠ **前提の警告：このまま点火すると 1783年の英海軍がゼロになる。**
`Region.FleetStock`（`Model.cs`）は**初期化がなく**、`EconomyStep.cs` の購入累積だけで育つ。したがって **Q0 では全国 0** → `FleetGauge = 0` → `NavalPower = min(0, 乗員) = 0`。
★ これは『理想の軍隊の形』§2-6 が空軍について却下したのと**同じ吸収状態**であり、そこでの答えは「ストック初期値＝原単位×初期兵数（開幕 Fill=1.0 を保つ）」だった。

### (i) 開幕の播種＝点火が**国別に**ビット恒等になる

```
FleetStock₀ = Military₀ × NavalShare₀ × FleetStockPerNavalGauge
```
★ Q0 で `FleetGauge = Military₀ × NavalShare₀` ＝ 旧ゲージそのもの。**総量恒等式より強い保証**（世界平均でなく国別に恒等）。以後の乖離は実際の建艦だけから積み上がる。

### (ii) 定数は定常恒等で代数的に決まる

★ 播種すると K は Q0 で約分されるので、K を決めるのは**その後の建艦フローがゲージをどれだけ動かすか**である。定常状態（購入＝劣化）で：

```
定常ストック ＝ Σ_{艦艇財 g}( MilitaryScale × rate_g × RefPrice_g ) ÷ Spoilage(軍艦)
K            ＝ 定常ストック ÷ ( Military × NavalShare )
```
★★ **右辺はすべて既存データ**（調達率・参照価格・劣化率）＝**選ぶ数ではなく現行の調達式から出てくる数。**

### (iii) 合否は「`min` のどちらも張り付かないこと」＝★ゲート8の物差し

| K | 起きること |
|---|---|
| 小さすぎ | `FleetGauge ≫ 乗員` ＝ **乗員側が常時binding**＝人口海軍に逆戻り |
| 大きすぎ | **艦隊側が常時binding**＝乗員が死ぬ |

★★★ **どちらの端も、ゲート8が定義する「殺された信号」そのものである。** ★ 目安＝**両側の binding 率がそれぞれ30〜70%**。**③の較正基準とゲート8は同じ物差しである。**

### ⚠ 実務上の注意

★ `FleetGoodIds` は軍艦86・装甲艦105・弩級戦艦123 で、**tier が解禁されるたびに構成が変わる**（4段カスケードの afford も段ごとに違う）。したがって上の比は時代で漂う。
★ **Q0／Q200／Q350／Q524 の4断面で測り、漂いを記録すること。** ⚠ **2倍を超えて漂うなら定数 K では正しくならず**、`Σ(原単位 × RefPrice)` から導出する形（＝**K という係数自体が消える形**）へ移す。
⚠ `NavalPowerFromFleet` の宣言コメントは「1914断面の分布で決める」と書いているが、**1914断面だけでは (i) を見落とす**（Q0 が 0 であることは1914の分布に現れない）。

★ 反映先＝§13-7。

## 2-1. ★ 100は適切か → **考え方は正しい。ただし96か112に丸めるべき**

★ 判定の中心は `◎`（その国が何割のシードで史実に到達したか）で、これは**1カ国あたりN回のベルヌーイ試行**である。粒度は 1/N、標準誤差は √(p(1−p)/N)。◎帯は 55〜85%＝中心70%から±15pt。

| N | 粒度 | SE(p=0.7) | 帯の幅/SE | 真に70%の国が帯を外れる確率 | 54カ国での誤判定の期待数 |
|---|---|---|---|---|---|
| 10 | 10pt | 14.5pt | ±1.03 | 30% | **16カ国** |
| 15（現・反復） | 6.7pt | 11.8pt | ±1.27 | 20% | 11カ国 |
| 30 | 3.3pt | 8.4pt | ±1.79 | 7.3% | 3.9カ国 |
| 50（現・最終） | 2.0pt | 6.5pt | ±2.31 | 2.1% | 1.1カ国 |
| **96 / 100 / 112** | 1.0pt | 4.6pt | ±3.26 | **0.11%** | **0.06カ国** |

⚠ **これが意味すること**：`docs/202607/99_実装ログ_2026-07-31夜_完了.md` が採否の根拠にした **◎21→23・逸脱過多13→10 という差は、10シードの雑音の床（±16カ国）の内側**である。あの比較は ◎ については情報を持っていなかった（`exact`／`near` の集計値は国×シードで平均されるので、もっと頑健）。

★★ **96 を推す理由＝並列度である。** 既定の並列度は `clamp(論理コア数, 2, n)`（`SelfPlay.cs:826`）で、本機は論理16。
- **100 → 6波＋末尾4**（末尾で12スレッドが遊ぶ＝**約7〜10分の無駄**）
- **96 → 6波ちょうど**
- 112 → 7波ちょうど（精度はほぼ同じで所要が+16%）

★ 96と100の統計的な差は無視できる（SE 4.68pt 対 4.58pt）。**96 を既定、112 を「もう一段確かめたいとき」の選択肢にする。**

★ `ceiling`／`ceiltrace`／`pricedist`／`freshboard`／`startboard`／`warmsettle`／`monitor` はすべて「価格÷参照価格の天井」という**単一量の診断**で、ゲート8が測る「クランプの binding 率」とは**別物**である。

## 13-7. ★★ ゲート8の最初の2つの用途（2026-08-01の裁定②③）

★★★ **ゲート8は「監査の道具」であると同時に「較正の物差し」でもある。** 裁定②と③はどちらも、**閾値や定数を選ぶ代わりに張り付き率で決める**形に落ちた。これがこの計器の最初の実用例になる。

### 用途1：`WarNeedsReach` の閾値がナイフエッジであることの検出（裁定②）

★ `Projection = decay × SeaControl` で **`SeaControl(a,b) + SeaControl(b,a) = 1`** なので、`max` 方向の `Projection` は構造的に `decay/2` 以上ある。
⚠ したがって閾値 `DefendProjectionMin` は、**0.25 付近で「何も止めない」から「海の戦争を全部止める」へ反転する。**

★★ **これはゲート8が検出すべき典型形である**：
- 閾値 0.2（現状）＝ **binding 率がほぼ0%**（双方海軍ゼロのペアだけ）＝「死んだ安全網」に見える
- ⚠ しかし**「境界までの正規化距離」を同時に見ると、多くのペアが境界のすぐ上にいる**＝§13-4(4) が言う「**生きた安全網**」である

★★★ **binding 率だけを見て「0%だから撤去してよい」と判断すると誤る、という最初の実例。** §13-4(4)（境界までの正規化距離の分位点を必ず同時に記録する）は、この裁定によって**具体的な要求になった。**

### 用途2：`FleetStockPerNavalGauge` の合否判定（裁定③）

```
NavalPower = min( FleetGauge , Military × NavalShare )     ← 船と乗員の弱い方
```
★ **`min` の両腕それぞれの binding 率がそのまま較正の合否になる。**

| 観測 | 意味 | 判定 |
|---|---|---|
| 乗員側の binding 率 ≈ 100% | `FleetGauge ≫ 乗員`＝K が小さすぎる | ⚠ **人口海軍に逆戻り**（改修の目的が消える） |
| 艦隊側の binding 率 ≈ 100% | K が大きすぎる | ⚠ **乗員の制約が死ぬ** |
| **両側が 30〜70%** | 船と乗員が交互に律速する | ★**合格** |

⚠ **`FleetGoodIds`（軍艦86・装甲艦105・弩級戦艦123）は tier の解禁で構成が変わる**ので、この比は時代で漂う。★ **Q0／Q200／Q350／Q524 の4断面で測り、漂いを記録する。** 2倍を超えて漂うなら定数では正しくならず、`Σ(原単位 × RefPrice)` からの導出へ移す（＝**K という係数自体が消える**）。

★ 詳細は §0-2 裁定③。
