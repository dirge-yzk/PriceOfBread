## 要旨（3行）

1. **第2の栓＝売り手側の流量蓋 `left[s] = min(在庫, flowS)`**。flowS はその州の**地元規模の5%**でしかなく、
   実測で売り手候補の **93%が在庫でなく流量で止まっている**（在庫87に対し流せるのは月0.1＝**870倍**の開き）。
2. その根は **買い手・売り手の両方が「地元市場規模 × TradeSpeed」でしか動けない**こと。
   貿易は経済規模の**定数割合**に構造固定され、価格差も比較優位も水準を決められない。
3. ⚠ **貿易/GDP の物差しが12倍過大**（分子＝四半期フローの年換算／分母＝月次フロー）。
   暦を直すと英1914は **1.51% → 0.13%**、史実25%との差は ×17 ではなく **×190**。栓を直す前に物差しの裁定が要る。

## 2. 第2の栓の名指し

> ### 第2の栓 ＝ **売り手側の流量蓋** `left[s] = Math.Min(sellers[s].Stock, sellers[s].Flow)`
> （☆ `BilateralMarket.cs:320`。Flow ＝ `access × TradeSpeed(0.05) × 地元規模`、`:299`）

**まず直すべき1つに選んだ理由**（5点）：

1. **唯一、単独で桁を動かした。** ★同一バイナリ A/B（`left = min(在庫, 流量×K)` の K だけを掃引）
   ＝ K=1（基線）英1914 **1.51%** → K=4 **1.98%** → K=1000（実質「在庫まで」）**13.23%（×8.8）**。
   世界成約額 27,626→65,765（×2.38）・成約量 6,673→17,264（×2.59）。
   他の全レバー（輸送容量無限 ×1.03／帯拡張 ×0.98／関税全廃 ×1.4〜2.3／到達障壁全消し ×1.43／
   購買力の蓋撤廃 ×1.0）は**桁を動かさない**。
2. **用量反応が単調で、カオスでない。** ★10サンプル点（1784〜1914）**全点で K=1000 > K=1**（比 1.15〜8.78）。
   単一四半期の跳ね（基線の隣接四半期比は中央値×1.36〜2.10）に埋もれていない。
3. **保存則を壊さずに直せる。** 蓋の外側は `min` のもう一方＝在庫。在庫を超えて売ることはないので、
   財は無から湧かない＝ leakhunt は緑のまま。
4. **新しい係数を増やさずに直せる**（後述 F1）。
5. **第1の栓と同じ行の別の顔＝1914年で効かなかった理由が構造で説明できる。**
   ☆ 裁定上乗せ（`:301-306`）は `flowS × (1 + x/(1+x/K))` ＝上限が **(1+K)＝K=4 で×5**。
   ★ 一方で実測の在庫/流量比は**桁で大きい**（1914年ボンベイの綿花＝在庫87に対し flowS≒0.1／**870倍**、
   売り手候補の**93.0%が Flow<Stock**）。**×5では蓋に触りもしない。**
   ⚠ この非線形性は罠でもある：★`TradeSellerFlowMult=10`（×10）でも世界は 0.780%→1.372%（×1.76）にしかならず、
   **小さい倍率で試すと「効かない」と誤判定する**。効き始めるのは在庫が律速に変わる ×100〜1000 の帯。

？ **未決着**：1833年で `TradeArbitrageMax=4` が効いた（3.56→7.51%）のに1914年で効かない理由を、
　 「在庫/流量比が年代とともに開くから」と**断定するには 1833年の在庫/流量比の分布が測られていない**。
　 次ラウンドで `tradewhy` に在庫/flowS 比のヒストグラムを足して確認すること（推測で書かない）。

### 根と栓の関係（名指しを1つに絞った理由）

根 R（両側が地元規模比例）そのものを直すのが本筋だが、**R を一度に直すと初期（1783-1823）が壊れる**
（★楔を厳密ゼロにした腕では 1783-1843窓が平均 78.7%・最大139.9%＝史実の3〜5倍）。
帰結1 は R の**最も binding な現れ**であり、単独で外しても在庫という物理的な上限が受け止める。
よって **F1（帰結1）→ 測定 → F2（帰結2）→ 測定 → 必要なら R 本体**の順が安全。

## 3. 生存した仮説と修正方針（因果の順）

新しい係数を作らない案を **【新係数ゼロ】** と印す。作者裁定が要るものは **【要裁定】**。

### F1（本命・帰結1）売り手の流量蓋を撤去し、蓋を輸送容量へ一本化する

- **現状** ☆`BilateralMarket.cs:320` `left[s] = Math.Min(sellers[s].Stock, sellers[s].Flow);`
- **案A【新係数ゼロ・推奨】** `left[s] = sellers[s].Stock;` ＝流量を left から外す。
  「その州の地元需要の5%しか船に積めない」という**物理的に説明のつかない蓋**を捨て、
  蓋の役目は既にある**輸送容量**（☆`:127` cap → `:491` `LastTradeThrottle` → `:132-133` access）に引き継がせる。
  - ★今は輸送容量が完全に非拘束（1914年 主要6カ国の律速率 min=1.000・容量余裕 世界×12.42）。
    だから「容量は無罪」という測定結果が出ていた。**蓋を外して貿易が数倍になると容量が binding し始める**
    （★英の容量余裕は×2.90＝先に当たる）＝混雑→輸送目標↑→港湾/鉄道投資、という**既存の内生フィードバックが引き継ぐ**。
    これは「例外を作らず、袋小路を状態の持続条件で解く」既存の型（条約港の自然失効）と同じ形。
  - ⚠リスク＝初期の過大。★楔ゼロ腕の前例（1783-1843が78.7%）。ただし本案は楔を残すので同一ではない。要実測。
- **案B【新係数ゼロ】** 既存 `TradeArbitrageMax` の**意味を変える**：上乗せを `x/(1+x/K)` の有界形から外し、
  在庫が律速になるまで許す。係数は増えないが、④の設計意図（自己有界）を捨てることになる＝**【要裁定】**。
- **案C（非推奨）** `scaleS` に在庫回転を足す。新しい係数が要るうえ、根 R をそのまま残す。
- **測り方**：★既に `TradeSellerFlowMult`（☆`Coefficients.cs:781`・既定1.0＝恒等）がツリーにあるので、
  **実装前に `POB_COEF="TradeSellerFlowMult=1000"` で案Aとほぼ同じ世界を先に測れる**（在庫が律速に変わるため）。

### F2（帰結2）買い手が次善以降へ回れるようにする

- **現状** ☆`:436` `q = Math.Min(q, left[best]);` → `:452` `left[best] -= q;` → **次の買い手へ**。
  同じ買い手×財が、切られた残りを2番目に安い売り手から埋めることは**一度もない**。
  ☆`secondDeliver`（`:369-370, 410`）は**単価の決定にしか使われていない**＝次善は「価格の目安」であって「代替の売り手」ではない。
- **修正【新係数ゼロ】** 買い手ループの内側を「希望が尽きるか、採算の合う売り手が尽きるまで」の反復にする。
  売り手は価格昇順の全順序（☆`:317` 同価格は州名で決定論）なので**決定論は保たれる**。
- ⚠計算量：★枝刈りを完全に外すと1四半期37秒（524四半期で約5.4時間）＝完走不能。
  反復は全探索ではない（残希望が尽きたら抜ける）が、**F1 の後に必要性を測ってから**着手すること。
  F1 で left が在庫になれば1相手で足りる場面が増え、F2 の効きは下がるはず。

### F3（帰結3）TradeSpeed は較正のつまみであって構造の修正ではない

- ★両側×10で世界 0.780→8.396%（×10.76）、弾力0.92。だが**市場額/GDP の時系列は基線とほぼ同一＝崩壊の形が1ミリも変わらない**。
- **方針**：F1/F2 の後、**再較正の最後**に触る。**先に触らない**（水準を合わせて構造を隠すことになる）。

### F4（生存・minor）枝刈り下界が運賃革命を見ていない

- ☆ `BilateralMarket.cs:356` `double minFreightMargin = c.TransportMargin;`（0.18）だが、
  ☆ `:365` の実マージンは `c.TransportMargin * (1 + …) * adValoremRev`。
  `adValoremRev` は前線技術で 1.0→0.5 へ落ちる（`TransportRevolutionMax=0.5`）ので、
  **1914年の真の下界は 0.09 ＝ 使用下界が ×2.000 に膨れ、`:361` の break が早すぎる**。
- ★実測＝最良の取り逃しは 1784年 0件／1813年 0件／1853年 235件／1893年 685件／**1914年 636件/12,832行（4.96%）**。
  着値超過 平均2.75%・取引消滅7件・希望量の目減り0.20%。
  **下界だけ `* adValoremRev` に直したビルドでは全5断面で取り逃し0件**＝相関でなく因果（唯一の原因）。
- **修正【新係数ゼロ】** `minFreightMargin = c.TransportMargin * adValoremRev;`（1行）。
- ⚠**これは貿易を増やさない**：★3シードA/Bで 1914年 ×1.34／×0.90／×1.61 と**符号が揃わない**（t=1.28・有意でない）。
  下界を正すと `secondDeliver` も動き、単価 `unit = min(lp, secondDeliver)` が**下がる**方向にも効くため。
  ⇒ **正しさのための修正**であって栓ではない。F1 の測定と混ぜない（別コミット・別測定）。
- ★**崩壊の原因ではありえない決定打**：世界貿易/GDP が 1803年11.88%→1823年2.67% と崩れる全期間で
  `adValoremRev = 1.0000` ＝**このバグは1833年頃まで存在すらしない**。

- **合成指標を1つ見て原因を推測しない。** 需要Σ/生産Σ・Σleft・律速州率・p75/p25 は**いずれも識別能力がゼロ**だった

  **切られた需要に生産と在庫目標が追従する**。よって「需要と生産が釣り合っている」は常に真に近い。
- **小さい倍率のA/Bで蓋を探さない**：蓋が桁で離れている場合（在庫/流量＝870倍）、×10 は「効かない」に見える。

  同一四半期・同一軌道の**読み取り専用の反実仮想**を優先し、A/B はその補強に使う。
- **診断は必ずフラグの内側**（既定 false）。追加したら診断なしビルドと `selfplay 1 200` を突き合わせて
  **diff 0行（できれば SHA-256 一致）**を確認する。
