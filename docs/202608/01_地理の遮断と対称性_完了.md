## 1. 通行不可地形が機能していなかった（採用済み）

作者指摘「通行不可地形が機能していない場所もありそうだ。ごく近くを通るパスは引けないようにしたい（データ上も）」。

### 旧方式の2つの穴
バリアが k近傍の**枠を1つ食う**ことで「山の向こうの州が押し出される」ことを期待する間接的な仕掛けだった。

- **穴①** バリアが上位kに入らなければ**1枠も食わない**＝線が山を貫通しても素通り（都市が密集した地域）
- **穴②** 追い出される相手が山の向こうとは限らない＝**方向を見ていない**ので無関係な隣人が巻き添え

⚠作者が挙げた代案「枠を2〜3食う」は穴①をわずかに減らすが**穴②を2〜3倍に悪化**させる（連結が痩せる）。

### 幾何判定へ
線分が**どのバリア点からも110km以上離れている**ことを要求。方向も距離も正しく効くので、バリアを近傍ランキングから外せる＝穴②が構造的に消える（峠は通行可なのでノードのまま）。

⚠**判定は重くない**：271ノード×候補5本×バリア59点＝約8万回の点-線分距離を、静的初期化で1回だけ。

### 閾値を2回誤った（記録）
| 版 | 値 | 根拠 | 結果 |
|---|---|---|---|
| 初版 | 275km | バリア点の間隔556kmの半分＝「隙間のない壁」 | ★壁の**厚み**が550kmになり、マドリード→パリ ×2.71（アルジェ経由）・パリ→マルセイユ ×2.96 |
| 自己バグ | — | 棄却した辺が**枠を消費**していた | ★辺700→620・連結成分2→**27**・最大198→134＝グラフが砕けた |
| 確定 | **110km** | **主要山脈の半幅**（ピレネー約100km・アルプス約200km・ヒマラヤ約250km） | 全6経路が帯内・連結は基準線と同一 |

★正しい意味は「町の道が減る」ではなく「**道が山を回って次の町へ伸びる**」＝棄却時に枠を消費しない。

### 掃引の実測
```
 80km 辺844 成分2/198 最悪×1.46 全て帯内
110km 辺839 成分2/198 最悪×1.31 全て帯内  ★採用
140km 辺817 成分2/223 デリー→ラサ ×2.00 帯外
180km 辺816 成分3/222 3経路が帯外
```

### ⚠既知の限界
バリア59点の間隔は中央値556km・最大の飛び2121km。半径110kmでは**壁は点線であって連続していない**。連続した壁にするには点を約220km間隔まで増やすか、山脈を**折れ線**として持つ必要がある。別ラウンド。

## 2. 陸グラフが海を歩いて渡っていた（測定中）

作者指摘「トリノとアシャンティが陸路でつながっている。地中海などは陸路を遮るべき」「島国には全て港がある筈」。

### 実測
```
陸の辺 1038本 のうち **別の陸塊を結ぶ辺 228本（22%）**
  アフリカ↔ユーラシア 45本 ／ ブリテン↔大陸 14本 ／ デンマーク島嶼↔大陸 12本
  九州↔本州 8本 ／ ヒスパニオラ↔南米 7本 ／ セイロン↔インド 6本

実例：トリノ↔アシャンティ（西アフリカ）・トリノ↔ゴンダール（エチオピア）
      フェズ↔リスボン・アルジェ↔マドリード・アルジェ↔バルセロナ
```
**サハラも地中海も歩いて越えていた。**

### 直し方＝既にあるデータを見るだけ
`Landmass`（landmass.json・29陸塊）は既にあり、`Diplomacy.IsSeaCrossing` が「別陸塊＝渡海が要る」で使っている。**陸グラフだけが参照していなかった。**

⚠上陸ゲート（海軍が無いとブリテン島に乗れない）を入れても、陸グラフ側で最初から地続きなら意味がない。

### 結果
```
辺 839 → 711（別陸塊の128本が消えた）
連結成分 2 → 29（最大159）＝**島と大陸が分かれた＝正しい**
```
経路の中身も改善：モスクワ→北京がコーカサス・ペルシャ経由の南回りをやめ**シベリア経由**に。
以前は地中海と黒海を歩いて渡れたので南に落ちていた。

★テストの前提を更新（連結成分 4以下 → 32以下）。診断側は元から「※島嶼・別大陸は別成分が正しい」と書かれていた。

## 3. 参戦の可否を経済と軍量に依存させた（測定中）

作者裁定「AIの参戦有無を国内の経済あるいは軍量に依存させたい。明らかに格上で勝ち目のない戦争や、国難時には参戦を控える＝プレイヤーが参戦拒否した際と同じ挙動」。

### なぜ要るか＝**プレイヤーだけが断れる**非対称の解消
旧＝参戦の条件は「緊張 ≥ 閾値」だけ。国が内戦の只中でも、飢饉でも、相手が桁違いに強くてもAIは必ず参戦した。
プレイヤーには要請（`PendingCallToArms`）が積まれ「受ける／断る」を選べる。**断る権利がプレイヤー専用の特権**になっていた。

★同じ理由でAIも断るようにすれば、プレイヤーの拒否は**特例ではなく同じ判断の一例**になり、非対称が構造的に消える。
断った帰結（要請元との緊張＝`AllyRefusalTension`）は既に両者共通なので、**罰の作り分けも要らない**。

```
勝ち目がない   敵の陣営戦力 > 自分の陣営戦力 × AppeaseMilitaryRatio(2.5)   ← 挑発/宥和で既に使う値
国難           WarExhaustion > WarWearyThreshold                          ← 連鎖段で既に使う値
               内戦の只中 ／ 飢饉(FoodFill<0.7) ／ 財政(FiscalFundingRatio<0.6) ／ 正統性(<0.4)
```
⚠新しい機構を1つも作らない。判定は否定形＝NaNは「国難」側へ倒れる。

### 決定論の確認（作者質問「参戦の有無は確定するか？」）
**確定する。** `JoinAllies` はRNGを1つも引かない純粋な述語。したがってUIに「参戦65%」のような**存在しない確率を出してはいけない**。
「参戦する／しない」の二値で表示する。

## 5. 地図の高速化（見た目は1ピクセルも変えない）

作者報告「マップ全体が重い。ゲームに支障をきたす」。

| # | 何が無駄だったか | 措置 |
|---|---|---|
| ① | 辺1本＝1コントロール。陸692＋海342＝1,034本 ×3コピー＝**約3,100個の視覚要素**がズーム/パンのたびに再レイアウト | `MapEdgeLayer`＝**1コントロールの1回のRender**で全部描く（要素数 3,100→1） |
| ② | 世界の複製3枚のうち **k=−1 は数学的に常に画面外**（`ClampAndWrap` が translate.X を (−period,0] に折り返し、period=2000×scale ≥ ウィンドウ幅） | 9箇所すべて2枚へ＝**全レイヤの要素が2/3** |
| ③ | 不変の幾何（`static readonly`）を**四半期ごとに全再構築**＝カク付きの正体 | ズーム（と運河の開通状態）が変わらなければ組み直さない |

⚠③で**自分でバグを作った**：早期リターンだけ入れると運河が開通しても線が出ない。開通状態も鍵に含めて解決。

### 海上の線が見えない
```
海の塗り #16314E ／ 旧・海の線 #1F3A55  ＝ 各チャンネルの差が9・コントラスト比 約1.1:1
新 #4E7FA8 ＝ コントラスト比 約3.1:1。線の太さの下限も 0.3→0.45px（0.3pxはサブピクセルで霞む）
```

### 未開通の運河が描かれていた
`SeaGraph.Edges` は運河の辺を常に含み、経路計算では開通状態で辺ごと消える設計。**地図はその状態を見ずに全部描いていた**＝1783年の画面にパナマ運河の線が出て「そこを通れる」と読めた。⚠経路自体は正しく迂回していた（表示だけの不整合）。
