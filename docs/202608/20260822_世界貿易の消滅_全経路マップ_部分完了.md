## 1. 一番上流の栓 ＝ 数量決定則の「形」（1本の根・3つの顔）

☆売り手側（`PriceOfBread.SimCore/BilateralMarket.cs`）

### 天井の算術（☆コードからの導出。実測ではない）

- 年間輸出 ≤ 4 × 0.05 × (月次規模) ＝ 0.2 × 月次規模、年GDP ＝ 12 × 月次産出
- ⇒ **輸出/GDP ≤ 1.67%**、**(輸出+輸入)/GDP ≤ 約3.3%**（買い手側は gap≤1 のとき）
- モノカルチャーの否定：主食消費の8割を輸入するには `gap = (lp−bestDeliver)/avg ≈ 48` が恒常化する必要がある（`0.05 × 4/12 × gap = 0.8`）。**構造的に不能。**

> **重要な区別**：この天井は「今の0.06%の説明」ではない（0.06% は天井3.3%の約1/55）。天井が言うのは **「下流を何も直しても史実水準には到達できない」** という到達不能性である。今の水準は「天井 × 稼働率2%」であり、稼働率を削っている因子は別に3つある（§2）。この2つを混ぜたことが、これまでの誤診断の反復の原因になっている。

**根R（式の形）**

　↓

　規模は月次・実行は四半期 ⇒ 実効が名目の1/3。天井が 5.0% → **1.67%** に潰れる。係数の見かけ（5%）と実効（1.67%）が一致しない。
　↓
**栓R2（両側が同型・直列min）** ☆`:443` の min の両腕が同じ `TradeSpeed × 地元規模`

**帰結①：価格が収束しない（非清算の定常状態）**

　買い手の q が四半期あたり `0.05 × gap × 月次需要` を超えられない（§1の gap≈48 問題）。

**帰結④：人口が食料輸入で伸びない ＝ ここだけ独立の断線がもう1本ある**（§6）

## 3. 修正の方向（原則遵守＝倍率で目標に合わせない）

### 案A（本命・根R本体）：数量則を「速度×規模」から「裁定が閉じるまで」へ

**何が物理的に正しいか**：貿易量は「どれだけ速く運べるか」という定数では決まらない。**価格差が輸送費＋関税を上回る限り運ばれ、上回らなくなったところで止まる**（一物一価への収束）。速度定数 `TradeSpeed=0.05` は物理量ではなく、「自州の市場規模の5%」という参照点には物理的な意味がない（世界の誰も自州の規模を見て売買しない）。

上限を与えてよいのは物理的な3つだけ：
1. **在庫**（保存則。無から財は湧かない＝`:327` の `Stock` 側は残す）
2. **輸送容量**（船・鉄道・港の実在キャパ＝案C）
3. **買い手の支払能力**（貨幣。☆現在**存在しない**＝`:468 netFlow[ni] -= value` に予算検査は無い）

実装の形：買い手×財ごとに「着値 `bestDeliver` で買って自州の clearing 価格に届くまでの量」を求め、売り手の在庫と輸送容量の配分で切る。`TradeSpeed` は残してよいが、掛ける相手を**地元の規模**から**価格差が示す超過需要／超過供給の量**へ移す（部分調整の時定数としてなら物理的意味がある）。閉じるのは**価格差**であって貿易/GDPではない＝目標値を見ないので原則違反にならない。

**同時に必須**：栓R3の解除（1買い手が次善の売り手へ回れる／1売り手が複数買い手へ売れる反復）。これが無いと、蓋を外しても増分の相当部分が「最高値の買い手による最安売り手の独占」＝**再分配**に化ける（★売り手蓋だけ×1000で英×8.8に対し世界成約額は×2.38）。

### 案B（案Aの前提・単位の是正）：月次スケール×四半期実行の解消

**何が物理的に正しいか**：同じ式の中で月と四半期を混ぜてはいけない。`Market.Step` を月次3回にするか、scale を四半期換算にするか、どちらかに揃える。効きは **×3**（★同等実験＝docs/202608 の実装ログで貿易/GDP 1.25→2.85%）。これは**栓の解除ではなく正しさの修正**であり、必要な×400のうち×3を供給するにすぎない。

⚠**素朴なループ実装は沈黙バグを踏む**（実装前に必読）：
- ☆`ExportsByGood/ImportsByGood` は毎回 `Array.Clear`（`BilateralMarket.cs:189-191`）
- ☆`LastImportValue/LastExportValue` は `+=` でなく `=`（`:515-516`）
- ☆`r.LastPortThroughput = 0`（`:90`）

物理量 `ms.LastExport += q`（`:460-461`）だけは加算されるので `Invariants.cs:113` の在庫恒等式は**緑のまま**。統計・関税徴収基礎（`:517 importVal`）・港湾投資シグナル（`MultiNationSim.cs:565 StepPorts`）・トランジット通行料（`:522`）だけが1/3に残る。**テスト緑を根拠にしてはいけない。**

### 案C：輸送容量を「本物の量の制約」へ格上げ

**何が物理的に正しいか**：19世紀の貿易拡大の主因は運賃低下と船腹増加＝**物理容量が本当の制約だった**。☆現在の `cap` は前月実績からの遅延スロットル（`:139`）で access に掛かる乗数にすぎず、★実測で非拘束＝運賃革命も港湾投資も鉄道も貿易量に効いていない。案Aで速度蓋を外したとき、**次に効くべき蓋がこれ**（容量を財の重量で按分して割り当てる形）。これにより「投資 → 容量 → 貿易 → 富 → 投資」の因果が初めて通る。

### 案D：輸出需要を「需要」として一本化

**何が物理的に正しいか**：生産者は買い手の国籍を見ない。☆現在は地元 `LastDemand` が重み1.0、輸出が `0.25 × EMA`（`EconomyStep.cs:300` vs `:303-304`）と**重みが分かれている**。重みを分けること自体が国別分岐と同型の恣意。同じ需要曲線に載せる。
（☆`ExportSmoothed` の単位は正しい：α=0.1 の月次EMAが四半期パルス X を (X,0,0) で食う定常水準は X/3 ＝月次輸出率＝隣の `LastDemand` と同単位。`:230` のコメントも明言。**ここは単位バグではない**。）

## 【親による検証・2026-08-22】Step 0 は静的に決着 ― 天井式の前提は成立する（測定不要）

これは**走らせずに決着する**。`TargetStock` の定義そのものが月次需要だからである。

```

Coefficients.cs:48  TargetStockBuffer = 1.0
Coefficients.cs:52  TargetStockFloor  = 1.0      ← ゼロ除算回避の絶対床。需要≈0の死んだ財でしか効かない

MarketFlow.cs:21    totalDemand = m.LastDemand   ← EconomyStep.cs:233 で月次リセット・:1261 で月次書き込み
```

⇒ 平時の `TargetStock ≡ 1.0 × 月次需要`。`LastDemand`／`LastProduced`（`:234` リセット・`:1433` 書き込み＝月次）と**単位が同じ**。

⇒ **`WinT` が支配しても天井式は撤回されない**。Step 0 の反証条件は原理的に発火しない。

⚠唯一の例外＝戦時備蓄（`StockpileFactor > 1`＝`WarScareTension` が閾値超）のとき `TargetStock` が月次需要を上回る。

⚠この検証は**天井式（到達不能性）についてのみ**。稼働率2%の内訳（gap／成約率／栓R3）は依然として Step 1 の測定対象であり、
