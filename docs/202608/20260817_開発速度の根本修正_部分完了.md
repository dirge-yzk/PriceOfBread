# 2. ★★★ 決定論の破れを特定する（⚠ 測定並列化の前提）

## ⚠⚠ 「単独で走らせる」の理由は**2つ混ざっている**

| ⚠ 問題 | ★ 正体 | ⚠ 対処 |
|---|---|---|
| ★ **作業ツリーの共有** | ⚠ 「直接ビルドすると他人の編集が混入する」 | ★★★ **§3（コピーで分離）** |
| ⚠⚠ **CPU競合で結果が割れる** | ★ **決定論が破れている疑い** | ⚠ **本節** |

## ⚠⚠⚠ 思想⑥が破れている疑い

> ★ **思想⑥＝同じシードは必ずビット単位で同じ結果。**
> ⚠⚠ **CPU競合で 3/10 と 2/10 に割れるなら、★ シードごとの結果が揺れている。**

★ **候補：**

| ⚠ 候補 | ★ 確かめ方 |
|---|---|
| ⚠⚠ **並列ループの浮動小数の加算順序**（★ 最有力） | ⚠ `Parallel.For` の reduction を探す |
| ★ **同一ティック内の閉路＋反復回数依存** | ⚠ §1 と同じ |
| ⚠ タイムアウトでの打ち切り | ★ 打ち切り条件を探す |
| ★ 測定スクリプト側（⚠ 前回出力の混入） | ⚠ `measure.sh` を読む |

## ★ 実装契約

```
★手順1：再現する
  ⚠同一ソース・同一シードで、★負荷をかけた場合とかけない場合を比べる
  ⚠負荷＝別プロセスでCPUを埋める（★measure.sh を2本同時に走らせる）

★手順2：割れたら二分する
  ⚠1シード×短期間まで縮めて、★どのティックで分岐するかを出す

★手順3：原因が §1（閉路）なら §1 の処方がそのまま治療になる
```

⚠⚠ **潰さないまま並列化すると、★ 測定結果が信用できなくなる。**——⚠ **順序は「①原因特定 → ②ツリー分離 → ③並列化」。**

# 3. ★★ 測定ツリーの分離（⚠ VCS は要らない）

> ⚠ **作者の制約：「現在gitは使いたくない（★ 私のgitは社用なため）。⚠ 類似サービスなら良い。★ ただしclaudeから操作できること。」**

## ★★★ VCS が要る目的は3つで、⚠ どれも git 以外で足りる

| ★ 目的 | ⚠ git 以外の解 |
|---|---|
| ★★ **並列測定のツリー分離** | ★★★ **単なるディレクトリコピー**（⚠ `robocopy` / `Copy-Item`）＝**VCS 不要** |
| ★ **差し戻し** | ★★★ **休眠フラグ規律が既に担当**——⚠ **新機構は既定0で入れる＝差し戻しがコード削除にならない** |
| ⚠ **事故からの復旧** | ★ **日次 zip スナップショット**（⚠ `Compress-Archive`・★ 数MB） |

★★★ **休眠フラグ規律は、実は VCS の代わりでもある**——⚠ **巻き戻しが要らない設計になっている。**

## ★ もし VCS が欲しい場合の候補（⚠ 参考）

| ★ 候補 | ⚠ 評価 |
|---|---|
| ★★ **Fossil** | ⚠ **単一実行ファイル・リポジトリ＝単一ファイル**・★ git と設定が完全に独立・⚠ **CLI で操作可**（★ 要インストール） |
| ★ Mercurial | ⚠ 同様に独立（★ Python 依存） |
| ⚠ クラウドストレージの版履歴 | ★ 導入ゼロだが、⚠ **差分が見えない・巻き戻しが手動** |

⚠ **ただし上の分解が正しければ、★ 導入の必要は薄い。**

## ★ 実装契約

```
★measure.sh を変える
  ⚠測定開始時に作業ツリーを測定用ディレクトリへコピー（★robocopy /MIR）
  ★測定はコピーで走る（⚠作業ツリーは自由に編集できる）
  ⚠終わったらコピーを捨てる（★あるいは SOURCE-HASH 付きで残す）

★日次スナップショット
  ⚠Compress-Archive で PriceOfBread_<日付>.zip（★ソースとdocsのみ・bin/obj除外）
```
