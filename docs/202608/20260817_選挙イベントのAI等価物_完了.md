## 1. 何が非対称だったか

総選挙の公示イベント（E2/E3・`docs/202608/20260814_選挙を動詞にする_部分完了.md` §3-0〜3-3）は実装済みだが休眠
（`Coefficients.ElectionEventEnabled = 0.0`）。その中身が**プレイヤー専用**だった：

```csharp
// 旧・Parliament.cs:89
if (c.ElectionEventEnabled > 0 && w.SelfPower?.IsPlayer == true && w.PendingElection is null
    && !noConfidence && w.QuartersSinceElection == c.ElectionIntervalQuarters - 1)
    w.PendingElection = BuildElectionEvent(w, c);      // ★プレイヤー国にしか公示が立たない
```

- 公示（`PendingElection`）が立つのはプレイヤー国だけ＝**選挙に介入できるのはプレイヤーだけ**。
- AIは常に即決＝素の得票。設計docの当初方針（§6「AIは即決」）どおりだが、
  これは総動員・移民法・国教法・幽霊戦線と**同じ形の非対称**（＝プレイヤーだけが持つ動詞）。
- 点火（E4）すれば、プレイヤーだけが4年ごとに「思想へ加担して得票を+30%まで押す」手を持つ盤面になる。

### 2-1. 付随の是正（同じゲートの内側・既定0で恒等）

政変で議会が消えた（非選挙政体へ転げた）国で、**公示と加担が失効するようにした**。

- 旧＝押し込み（`ElectionPushIdeology`）のクリアは「総選挙が起きた四半期」（`Parliament.cs:102`）にしかない。
  公示から開票までの間に政体が転げると `hasElections=false` で開票が永久に来ず、しかし `ComputeVotes` は毎四半期走る
  （非選挙政体は毎期 `SnapshotSeats`）＝**一度きりの動詞が恒久の議席補正**になる。
- プレイヤー国でも起きる古い穴だが、公示が全国に立つ改修で発生機会が53倍になるため同時に閉じた。

## 3. AIの選好と強さ（既存のどの量から導いたか）

`UtilityAgent.DecideElection`（SelfPlay.cs）。**新しい観測を作らない・固有名詞/年号/`IsPlayer`分岐なし・RNGを引かない。**

### 3-1. どの思想に加担するか（＝綱領選好）

看板 k（＝`ElectionEvent.AgendaAxes[k]` と `AgendaIncrease[k]`）ごとに：

```
align(k) = 支配ブロックの立場   PolicyPreferences.Stance(w, 軸k, 向きk) の3成分のうち1つ
                                  DoctrineFrom(w) = Balanced/Militarist → 旧支配層
                                                    Industrialist       → 近代エリート
                                                    Modernizer          → 大衆
         + AiElectionIncumbentAffinity (=0.5)   if PoliticalQuantities.FamilyOf(思想k) == w.GoverningParty
align(k) <= 0 → その看板には加担しない（NaN もここで落ちる＝否定形ガード）
```

- `DoctrineFrom` はAIが既に毎四半期読んでいる教義（支配ブロック＋親軍法から創発）。その**逆写像でブロックを1つ選ぶだけ**＝新しい判定ではない。
- `Stance` は法律タブのホバーが表示しているのと同じ関数（賛否＝概ね −2..+2）。看板議題への賛否＝**綱領選好そのもの**。
- 与党族との一致は控えめな上乗せ（0.5）＝支配ブロックの利害が主・党派心が従。

### 3-2. どれだけ強く押すか（予算制約の内点解）

```
margin  = MandateWeight × (Legitimacy − 0.5)        ← ResolveElection が「動かせるか」に使うのと同じ量
budget  = 0.5 × margin ÷ (1 + MandateSpent)         ← 政治資本（紛争記憶）で渋る
price(k)= max(0, −NetSupport(軸k, 向きk))           ← ResolveElection が実際に請求する額と同一
price(k) > margin → その看板は捨てる（ResolveElection が拒む線と同じ＝無駄玉を撃たない）
s(k)    = price(k) > 0 ? min(1, budget ÷ price(k)) : 1.0      （無償なら満額）
選ぶのは u(k) = align(k) × s(k) の最大（同点は支持の高い看板＝配列の先＝決定論）
u が無い／s < AiElectionMinPush(0.05) → 静観 ResolveElection(-1, 0)
```

- **代価が高いほど押しは弱まる**（`budget ÷ price`）＝振り切りが常に正解にならない内点解。
  さらに高ければ「余白超え＝動かせない」で**静観**に落ちる＝「代価が高いときは静観する」が式から出る。
- ⚠**純支持は代価としてだけ読む**（意図として読まない＝「通る法しか望まない」トートロジーを持ち込まない。
  意図は `align`＝ブロックの立場が担う）。この禁則は移民制限法のAI（AiLawWriteCoverage）と同じ。
- 判定線3本（0.5 / 0.5 / 0.05）は **SelfPlay私有の定数**＝`Coefficients` に新フラグは作っていない。

### 3-3. 実測でわかったこと（点火前に知っておくべき数字）

単一国（英・seed7・Q6）で全法軸を走査した結果：

- 支配ブロックが推し、かつ世論が逆風（純支持 < 0）の軸は13本ある。**最も安い逆風でも |純支持| ≈ 0.39**。
- 一方、既定較正の余白は `MandateWeight(0.3) × (Legitimacy − 0.5) ≦ 0.15`。
- ⇒ **「正統性を払って世論に逆らう」枝は既定較正ではほぼ到達しない**（プレイヤーも同じ＝「動かせない」）。
  点火後に実際に起きるのは「**無償で押せる看板（純支持≥0）のうち、支配連合の利になるものを選ぶ**」＝
  設計doc §3-3 の狙い（「できるのは傾きかけている天秤を押すことだけ」）どおりの帯にいる。
- したがって点火の主効果は**代価の出血ではなく、AIが自派の思想へ票を寄せること**（族の得票が最大 +30%×強さ）。

## 4. 恒等性

`ElectionEventEnabled = 0`（既定）では：

- `Parliament.Step` の分岐に入らない＝公示も立たず、`UtilityAgent.DecideElection` も呼ばれない。
- `DecideElection` は先頭で `ElectionEventEnabled <= 0` を見て即 return（公開関数として直接叩かれた場合の二重ガード）。
- 非選挙政体の失効も同じゲートの内側＝**1つも状態を書かない**。
- `World.ResolveElection` は従来どおり `ElectionEventEnabled <= 0` の残骸を捨てる。

## 6. 点火A/B手順

ゲートは1本。**点火するとプレイヤーとAIが同時に有効になる**（片側点火はできない＝構造的に非対称を作れない）。

```bash
# A（基線・既定＝休眠）
bash measure.sh /tmp/e4_A.txt selfplay-batch 30
bash measure.sh /tmp/e4_A_int.txt integration            # 総政変（恒等物差し）

# B（点火）
POB_COEF="ElectionEventEnabled=1" bash measure.sh /tmp/e4_B.txt selfplay-batch 30
POB_COEF="ElectionEventEnabled=1" bash measure.sh /tmp/e4_B_int.txt integration
```

⚠ヘッダーの `★係数の上書き（POB_COEF）` 行を突き合わせてから数字を読む（条件の名乗りが先）。
⚠孤児 `PriceOfBread.Runner` プロセスがあるとDLLロックで「ハング」に見える（既知）。
⚠バッチは約11分／`integration` は約5分（`selfplay-batch 30` の後に回す）。

### 見る帯

| 帯 | 出所 | 見どころ |
|---|---|---|
| **政体 exact / near** | `selfplay-batch` の忠実度表（`PrintFidelity`） | 加担で与党が変わる＝綱領（福祉・累進・関税・親軍・労働法）が動く→政体遷移の速度に効く |
| **法の多様性** | `selfplay-batch`「法の多様性」（軸ごとの最頻値シェア） | AIが自派の思想へ寄せると法が**収束する**方向（最頻値シェアが上がれば行き過ぎ） |
| **総政変** | `integration` の「政変：総遷移 N 回」 | 加担が政権交代を減らす（現職の延命）か増やすか＝恒等物差し |
| **選挙回数・平均間隔** | `selfplay-batch`「選挙（E0計器）」＝`AvgElections` / `AvgElectionIntervalQ` | 押し込みで与党得票が上がる＝不信任（`NoConfidenceThreshold`）の繰り上げ選挙が減るはず。**回数が減る方向が想定挙動**・増えたら押し込みの符号を疑う |
| 破綻・ハーネス | `破綻(未完走)` / `ハーネス不合格を含む試合` | 0 を維持（裁定順序「破綻しない ＞ 正しい挙動 ＞ バランス」） |

| | A（休眠） | B（点火） |
|---|---|---|
| 完走 | ○ | ○ |
| ハーネス | 〇9 △0 **×1** | 〇9 △0 **×1**（同じ検査＝「下流の無い財」＝**基線由来**・本改修と無関係） |

### 想定される効き方（点火前の予想＝外れたら疑う）

- 代価はほぼ発生しない（§3-3）＝**正統性の帯は動かないはず**。動いたら「余白超えの判定」か `MandateWeight` の読み違い。
- 効くのは4年に1度・1回の開票だけの ±30%×強さ＝**単発の弱いブースト**。帯が大きく動いたら、
  押し込みが開票以外の四半期にも効いている（＝失効の穴）を疑う。
- AIが自派へ寄せる分、**与党の固着**（同じ族が居座る）が増える方向。総政変・法の多様性で見る。

## 7. 残した論点（作者裁定待ち）

1. **代価の逓増**（設計doc §3-3「大きく動かすほど単価が上がる」・App のスライダー注記も「代価は逓増」と書いている）は
   **未実装**＝現在の代価は強さに**線形**（`Legitimacy −= |純支持| × 強さ`）。本ラウンドは共有関数を変えない方針で据え置いた。
   AI側は予算制約で内点解を出すので「振り切りが常に正解」にはならないが、**プレイヤーのスライダーは無償の看板では常に振り切りが最適**。
   逓増を入れるなら `World.ResolveElection` の1か所＝プレイヤー/AI同時に効く（AI側の式は変更不要）。
2. **代価の国庫項**（設計doc §3-3・E7）は枠だけ＝未実装。入れる場合も同じ1か所。
3. **AIの加担を外交ログに出すか**（`Diplomacy.Log`）＝現在は出していない。年表（chronicle）に「◯◯党へ加担」が並ぶと
   点火後の挙動が読みやすいが、53カ国×4年ごと＝1試合1,700行の増加になるため保留（lean バッチではログ自体が止まる）。
4. E4の点火そのもの（`ElectionEventEnabled = 1`）は上のA/Bを取ってから。
