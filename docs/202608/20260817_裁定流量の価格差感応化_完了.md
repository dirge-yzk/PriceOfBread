# 1. 律速はどちらの側か（**診断でなくコードで確認した**）

「売り手の流量だけ増やしても買い手側の `q = Math.Min(q, left[best])` で切られるなら効かない」を、
**計数を仕込んだスナップショット**（作業ツリーは汚さない）で実測した。`tradeprobe`（1789シード・53カ国・Q200）を
四半期ごとにリセットして数える：

- 売り手候補の `left = min(Stock, Flow)` が**どちらで決まったか**（流量律速 / 在庫律速）
- 成約1件ごとに買い手の希望 `q` が `left[best]` で**切られたか**（切られた件数・切られた額）
- 提示量（Σ`left`初期値）のうち**実際に動いた割合**・**枯渇した売り手の割合**

| Q（年） | 流量律速の売り手 | 提示量に対する成約 | 枯渇した売り手 | 売り手蓋で切られた成約 | 希望額に対する成約額 |
|---|---|---|---|---|---|
| 40（1793） | 97.0% | 6.2% | 8.4% | 19.3% | 77.0% |
| 80（1803） | 96.2% | 4.9% | 9.2% | 20.3% | 74.3% |
| 120（1813） | 95.6% | 2.9% | 8.4% | 19.2% | 65.7% |
| 160（1823） | 94.8% | 2.1% | 8.4% | 23.3% | 66.9% |
| 200（1833） | 84.5% | 1.5% | 8.6% | 25.0% | 62.8% |

**答え＝両方。ただし役割が違う。**

- **総量の水準を決めているのは買い手側**：提示量の 1.5〜6% しか動いていない。
  買い手の `q` は `access × TradeSpeed × ((lp−着値)/avg) × 規模` で、価格差に**既に比例している**。
  つまり「価格差を見ていない」のは売り手だけで、買い手側には感応が**すでに入っている**。
- **裁定チャネル（最安の産地）の律速は売り手側**：売り手候補の **95%前後が在庫でなく流量（＝定数蓋）で止まっている**。
  そして買い手は「自分のところへ最も安く着く売り手」を選ぶので、**安い産地に注文が集中して蓋に当たる**
  ＝成約の 19→25%・希望額の 23→37% が `left[best]` で切り落とされ、売り手の 8〜9% が毎期枯渇する。
  枯渇した瞬間に買い手は次に安い売り手へ移る＝`bestDeliver` が上がる＝**値崩れが世界価格に伝わらない**。

**よって蓋を上げるのは売り手側だけでよい。**買い手側に同じ価格差指標を掛けると、
`q` の中の `(lp−着値)/avg` と**二重に効いて価格差が二乗**になる（＝二重計上）。係数は1本のまま、売り手側だけに入れる。

# 2. 実装（`BilateralMarket.cs` 売り手Flow・係数1本）

```
旧： flow = sellAcc × TradeSpeed × scaleS                      （在庫と規模だけ）
新： x    = avg / lp − 1                                        （裁定margin＝「世界平均で売れば何割乗るか」）
     flow = sellAcc × TradeSpeed × scaleS × (1 + x/(1 + x/K))   （K = TradeArbitrageMax）
```

- **指標は既存の量だけで作る**：`avg`（その財の世界平均＝その場で計算済み）と `lp`（その州の金建て局所価格）。
  新しい観測・新しい状態・新しい配列は1つも増やしていない（セーブにも何も足さない）。
- **自己有界の形＝`x/(1+x/K)`（採った理由）**
  - (a) `x` が小さい領域では `f ≈ x`＝**線形**。平時（世界平均の±数割）の挙動を歪めないので、較正済みの基線を静かに壊さない。
  - (b) 上限が `K` そのもの＝係数が「**最大何倍まで速く出せるか−1**」として読める。掃引の物差しになる（1.0で最大2倍・4.0で最大5倍）。
  - (c) `clamp`（壁）と違い微分が連続＝閾値の前後で挙動が飛ばない。作者の流儀「壁でなく逓減」（思想⑧の条件②）。
  - 有界にする理由＝上限のない乗数だと `lp→0` の産地から在庫が尽きるまで無限に流れ、**値崩れが「無限の輸出能力」に化ける**。
- **在庫の蓋は不変**：`left = min(Stock, Flow)` はそのまま＝**無から財は湧かない**（速くなるのは「持っている物を出す速さ」だけ）。
- **決定論**：辺の処理順・売り手の並べ替え（価格昇順→同値は州名で全順序）・買い手の走査順に**一切触っていない**。変えたのは流量の値だけ。
- **既定0で厳密恒等**：`bool arbOn = arbMax > 0;` の**分岐ごとスキップ**＝`(1 + 0×…)` のような乗算を1個も残さない
  （浮動小数の結合が変わると決定論軌道が変わる前科＝`Fiscal.cs` の警告）。NaN は `arbOn` も `boost > 0` も false 側＝**休眠へ倒れる**。

係数（`Coefficients.cs` 国際・世界市場の節・`TradeSpeed` の直後）：

```csharp
public double TradeArbitrageMax = 0.0;   // 0＝休眠（厳密恒等）／>0＝上乗せの上限倍率−1
```

| 3 | `9.0`（最大10倍） | 未測 | 上限側の探り。1.0→4.0 で効きが 1.9→2.1 倍にしか伸びていない＝**既に飽和域**なので、ここで頭打ちが確認できれば掃引は終わり |

**その腕で必ず見る帯**

1. **貿易/GDP**（`tradeprobe`／忠実度計器の**貿易開放度**次元＝`HistoricalReference.TradeOpenness1913`・9カ国±50%）＝この改修の目的関数。
2. **exact / near**（`selfplay-batch 10`）＝忠実度の本体。⚠バッチは親が回す。
3. **硬性ゲート＝破綻0・ハーネス0/10**。
4. **`leakhunt` 清潔**（保存則）。売買の額と量の対応は触っていないが、国際清算の中核なので毎回見る。
5. 副次で **経済規模**の次元（§4-23 の前科＝速度を上げると参照8カ国のGDP順位が大きく動く。
   `TradeSpeed` を3倍にした診断では 経済規模 28.8→17.5 だった＝**この腕でも同じ形の劣化が出るなら Search 同時再較正へ回す**）。

判定順序は `pob-fix-priority-2026-08-01`（**破綻しない ＞ 正しい挙動 ＞ バランス**）。
帯の悪化だけでは差し戻さない（記録は必須）が、**破綻>0・硬性ゲート赤・テスト赤は即差し戻し**。

⚠この係数は `TradeSpeed`（較正済みライブ）と**同じ次元を触る**（量の速さ）。
§4-23 の裁定「手回しの `TradeSpeed` 変更は禁止・採用するなら Search 再導出とセット」と同じ扱いにするのが筋なので、
点火して帯が動いた場合の本線は **Search の探索空間へ `TradeArbitrageMax` を足して同時再較正**すること
（`TradeSpeed` / `ExportDemandWeight` / `TransportMargin` / `TradeBandWiden` と同居させる）。

# 6. 触っていないもの（次ラウンドの候補）

- **買い手の `q`**＝既に価格差比例なので触らない（同じ指標を両側に掛けると二乗＝二重計上）。
  ただし**総量の水準を決めているのは買い手側**（提示量の1.5%しか動いていない）＝
  §4 の効きが足りない（1914 で ×1.16 しかない）以上、次の一手は「買い手側の**水準**」＝`TradeSpeed` 本体か
  `scaleT`（規模の取り方）であって、価格差の感応をもう一段足すことではない。
- **時間とともに交易が死ぬカーブ**そのもの（OFF/ON とも 1783→1914 で1桁落ちる）。
  裁定の蓋を外しても形が変わらない＝**別の律速が下に居る**。`pob-world-trade-collapse` の本丸はここ。
  容疑の順は (a) 価格分散の消滅（全州自給＝`tradewhy` の「必要比」を分散が下回る） (b) 買い手側の水準（`TradeSpeed`・`scaleT` の床）
  (c) 生産目標の輸出応答（`ExportDemandWeight` の複利が回るか）。
- 鋼市場診断の **#7 恐慌の資本破壊を `BuiltScale` へ**・**#8 国際市場の買い手に支払い能力検査**（国内popとの非対称是正）。

# 7. 測定の作法メモ（次に測る人へ）

- **計数は本体に残していない**。律速の切り分け（§1）は**スナップショット側だけ**に一時的な静的カウンタを足して測り、
  作業ツリーには1行も入れていない（テレメトリを恒久化すると、休眠のはずの機構が「何かを書く」状態になる）。
  同じ測定を再現したいときは `BilateralMarket` の `left[s]` 初期化直後と `q = Math.Min(q, left[best])` の直後に
  カウンタを置き、`tradeprobe` の四半期ループでリセット＋印字する（本doc §1 の6列がそのまま出る）。
