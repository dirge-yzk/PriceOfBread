## 4. 残存タスク：交易テストの物差しの是正

`ServiceEconomyTests.距離の遠い国は輸送マージンが嵩み交易が細い` は長く赤だった。

**原因＝テストの物差しが間違っていた**（エンジンは正しかった）。
`|CumulativeTradeFlow|` は**貨幣保存の台帳**で、植民地収入（`Colonial.cs:183`）・外債の元利
（`CapitalMarket.cs:236/252`）・貢納・拿捕まで載る。しかも**純額**なので、
輸出入が拮抗する中継貿易国（イギリス）ほど小さく出る＝「交易の厚さ」とは**逆向きの量**だった。
テスト側で外交を凍結する対処が既に一度入っていたが、植民地収入と資本移動は凍結では消えない。

**修正**＝本ゲームが既に「貿易取扱高」と呼んでいる量（`MultiNationSim.cs:741`）＝
輸出額＋輸入額の総額をランを通じて積算して比較。→ **緑**（距離の壁は実際に効いている）。

## 5. 多エージェント監査で出た実バグ5件（同日修正）

3法の固着・着工動詞・変更点の3方向を並行で監査させた結果。

### 5-1 束の横取り（★私が入れた着工ガードが露出させた回帰）

建設の束は個体ではなく**州**（`Region.MonumentBuiltUnits`）に溜まる。host 州を共有する組が3つある
（ロンドン＝水晶宮/地下鉄、ベルン＝ゴッタルド/アルプス水力、カイロ＝アスワン/ケープ＝カイロ鉄道）ため、
「誰の束か」が会計上決まっていなかった。旧実装は `dip.Megaprojects` のリスト順の先頭が全部さらう。

**実測（seed1・chronicle）**＝着工17件に対し**完成18件**。ロンドン地下鉄（1852）とアルプス水力発電所（1890）は
**着工ログが1本も無いのに完成**し、工業化+0.2／送電容量+4.0 を無償で取得していた。

**修正**＝`Megaproject.PendingClaim`（前四半期の拠出額）を持たせ、`Step` の先頭の前処理 `CollectBuiltUnits` で
州の束を拠出比で按分。払った者が受け取る。未着工は拠出0なので1単位も受け取らない。

### 5-2 一覧が戦争タブに入っていた（到達不能）

`BuildMegaRows()` は `RefreshProduction()` からしか呼ばれず、`RefreshProduction` は `ProdOpen` の時だけ走る。
一方マークアップは `TabWar` の中にあった＝**全画面の生産タブを一度も開かないプレイヤーには節ごと出ない**。
生産タブのオーバーレイへ移設（資材と労働を市場から買う建設は生産の話）。四半期tickでの追従は
`GameViewModel.cs` の `if (ProdOpen) RefreshProduction();` で既に効いている。

### 5-3 穀物法の飢饉閾値が常態を拾っていた（固着の主因①）

`famineNow = 1−FoodFill > 0.05` は、`Coefficients.DynMandateFoodAnchor=0.8` のコメントが既に
「1.0基準は慢性輸入国＝英を常時罰する。**罰すべきは飢饉であって輸入依存ではない**」と否定していた水準。
第1分岐がほぼ常に真になり、都市化の2分岐が一度も判断に効かない死んだ枝だった。

**修正**＝既存の較正済み基準 `w.Coef.DynMandateFoodAnchor` を使う。判定は否定形 `!(FoodFill >= anchor)`（NaNは飢饉側）。

### 5-4 地代余地が非RGO工場を数えていた（固着の主因②・自己触媒ラチェット）

`FarmRentCap` が律速するのは **RGO のみ**（`EconomyStep.cs` の `s.IsRgo ? Min(...) : s.RentShare`）なのに、

**修正**＝`if (!pr.IsRgo) continue;`。分母も**全RGO数**へ（超過件数で割ると200件中1件でも全部でも同じ値になり、
問題の広がりが消える）。

### 5-5 AIが結局全件着工する＝動詞の意味がAI側に無い

## 7. バランス調整ラウンドへの引き継ぎ（最重要）

計器を直したことで、**これまで見えていなかった逸脱**が国別に出るようになった。

| 国 | 法一致 | 何が外れているか |
|---|---|---|
| プロイセン | **18 %**（6軸） | 穀物法＝保護に戻らない／土地改革＝ユンカー農場が解体される |
| ポルトガル | 27 %（3軸） | 同上 |
| フランス | 44 %（5軸） | メリーヌ関税に相当する保護回帰が出ない |
| オーストリア | 45 %（4軸） | 土地改革＝マジャール大貴族領が解体される |
| 日本 | 45 %（4軸） | 参政権・教育の側 |

**構造的な原因**＝現行のAI規則は穀物法を `UrbanShare`（都市化率）で判断するが、史実の農業保護を決めたのは
都市化率ではなく**地主層の政治的比重**である。ドイツは都市化していた（1914年に約6割）が、
ユンカーが不釣り合いな政治力を保ったから保護へ回帰した（「鉄とライ麦の結婚」）。英は逆に、
1846年時点で地主が製造業に敗れていた。

したがって正しい入力は「都市化率」ではなく「地主の政治的比重」だが、これは勢力（faction）の機構に触れる設計判断であり、
設計書が明示的に警告した「`PolicyPreferences` を意図として読むとトートロジーになる」問題と隣接する。
**バランス調整ラウンドで作者の裁定を仰ぐべき筆頭項目**として記録する。

## 10. 「商品をクリックするとフリーズする」の根治（作者報告・同日）

### 症状と正体

作者報告「商品をクリックするとフリーズする」。§9-3 で塞いだつもりだった Polyline の null が、
**別経路で残っていた**。

`BuildWorldSpark` は世界価格の点列を `"x,y x,y …"` の**文字列**で返し、`Polyline.Points` へバインドして
Avalonia の型変換に解析させていた。価格に非有限値が1つでも混じると `"NaN,NaN"` になり、
**変換が null を返す**。Polyline は Points が null だと `MeasureOverride` の `CreateDefiningGeometry` で
ArgumentNullException を投げ、毎フレーム**レイアウトごと**中断する＝操作を受け付けない。

§9-3 の対策（VM 側で非nullを返すプロパティ）は「経路の途中が null」だけを塞いでおり、
**文字列の解析が失敗して null になる**方は残っていた。

### 直し方＝文字列を描画経路から消す

`BuildWorldSpark` の戻り値を `string` → `Avalonia.Points` に変更。点列を自前で組むので解析が起きない。
非有限値は否定形 `!(v > double.MinValue && v < double.MaxValue)` で点ごと落とす（NaN も弾く）。
`ProdDetail.WorldSparkPoints` も `Points` 型へ、`HasWorldSpark` は点数で判定。

### 検証手段の穴を埋めた

uishot に「**財を選択して撮る**」段を追加（`SelectProdGood(32)`＝鋼）。
それまで右の詳細パネルは無人検証の穴で、この型の不具合を一度も踏めていなかった。
追加した直後の実行で例外が **8→9** に増えて再現し、修正後は **9→9**（増えない）で確定。

判定は `crash.log` の `UIThread例外` 件数を before/after で数えるのが最速。

### 併せて直した取りこぼし

前段のスクリプトが途中で落ちて連鎖が切れ、**スタイル定義が1つも入っていなかった**
（`TextBlock.use` / `.unused` / `Button.row:disabled` / `ToggleSwitch.mini`）。
＝用途の灰色もトグルの幅も効いていなかった。追加のうえ実画面で確認：

- 補助金・消費税＝コンパクトなトグルスイッチ（On/Off の英語ラベルは撤去）
- 州別の着工ボタン＝「**工場 着工 £70k・2.0年**」（RGO の「プランテーション 着工 …」と揃った）

## §18 決定論の破れ＝**海ノードのキャッシュ**（2026-08-04・§17の訂正の訂正・根因確定）

§17 で「引数の誤りだったので破れは実在しない」と書いたが、**それも誤りだった**。
引数の誤り（第2引数＝金利に `0` を渡していた）は実在したが、それは**真の破れを覆い隠していただけ**である。
条件を揃えた比較で破れが確認された：

| 指標 | 既定並列 | 並列度1 |
|---|---|---|
| 平均首位確定 | Q547 | Q485 |
| 終盤決着 | 6/10 | 3/10 |
| 分離独立の建国 | 106回 | 124回 |

### 切り分け

1. **同一並列度で2回** → 差分**0行** ＝ 競合（レース）ではなく、**スレッド数で決まる順序効果**
2. `[ThreadStatic]` スクラッチの再利用を無効化 → 結果は**1バイトも変わらず**
   ＝ `EconomyStep.RentScratch` のビット恒等は**実測で証明**された（コメントの主張は正しい）
3. 残る「プロセス全体で共有され、到達順に依存しうる状態」＝ `SeaGraph` のキャッシュ

### 根因

```csharp
public static int NearestSeaNode(double lat, double lon)
{
    var key = ((int)Math.Round(lat * 10.0), (int)Math.Round(lon * 10.0));   // ← キーは0.1°に量子化
    if (NearestCache.TryGetValue(key, out int cached)) return cached;
    ... Geo.DistanceKm(lat, lon, ...)          // ← 計算は元の高精度座標
    ... StitchCrossesLand(lat, lon, ...)
    NearestCache[key] = pick;
}
```

**キャッシュ値がキーの関数になっていなかった。** 同じ0.1°マスに落ちる異なる地点は互いに違う答えを出しうるので、
そのマスの値は「**どの試合のどの地点が最初にそのマスへ来たか**」で決まっていた。
`NearestCache` は `static` ＝プロセス全体で共有されるので、これは**試合をまたぐ汚染**である
（試合Bの海路が試合Aの貿易重心に依存する）。貿易重心は毎四半期動くので、この経路は常時踏まれる。

並列度を変えると試合の到達順が変わる＝同じシードでも結果が変わる。
「バッチでseed8が落ちるのに単走では落ちない」も同じ現象だった。

### 修正

**マスの代表点（格子の中心）で計算する**。これでキャッシュ値がキーの純粋な関数になり、到達順に依存しない。
粒度は変えていない — 旧実装も既に量子化した答えを配っており、**どの代表点かが不定だっただけ**。

実測＝既定並列 vs 並列度1 の差分**0行**・硬性ゲート全緑（破綻0/デッドロック0/異常0/ハーネス0/10）。

### 教訓（キャッシュの不変条件）

**量子化したキーで引くキャッシュは、値も量子化した入力から計算しなければならない。**
キーより細かい情報を計算に使うと、キャッシュは「最初に来た者勝ち」の隠れた大域状態になる。
`static` キャッシュでは、それがそのまま試合間の汚染になる。

同型の点検先＝`RouteBasinCache`（キーは(s,t,cfg)＝離散・純粋）・`DistCache`（同）は無罪。

## §21 法改正を難しくする（2026-08-04・作者指示「強権のたまりが早く、あまりに早期に近代的な法律を取り入れすぎる」）

### 21-1 実測＝**強権は主因ではなかった**

`lawtiming`（新設・1試合を通して各国が各段の法へ到達した年を出す）で見ると：

|---|---|---|---|---|

**全て同年**＝政変1回で近代法制が丸ごと手に入っていた。
根因は `Politics.RaiseFoundingInstitutions` が政体の含意水準へ**一足飛びに直接代入**していたこと（立法の門を通らない）。

### 21-2 実装（5点）

1. **参政権を憲法級に**（`ConstitutionalMandateScale = 0`）＝参政権/女性参政権/秘密投票では**マンデート余白が効かない**。

   負側（信を失った政権の滞り）は非適用＝非対称は維持。
2. **強権の回復を半減**（`MandateRecoveryRate` 0.07→0.035）＝時定数≈3.5年→≈7年。押し切りの連発を封じる。

## §22 近代化投資（2026-08-04・作者仕様(2)「工業化投資を近代化投資に変更する」）

### 22-1 実装

- **改称**＝`IndustryInvestFrac`→`ModernizationFrac`・`ApplyIndustryInvestment`→`ApplyModernizationInvestment`・UI表記「近代化投資」（30箇所）
- **予算の基礎**＝国庫比 → **GDP比の絶対額**。旧 `frac × 国庫 × 0.5` は国庫比なので frac=1.0 が常に「国庫の半分」＝
  **どの国でも必ず払える**。「100%はほとんどの国で不可能なほど高額」は費用が国の**規模**に対して決まって初めて成立する。
- **凸型**＝`A × GDP × コスト倍率 × frac/(1−frac)`。frac→1 で**発散**＝閾値でなく形として不可能。
  A=1.0 で frac=0.3 が四半期GDPの0.43倍＝**年GDP比11%**（発展途上国家の投資率として妥当）。
- **コスト倍率**＝`1 + 1.5×制度疲労 + 1.0×技術遅れ`（清 約2.2倍）
- **制度疲労の改善**＝**実現した建設**に比例（`ModernizationDecayRelief=0.10`／約20年で疲労0.8を解消＝明治型）。
  ⚠予約でなく実現量に比例＝**新しい金の流れを作らない**（保存不変）
- **技術**＝直接チャネルは**置かない**（既定0）。制度疲労は既に技術採用を律している（`DecayTechAdoptWeight`）ので、
  疲労を削れば技術はその経路で伸びる。二重計上を避ける。
- **旧体制の反対**＝旧支配層の政治力シェアで予算が削られる（`ModernizationOldGuardResist=0.5`）。
  免許・検地・認可を握るのが旧支配層＝制度疲労が彼らの政治力を膨らませる既存経路と結び
  「改革を要する国ほど改革できない」が創発。
- **疲労ペナルティ強化**＝3チャネルとも 0.55 → 0.75

### 22-2 測定で3度赤を出して直した（記録）

1. **技術がフロンティアに張り付いた**＝絶対加点にしたため公教育の普(0.31)と宗教教育の露(0.31)が同値になり、
   「教育が技術を分ける」中核の不変条件が壊れた（テスト赤）。→残差比例へ→さらに**チャネルごと畳んだ**（二重計上）。
2. **英が覇権でなくなった**＝線形 `A×GDP` にしたら通常域（frac≈0.3）まで一緒に潰れた（テスト赤）。
   旧式は英に**四半期GDPの約80%**を投資させていて、それが覇権の源だった。→**凸型**で通常域を残しつつ100%を発散させる。
3. **トスカーナが7/10で最下位**（要注意フラグ赤）＝旧体制の反対0.8が小規模貴族国の近代化を完全に潰した。→0.5へ。
4. **列強・再現率 −11pt**＝罰（0.75）だけ重くして**除去速度が足りていなかった**（0.02では疲労0.8の解消に100年超）。
   作者指示は「取り除きやすくなる**から**罰を大きくする」という条件付きの組で、前提が満たされていなかった。→0.10へ。
   ⚠A を 1.0→2.0 にしても列強は**±0.0**＝予算水準は原因でないと切り分けられた。

## §23 戦争のラウンド化（2026-08-04・作者仕様(1)）

**戦争の解決は元から月次だった**（`war.Months` が月で進み、毎月1回の押し合いが走る）＝ラウンドの実体は既にあり、
欠けていたのは**その月に何が起きたかが見えない**ことだった（終戦時に一括で結果が出るだけ）。

新しい判定は足さず、その月の押し合いの結果をそのまま年表へ書く＝表示と物理が同じ。

```
1786/02 陸戦 - イギリスがオスマンに快勝（戦況 イギリス優勢0.06・1ヶ月目）
1786/02 海戦 - フランスがイギリスに圧勝（戦況 フランス優勢0.10・1ヶ月目）
```

- **陸戦/海戦**＝上陸ゲート（landP）で決まる。陸で押し合えない月は海の戦い（制海権の奪い合い）
- **度合い**＝その月の戦勝点の動き÷崩壊点（圧勝/快勝/辛勝）。別の物差しを作らない
- **戦況**＝累積戦勝点は war.A から見た符号なので、そのまま出すと「英が快勝（戦勝点−0.06）」と読めて意味が通らない
  （その月の勝ちと戦争全体の優勢は別物）。**優勢な側の名前**で語る
- 月カウンタを Diplomacy へ追加（増加点は月次の戦争ループ1箇所のみ・年の切り替わりで1へ戻す＝決定論）

### ⚠浮動小数の結合順で帯が動いた（記録）

記帳のため `delta` を変数に括り出し `war.Score + delta` に書き換えたところ、
`(Score + X) + luck` → `Score + (X + luck)` と**結合順が変わって最終ビットがずれ**、
純記帳のはずが**帯が動いた**（政体exact+1.9・列強+3.8）。
状態更新の式は**元のまま一字も触れず**、delta は表示専用に別途計算する形へ是正。
再測定で帯が完全に一致（差分が正確に逆向きに戻った）＝**ビット恒等を確認**。

## §24 材ごとの売買方針（2026-08-04・作者仕様(3)「高く買う/安く売る」）

**既存のダンピング（負の関税＝全財一律の輸出補助）と同じ保存経路**（国庫→商人＝`PaySubsidy`）に載せる＝新しい金の出口を作らない。

- **高く買う**＝その財の輸入の敷居を `TradeBiasStrength`(0.25) 下げる（他国より高く付けて引き込む）
- **安く売る**＝その財の輸出の敷居を同じだけ上げる（安値でも売れる）
- 代金は**取引が立った分だけ**国庫から。国庫が尽きれば部分払い＝効果も自然に細る
- `World.GoodTradeBias`（sbyte配列・未使用なら空＝厳密恒等）／`SetTradeBias` がプレイヤーとAIの共通の入口
- **AI**＝在庫が目標の半分未満で「高く買う」・2倍超で「安く売る」・財政逼迫（>0.4）で全部畳む
- **UI**＝生産タブの財パネルに補助金/消費税と並べて排他トグル2つ＋**輸入表示**（`輸入 n／月（国内需要のn%）`）

帯＝政体exact +1.3・経済規模 **+5.0**・法 −2.5・領土 −2.5／exact 26・near 63。硬性ゲート全緑。

## §25 条約港（2026-08-04・作者仕様(4)）

遠く離れた国は**属国として統治できない**（守備兵も総督も送れない）。史実の遠隔地への圧勝の帰結は
領土でも従属でもなく**賠償金と通商特権**だった（南京条約1842・安政条約1858・下関条約1895）。

- 首都間距離 > `TreatyPortWinnerDistanceKm`(6000) の相手には**属国化せず**、条約港を1つ開かせ賠償を2.5倍にする
- 条約港の実体＝**関税自主権の喪失**。不平等条約の中身は「開港」と「協定関税」で、後者がゲーム上効く量
  （清は税率を自分で決められなくなった）。1港につき実効関税が25%失われ4港でゼロ
- **最恵国待遇で特権は全列強へ波及した**ので許与相手を選ばない＝二国間テーブルを持たない（モデルの粒度と一致）

⚠**賠償の倍率は取り立ての前に掛ける**：最初は講和の後段で追加徴収したが、その時点では通常の賠償で
敗者の国庫が空＝**常に0**だった（実測）。金は「取れる時に取れるだけ」しか動かせない。

実測＝`1796 朝鮮がイギリスに条約港を開かせた（第1港・賠償4,888）`／`1804 オーストリアがアメリカに（賠償16,199）`。
近距離ペアは従来どおり属国化＝距離ゲートが効いている。硬性ゲート全緑。

## §26 陸海の熟練度と維持費の分離（2026-08-04・作者仕様(5)）

### 26-1 維持費の分離（割り振りの廃止）

真の状態を**2本の維持費**（`World.ArmyUpkeep` / `NavyUpkeep`）にし、`MilitarySpending` をその**和＝派生量**にした。
これで軍隊規模・軍需予算・親軍の政治力・圧政といった**既存の読み手は1行も変えずに動く**（書き手は4箇所だけ＝按分口 `SetMilitarySpending` で受ける）。

**海軍シェアは払った金の比**（`NavalSpendShare`）から出す。旧＝地理（外洋に開くか・植民地数）から自動で決まり、
プレイヤーもAIも直接は動かせなかった＝「割り振り」という抽象レバーが実体のない場所に座っていた。
地理由来の値は**AIの目標**として残るので英が海軍へ寄る傾向は保たれる。`NavalShareFromUpkeep=0` で旧＝厳密恒等。

### 26-2 熟練度

平時は維持費が `SkillUpkeepThreshold`(0.5) を超えれば育ち、下回れば錆びる。戦争（内戦含む）は別に育てる＝実戦は訓練に勝る。
`SkillDecayPerQuarter=0.0115`＝**約2世代（60年＝240四半期）でほぼ完全に失われる**（0.9885^240≈0.06）＝訓練された世代の退役。

| 接続先 | 効果 |
|---|---|
| 戦力 | 最大2倍（`SkillCombatMax=1.0`・陸海それぞれ） |
| 総動員 | 国民意識ゲートを緩める（予備役幹部がいれば急な動員でも部隊の形になる） |
| 緊張 | **軍隊規模に乗算**＝小国の精鋭は怖くないが大国の精鋭は怖い |

### 26-3 戦時の下限ロック

`WartimeUpkeepFloor=0.8`＝戦争中は目標を現在値の80%より下へ置けない（戦争中に軍を解散できない）。
**機構側（`Government`）でクランプ**＝AIもプレイヤーも同条件。UIの床は同じ式の表示。

### 26-4 UI

「軍事費」1本＋「海軍偏重」を廃し、「陸軍維持費」「海軍維持費」の2スライダーへ。各行に実効値と熟練度。

### 26-5 測定

テスト **184/184**・硬性ゲート**全緑**。帯（対 §25）＝政体exact −2.0・列強・再現率 **+5.0**・経済規模 +3.8・領土 −7.5。
**exact 24 / near 69**（目標≈70%）・法一致 51%＝**この一連で最良の near と法**。

## §27 熟練度の水準・用語・官僚制度の既定（2026-08-04・作者の4指示）

### 27-1 「最大2倍は史実的に適切か」への判断＝**1.5倍へ**（`SkillCombatMax` 1.0→0.5）

1. **訓練・経験だけ**の効果を定量化した実証（デュピュイの戦闘効率指数が最も引用される）は独軍の対英米で1.2〜1.5倍。
   2倍前後に届くのは対ソ連の緒戦だけで、しかもその数字は**装備と教義**を含む。兵数と装備を揃えた練度だけの差は1.3〜1.5倍が中心。
2. このエンジンには**技術による軍質の倍率が既にある**（`TechMilLowFloor` 0.4→1.0＝2.5倍の幅）。
   そこへ練度で2倍を重ねると合計5倍の幅になり、**同じ「精鋭軍」を二重に数える**。
   オムドゥルマンやアヘン戦争の一方的な結果は練度でなく技術の差で、既に技術側が担っている。
3. 作者指示は「最大でも2倍**程度**に留める」＝上限の指定なので1.5倍はその範囲内。

### 27-2 熟練度の表示は0〜100

`熟練 45` の形。**%を付けない**のは割合ではないから＝「兵の何%が熟練」ではなく軍全体の練度の指標で、%は意味を誤らせる。

### 27-3 「フロンティア」を廃止（全20ファイル）

`TechFrontier` → `WorldTechLevel`／日本語は「世界の技術水準」。
UIには元々出ておらず、コード内の用語とコメントで使われていた語。

### 27-4 官僚制度の既定を縁故任用（Spoils）へ

資格任用は**例外であって出発点ではない**（英ノースコート＝トレヴェリアン1854・米ペンドルトン1883）。
旧＝`Policy`/`World` の既定が `MeritExam` で**全53カ国が1783年から資格任用に到達済み**＝
それを前提にした法（社会保障の高段/独占禁止/国有化/累進課税＝§21で追加した前提）が最初から満たされ、
**制度の階段が1段まるごと存在しなかった**。

- `NationConfig.Bureaucracy`（既定 Spoils）→ `Scenario.InitialBureaucracy` → `World.Bureaucracy` + `Policy.Bureaucracy`
- 史実の例外は world.json で個別指定＝**清（科挙）・プロイセン（文官制度）は MeritExam で開始**
- ⚠`Scenario` 側の既定は `MeritExam` のまま＝**単体テスト/較正harnessは不変**（行政効率に倍率が乗らない中立点）

### ⚠残った課題（次ラウンドの主題）

**資格任用の到達年は依然としてほぼ全国1783年**（実測）＝AIが即座に目標化し門が緩い。
参政権で見つけたのと**同じ構造**（§21-1）で、既定値の是正だけでは階段が立たない。
`列強・再現率 −11.2`（§22-3）と併せて独立した較正ラウンドで扱う。

### 27-5 最終測定（§27の4項目こみ）

テスト **184/184**・硬性ゲート**全緑**。帯（対 §26）＝政体exact +2.2・法 −4.4・列強・再現率 +1.3・
経済規模 −1.3・**領土・植民地 +11.7**／**exact 26・near 66**。

## §28 海軍配分の実装漏れ（2026-08-04・§26の自己バグ）

### 28-1 症状

§27の測定を読み込むと1914年の姿が壊れていた：

| 国 | 国力順位 |
|---|---|
| イギリス | 13位 |

| プロイセン | 30位 |
| オーストリア | 40位 |

海軍順位の1〜8位が**全てアジア**（成都王国/清/チベット/日本/朝鮮/アワド/阮氏/ビルマ）で、**英の艦隊が圏外**。

### 28-2 根因＝§26の実装漏れ

海軍シェアを「払った金の比」に変えたとき、**`NavyUpkeepTarget` を設定するAIを配線していなかった**。

### 28-3 修正

地理由来の海軍シェアを `Diplomacy.GeoNavalShare` として公開（**式の二重定義を避けるため元の計算箇所もこれを読む**）、
AIが毎期それを目標にして陸海を割り振る（`SelfPlay.SetNavalUpkeepShare`）。
プレイヤー国（NullAgent）はこの関数を通らない＝2本のスライダーで自分で決める形は保たれる。

実測＝**英が海軍6位（1.9）へ復帰**（圏外→）。列強・再現率 +1.3。硬性ゲート全緑・テスト184/184。
帯は near 66→58 と下がったが、これは**基線が私のバグの上に乗っていた**ため＝バグ修正の当然の帰結（差し戻さない）。

### 28-4 残る本丸＝アジア過近代化

英の海軍が戻っても上位は依然アジア（日本5.0・マラータ4.2・西山朝2.9・ビルマ2.8・清2.7 vs 英1.9）。

## §60 生産タブ第2弾＝稼働率の内訳と価格分解（2026-08-10）

作者フィードバック8項目。**223テスト緑**（218＋新規5）・savetest 0.0・**帯測定は不要**
（SimCore変更はフィールドを持たない新規静的クラス `ProductionDiag` と可視性修飾子のみ＝力学の式は1つも変わらない。
「診断は世界を1ビットも動かさない」テストが並走比較の厳密一致で固定）。

- **稼働率の内訳**（作者「低い稼働率の原因がわからない」への回答）＝画面に出ていた「原料」は**素材のみ**の配給率
  （`Producer.LastMaterialFill`）で、エンジンが使う投入充足は**労働込み**（`LastInputFill`）だった
  ＝**労働不足も採算割れも在庫過剰も画面から読めなかった**。内訳を **採算／投入充足／在庫調整／慣性による遅れ** の
  4項で出し、素材のみの配給率を併記（差＝労働不足の量）。
  エンジンの実式は `target = Capacity × fill × profit × invAdj`／`Output += SupplyAdjustSpeed × (target − Output)`。
  全国値は**条件付き比の連鎖（望遠鏡和）**で積む：
  採算 `Σ(Cap×profit)/ΣCap` → 投入充足 `Σ(Cap×profit×fill)/Σ(Cap×profit)` → 在庫調整 `Σtarget/Σ(Cap×profit×fill)` →
  慣性 `ΣOutput/Σtarget`。隣接する分母分子が打ち消し合うので **積 ＝ ΣOutput/ΣCapacity ＝ 稼働率が厳密に成立**
  （単純平均では一致しない）。番人＝53カ国×全財×60四半期で |積−稼働率| ≤ 1e-9。
- **価格の分解**＝段1（乗法）`基本価格 × 物価水準 × 需要と供給 ＝ 市場価格`／
  段2（加法の楔）`× (1 + 消費税 + 流通マージン + 独占レント) × (1 − 健康保険) ＝ 購入価格`。
  「需要と供給」は残差 `Price/(RefPrice×PriceLevel)`＝日次の在庫ギャップ・需給フロー・寡占マークアップが
  **価格という状態変数へ積分された結果**で項別に分離できないため1行に畳む。
  関税・穀物法・寡占・在庫目標は**局所価格に乗る項ではなく「需要と供給」を動かす駆動値**なので行にせずホバーへ
  （二重計上の回避）。番人＝5000組超で積み上げ＝実価格の一致。UIに第二の式を置かず `ProductionDiag` が唯一の正本
  （`InsuranceCoverageCap`／`InputCostPerUnit`／`CornFactor`／`TreatyPortTariffScale` を internal 化して**関数と定数を読む**）。
- 余剰/不足＝`(国内生産 − 国内消費) ÷ 国内生産`（`LastImport`/`LastExport` は分子にも分母にも不算入）。
  廃棄率＝`直近1年の廃棄量 ÷ 直近1年の生産量`（数量は出さない）。いずれも生産0は「—」。
- 「原料:n%」→「原料供給」・「原料充足」→「現況供給」・カテゴリを見出し級（12→15+Bold）・詳細でも対世界比を +n%（青/赤）。
- **★横断原則の適用**（作者「基本レイアウトが変わるのは好ましくない・場合によっては非表示は避ける」）＝
  詳細パネル全体を点検し、実行中に出入りしていた8箇所を常時表示化：現況供給・廃棄率・**価格分解の行数**
  （旧は3〜9行に伸縮＝**消費税ボタンを押すだけで行が生えていた**）・世界価格スパークラインの枠（開幕に68px跳ねていた）・
  貿易断片・設備断片・輸入行・月ごとの消費。ツールチップを持つ行は据え置き同期へ（日次20回/秒の差し替えでホバーが消えるため）。
