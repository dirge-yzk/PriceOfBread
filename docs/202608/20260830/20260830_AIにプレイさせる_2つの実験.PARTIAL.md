## 2. ★★ `ClaudeAgent` の設計

### 2-0. ★★★ いつ操作させるか（作者案 2026-08-30＝採用）

★ 作者案「**3か月または時間停止時のみ操作できる**」。★★ これは費用の削減以上に、**測定として忠実**である。
⚠ 人間は毎月は再検討しない。方針を決めて事件に応じるだけ＝**常時操作できる形で打たせると、人間より細かく反応できてしまい、プレイヤビリティの測定として過大になる**。

#### ★ 時間停止は UI だけの話ではない（現物）
```csharp
// Diplomacy.cs:94-95
public Power? PendingWar;                                 // プレイヤー最後通牒の待ち（#106）
public (Power Caller, Power Enemy)? PendingCallToArms;    // 同盟からの参戦要請の待ち
//  ★「即開戦せずここに積む＝UIが選択を出す」。null＝待ちなし。
//  ★★プレイヤー経路のみ＝自己対戦/較正に無影響（非プレイヤーでは常に null）
```
★★★ ⇒ **SimCore 側に「プレイヤーの決断待ち」の状態が既にある**。Claudeの国を `Diplomacy.Player` に指定すれば、
　**ヘッドレスでも人間とまったく同じ停止点が立つ**（UIを描かずに、UIが止まる瞬間だけ取れる）。

#### ★★★ 観測と操作の規則（作者裁定 2026-08-30＝確定形）

★★★ **毎四半期に、8つのタブすべてを確認する。**

⚠⚠ **初案（Claude自身に次の起床時刻を決めさせる）は撤回した——交絡があるため。**
　★ 自己申告方式だと、不意打ちを食らったとき
　　**(a) ゲームが予兆を出さなかった**（＝UXのバグ＝探している物）と
　　**(b) Claudeが見ていなかっただけ**（＝ただの雑音）
　が区別できない。
★★★ **毎四半期に全タブを見るなら、見落としは全て (a) に確定する。**

#### ★★ 副産物：α の制約が自動的に満たされる

⚠ 「UIに無い情報を載せない」を**毎回判断する**のは危険（うっかり内部状態が混ざる）。
★★★ 要約を **「8タブの内容そのもの」と定義すれば判断が要らない**——見せるものはUIが決める。
　⇒ 構造上、**Claudeが見るものとプレイヤーが見るものが一致する**。

#### ★ 実装の受け皿は既にある

★ `PriceOfBread.App/Program.cs:22-24` の `--uishot` の説明：
> 「タイトル→自動で国選択→高速で目標年まで進行→**各タブを開いて**連番PNG保存→終了コード0」

★★ **「各タブを開く」経路が既に存在する**。四半期ごとに回す形へ変えるだけで観測側はほぼ完成。

#### ⚠ 選択：テキストか、画面そのものか

| 方式 | 測れるもの | 費用 |
|---|---|---|
| **テキスト要約**（タブが束ねている値をそのまま文字に） | ★**情報が存在するか** | 安い |
| **スクリーンショット**（uishotの出力をそのまま読ませる） | ★**情報が見つかるか**（レイアウト・埋没） | ⚠高い（40四半期×8タブ＝320枚） |

★ これは別の問い。⚠**画面のどこかに数字はあるが3スクロール下に埋まっている**なら、存在はするが見つからない。
★★ AI審査の指摘はほぼ「**存在しない**」側だった（説明台帳が無い・反対勢力の内訳が出ない）。
　⇒ ★**まずテキストで存在を測り、必要なら第2波で画像の見つけやすさを測る。**
⚠ 画像にはもう一つ難点＝Claudeの読み取り誤りが混ざると「UIが不親切」か「Claudeが読めなかった」か分からず、**同じ交絡が別の形で戻る**。

#### ★ 手記に残させ続けるもの（起床の自己申告の代わり）

★ 「次に何を確認するつもりか」は**手記に書かせ続ける**（操作の頻度は変えない）。
★★ **書いた予定と、実際に起きたことのズレ**が、そのままUXの所見になる
　（「不満を見張るつもりだった。しかし政変は貿易の方から来た」＝予兆の出し方の問題）。

#### ★ 副産物：テンポ問題の実測
★ AI審査の指摘「604ターンで9種類のポップアップが頻発するとテンポが壊れる。**頻度の実測が要る**」に、
　**強制停止（`PendingWar` / `PendingCallToArms` 等）の回数がそのまま答えになる**＝151年で何回プレイヤーを止めるのか。

### 2-1. ★ 1ターンの流れ

```
DecideQuarter(world):     ← ★四半期ごとに必ず呼ぶ（間引かない）
    1. 8タブすべての内容をテキスト化（★uishot と同じ「各タブを開く」経路から）
    2. Claude へ渡す：タブの内容 ＋ **自分の手記** ＋ 前回からの出来事 ＋ 強制停止の有無
    3. 返答を解釈：スライダー13本の目標値・法33軸の押し引き・手記の更新
    4. World.Policy へ適用（⚠UIと同じ口＝プレイヤーにできないことはAIにもできない）
    5. 決定を JSONL へ記録（§4）
```

### 2-2. ★★★ 持続する手記（long-horizon play の要）

⚠ 131年＝604四半期を、毎回まっさらな頭で判断させると**方針が続かない**（前回何を試したか覚えていない）。
★ したがってエージェントは**手記（journal）**を持つ：
- いま何を目指しているか（例：「1830年までに公教育を通す。そのために官僚を厚くする」）
- 何を試して何が起きたか（「関税を上げたら翌年パンが上がって不満が出た」）
- 次の判断の予定

★ これが**そのまま実験の主成果物になる**（§5-4）。

### 2-3. ⚠⚠ 要約に何を載せるかが実験を決める

| 実験 | 要約に載せてよいもの |
|---|---|
| **α 目隠し** | ⚠**UIの画面に出ている情報だけ**。数値・内訳ホバー・年表・地図の色。**それ以外は一切載せない** |
| **β 目明き** | ★何でもよい（内部状態・係数・保存量まで）。目的は探索であって公平さではない |

★★★ ⚠**αで「UIに無い情報」を1つでも載せた瞬間、UX監査としては無効になる。**
　（人間より多くを知っているAIが「分かった」と言っても、人間に分かる証拠にならない。）

★ 幸い、要約はゼロから書かなくてよい——**説明API（`ExplainLedger` / `World.Explain`）が既に内訳を出せる**。
　★★ プレイヤーへの説明とAIへの入力が**同じ配管**になる＝説明が足りなければAIも困る＝**UX監査の道具として正しい**。

## 3. ★★ 実験α：目隠しUX監査

### 3-1. ★ 目的
★ AI審査で3本のレビューが揃って指摘した「**説明文を書かない規律 × 機構710件で、プレイヤーは因果を追えるのか**」に実測で答える。

### 3-2. ⚠⚠ 絶対条件：ソースの遮断
⚠ **コードを読ませない。** 実装を知っているAIが試しても意味がない。
⚠ ⚠**別セッション**で、ゲームの出力だけを見せて走らせること。

### 3-3. ★ 記録するもの（勝敗ではない）
★ 「**なぜそうなったか分からなかった瞬間**」を全部書かせる：
- パンが値上がりしたが、不作か／封鎖か／輸送か／買いだめか **画面から判別できたか**
- 法が通らないとき、**誰が反対しているか分かったか**
- スライダーが動かないとき、**理由が読めたか**
- 政変が起きたとき、**予兆に気づけていたか**

★ 出力＝**困った箇所の一覧**。これが AI審査 3-12（パンの値段の説明台帳）・3-14（できない理由の内訳）の実装要件になる。

### 3-4. ★ 規模
◇ 20〜40四半期で足りる（131年を遊ばせる必要はない）。⚠ 開幕の情報不足が最も出るのは序盤。

## 4. ★★★ 決定論の隔離（両実験に共通・必須）

⚠⚠ **LLMの返答は再現しない。** このプロジェクトはビット恒等を規律にしているので、そのままでは：
- テストスイートに入れられない
- 結果をA/Bで比較できない
- 「もう一度同じことが起きるか」を確かめられない

★★★ **解＝記録と再生を分ける**：

```
ClaudeAgent   … 判断を生成し、(四半期, 行動列) を JSONL へ記録する（非決定的・実験用）
ReplayAgent   … その JSONL を読んで同じ行動を打つだけ（★完全に決定論的）
```

★ これで：
- 生成は1回だけ（高価）
- ★**結果の検証・A/B・回帰は ReplayAgent で何度でも決定論的にできる**
- ★ 面白い試合を「棋譜」として保存でき、係数を変えた後に**同じ手順を再生して差を見る**ことができる

⚠ `ClaudeAgent` は **selfplay / fidelity / テストの経路には絶対に入れない**（別コマンドとして隔離）。

## 5. ★★★ 実験β：清の近代化テスト

### 5-1. ★ なぜ清が正しい題材か

- ★ **史実で失敗した**（洋務運動は挫折した）
- ★ 構造的な罠が全部乗っている＝検閲と宗教教育による技術天井0.5／制度疲労／独占レントの倒錯誘因（工業化しないほどレントが続く）／巨大人口／天命／アヘン
- ★ **既に測定値がある**（近年のバッチで清の再現率33〜43%）＝対照が取れる
- ★★★ **同型の前例がある**＝以前「**幕府が無代価で近代化できる**」という非歴史的最適解が見つかっている。**清でも同じ型のバグを探す実験**である

### 5-2. ★ 設計

| 項目 | 内容 |
|---|---|
| 対照 | ★清を `UtilityAgent`（現行AI）が打つ・**同一シード** |
| 処置 | ★清を `ClaudeAgent` が打つ・他国は `UtilityAgent`（⚠AI＝プレイヤー対称は保つ） |
| 窓 | ◇1783〜1914（604四半期）／または1783〜1860（критический窓＝アヘン戦争前後） |
| 判断の頻度 | ★**毎四半期・全タブ**（§2-0の確定形）。◇βは窓を短くして回数を抑える（下の「窓」を先に決める） |
| 測るもの | 工業化度・技術水準・列強再現率・分裂の有無・人口・国庫 |

### 5-3. ★★★ 判定基準（これが設計の要）

| 結果 | 意味 | やること |
|---|---|---|
| **楽勝** | ⚠⚠**バグ**。史実で失敗したことが簡単にできる＝非歴史的最適解 | ★Claudeが使った道を塞ぐ（＝機構の穴） |
| **不可能** | ⚠**動詞不足**。プレイヤーに手が無い | ★動詞を足すか、罠を緩める |
| **難しいが道がある** | ★★★**正しい**（明治日本の経路と同じ手触り） | ★その道が史実的に妥当かを見る |

★★★ ⚠**この実験は「Claudeが勝つか」を見るのではない。「どう勝ったか／なぜ勝てなかったか」を見る。**
　★ 手記（§2-2）に残る**試行と失敗の履歴**が主成果物である。

### 5-4. ★ 副産物

★ Claudeが「これをやりたいのにボタンが無い」と書いた項目＝**動詞の欠落リスト**。
★ 「この数字が読めないと判断できない」＝**UI要件**。
★ 「この手が強すぎる」＝**バランスの穴**。
⇒ ⚠ どれも人間のテストプレイでは出にくい（人間は無意識に迂回してしまう）。
