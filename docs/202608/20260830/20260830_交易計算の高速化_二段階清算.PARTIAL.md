## 1. ★ 現状の計算量

### 1-1. 構造

★ `BilateralMarket.StepBilateral` の骨格：
```
for 財 g (交易可能≈120):
    平均価格           O(州)
    売り手の選別＋価格昇順ソート    O(州 log 州)
    買い手の選別＋価格降順ソート    O(州 log 州)
    for 買い手 t:
        while (ロールオーバー; guard 400):          ← ★S4で追加
            for 売り手 s:                            ← 早期打ち切りあり
                PairKm(s, t)                         ← ⚠**ここが毎回呼ばれる**
                deliver = Price_s × (1 + margin(km) + wedge + risk)
            成約・記帳
```

★ 支配項＝ `財 × 買い手 × ロールオーバー回数 × 走査深さ`、その各回に `PairKm` が1回。

### 1-2. ⚠ `PairKm` が高い

★ 現物（`BilateralMarket.cs:214-232`）：
```csharp
double PairKm(int a, int b)
{
    ... Geo.SeaDistanceKm(...)        // → SeaGraph の最短路（量子化キャッシュ付き）
    ... PathGraph.LandMatrix()[na * N + nb]
    return Math.Min(viaSea, viaLand);
}
```
⚠ **`BilateralMarket` にペアのメモ化は1つも無い**（`Dictionary` の用途は港・通行料のみ）。
★★★ しかし **`PairKm(a,b)` は1回の `Step` の中では純関数**である——依存する量（`lat/lon/landKm/terrCost/landRatio/landNode/landGraft/suezOkN/panOkN`）は**すべて財ループの前に確定**しており、財が変わっても変わらない。
⚠ それを **120財 × 全買い手 × 全ロールオーバー反復** ぶん再計算している。

### 1-3. ★ 最近の悪化の内訳

| 要因 | 倍率 |
|---|---|
| 州 245 → 302（二乗で効く） | **×1.52** |
| `TradeMonthlyClearing = 1`（四半期1回→月次3回） | **×3** |
| `TradeArbitrageClearing = 1` のロールオーバー（同じ買い手が次善へ回る） | **×反復回数** |

⚠ さらに **国際市場は StepDay の逐次相にある**（日次並列の外）＝高速化の恩恵をまったく受けない。
★ 実測でも並列化後に国際市場の占有率が **17 % → 29 %** へ上がっている（他が速くなったため）。

## 2. ★★★ 第1手：距離のメモ化（最優先・最も安く最も大きい）

### 2-1. 形

```
Step の冒頭（tr が確定した直後・財ループの前）で
    km[tc × tc] を1回だけ埋める（PairKm を tc²/2 回呼ぶ＝対称）
以降 PairKm(a,b) の呼び出しを km[a*tc+b] の読み出しへ置換
```

- ★ `PairKm` は**対称**（`suezOkN[a] && suezOkN[b]`・陸脚の和・地形係数の和がすべて対称）＝上三角で足りるが、全表でも 302² × 8 byte ＝ **約 730 KB**（無視できる）
- ★★ **厳密恒等**：同じ入力から同じ値を返すだけ＝1ビットも変わらない

### 2-2. ◇ 見積り

| | `PairKm` 実呼び出し回数／清算 |
|---|---|
| 現在 | 財120 × 買い手302 × 反復3 × 走査深さ30 ≈ **330万** |
| メモ化後 | tc²/2 ≈ **4.6万**（財の数に依存しない） |

◇ **約70倍の削減**（走査深さと反復回数の実測値しだい。要 `POB_TIME` での確認）。

### 2-3. ★ 副産物：着値の式が2乗算になる

★ 運賃マージンは**距離の1次式**である：
```
margin = TransportMargin×(1 + DistanceMarginScale×km/D)×adValoremRev + weightAdd×(km/D)
       = A_g + B_g × km        （A_g, B_g は財ごとの定数＝財ループの先頭で1回計算）
```
⇒ メモ化後の内側は `deliver = Price_s × (1 + A_g + B_g×km[s,t] + wedge + risk)` ＝**乗算2回と加算数回**だけになる。

## 3. ★★★ 第2手：作者案＝国別の二段階清算（分枝限定）

### 3-1. ⚠ 「平均」でやると挙動が変わる。「上下界」でやれば厳密恒等

★ 財 g・売り手国 A・買い手国 B について、**保守的な境界**を作る：

| 量 | 取り方（保守側） |
|---|---|
| 売値の下界 | `minSell(A) = A の売り手州の最安価格` |
| 買値の上界 | `maxBuy(B) = B の買い手州の最高価格` |
| 距離の下界 | `minKm(A,B) = A×B の州ペアの最短`（★メモ化した km 表から1回で作れる） |
| 楔の下界 | `minWedge(B) = B の買い手の最小 wedge`（関税・穀物法・方針） |
| 危険料 | ★`PairRisk ≥ 0` なので **0** を使う |
| 封鎖バイアス | ★`≥ 0` なので **0** を使う |

**枝刈りの条件**
```
minSell(A) × (1 + A_g + B_g × minKm(A,B) + minWedge(B)) ≥ maxBuy(B)
   ⇒ A の州から B の州へは、どの組み合わせでも取引が成立しない ⇒ A×B を丸ごと飛ばす
```

★★★ **これは admissible（見落としゼロ）**：実際のどのペアも売値はこれ以上・距離はこれ以上・楔はこれ以上・買値はこれ以下だから、境界で不成立なら実ペアも不成立。
⇒ **枝刈りしても結果は1ビットも変わらない。**

### 3-2. ★ コスト

- `minKm(A,B)` の表＝61² ＝ 3,721 要素。km 表から作るので **tc² ＝ 9.1万回の比較**を Step ごとに1回
- 財ごとの `minSell / maxBuy`＝州の走査 O(tc)（**既に平均価格の計算で1周しているのでその中で取れる**）
- 判定＝財120 × 61² ≈ **45万回の比較**（無視できる）

### 3-3. ◇ 効き目

◇ 枝刈り率は未実測。効きやすい条件＝
- ★ 価格が参照価格の近くに密集している財（＝多くの財）では、**距離の下界が大きい遠方の国対**が落ちる
- ⚠ 逆に「世界中どこでも成立する」財（価格差が大きい財）では枝刈りが効かない

⇒ **メモ化（第1手）の後に測ってから入れる**のが順序として正しい。第1手だけで足りる可能性がある。

## 4. ⚠⚠ 実装上の落とし穴（ビット恒等を壊さないために）

### 4-1. ★ 早期打ち切りは「最良には厳密・次善には近似」

★ 現物（`BilateralMarket.cs:431`）：
```csharp
if (sellers[s].Price * (1 + minFreightMargin + pruneWedge) >= bestDeliver) break;
```
★ 売り手は価格昇順なので、これ以降の売り手は**最良にはなれない**（＝最良は厳密）。
⚠ **しかし「次善」は違う**：打ち切った先に `bestDeliver` と `secondDeliver` の間に入る売り手が居る可能性がある。
⚠⚠ したがって **走査を「全探索＋ソート」に置き換えると `secondDeliver` が変わり、成約単価が変わり、世界が変わる**。

★★★ **メモ化しても、走査の順序と打ち切り条件はそのまま残すこと。** 変えてよいのは「距離をどこから取るか」だけ。

### 4-2. ★ 買い手ごとの着値は反復のあいだ不変

★ ロールオーバーの中で変わるのは `left[s]`（残量）と `skipS[s]` だけで、**`deliver[s]` は買い手が同じなら不変**。
⇒ 買い手ごとに `deliver[]` を1回作れば、以降の反復は**比較だけ**になる。
⚠ ただし 4-1 のとおり、**打ち切り条件を含めて同じ順序で走査すること**（配列を作るだけで、走査規則は変えない）。

### 4-3. ⚠ 並列化はできない

★ 国際市場は `StepDay` の**逐次相**にある（月次決算・四半期末と同じ）。
⚠ 国をまたぐ在庫・貨幣の移動そのものなので、**日次相のような国ローカル並列は原理的に不可能**。
⇒ ここは**アルゴリズムでしか速くならない**。

## 7. ◇ 付記：二段階清算には速度以外の利点もありうる

★ 国別の集計価格を持つと、以下が**副産物として**得られる：
- 「この財の世界価格」を国別に持てる（現状の平均価格は全州の単純平均＝統計）
- 貿易の説明台帳（「なぜパンが値上がりしたか」＝AI審査 3-12）に**国別の需給という中間層**ができる
- ◇ ただし**力学に読ませてはいけない**（読ませた瞬間に「世界市場という1つの池」が復活し、二国間交易という設計思想に反する）

## 8. ★ 実測（2026-09-01・timeprobe 480Q・国68州321・単独走）

### 8-1. 微細計器の結果（POB_TIME=1・純カウンタ＝挙動非接触）

| 量 | 値 | 読み |
|---|---|---|
| 本走 | 491秒 | 各国の日次 216秒（43%）・国際市場 190〜199秒（38〜39%）・その他 90秒 |
| 清算ループ | 106〜114秒 | 国際市場の中身。リスト構築は **17ms＝ゼロ**（平均価格・売買リストは問題でない） |
| 財処理 | 172,556回 | 480Q×120財/月相当 |
| 買い手行 | 2,950万行 | 財あたり平均171買い手 |
| ロールオーバー反復 | 2.97億回 | 買い手行あたり平均10回（成約1.56億＝反復の52%が成約。残りはskipS霧散） |
| **実効走査歩** | **80.4億歩** | 反復あたり平均27歩。**1歩≈14ns**（メモ化済み着値の読取＋比較のみ＝ほぼメモリ速度） |
| 空振り | 36.1億回 | 在庫切れ/skipSのcontinue。走査全体の31%だが1回≈2-4ns＝最安の反復 |
| 着値充填 | 8.5億回 | 走査歩の10.6%だけが実計算（手2の遅延計算が効いている証拠） |

### 8-2. 施した手と効果

| 手 | 効果 | 恒等の証明 |
|---|---|---|
| PairRisk（通商破壊リスク）のメモ化 | 国際市場 197.5→188.2秒（**−4.7%**） | armstrace 604Q 完全一致・POB_RISK_MEMO=0 非常口 |
| 連結リスト圧縮（在庫切れ売り手の恒久unlink） | **実質中立**（清算111.2秒・空振り36.1→34.2億＝−5%のみ。ノイズ帯188〜199秒の内側） | armstrace 604Q **完全一致**＋全カウンタ一致・POB_SKIPLIST=0 非常口 |

★ 連結リストの狙いは「死んだ接頭辞」の再walk根絶だったが、**実測で仮説が棄却された**：空振りは−5%しか減らない＝
主成分は死んだ売り手でなく **skipS（買い手一時＝Y=0霧散）の再走査**（反復の48%が霧散→残り反復×接頭辞27歩を再walk）。
skipSは買い手が変われば復活するためunlink不能（undoログ方式なら消せるが上限2〜3%＝複雑さに見合わない）。
圧縮自体は恒等実証済みなので**最悪ケース（売り手多数×大量死）の番人として温存**。

### 8-3. ★ 結論：厳密恒等の枠内では床に達した（2026-09-01確定・419緑・savetest 0.0E+000）

- 実効80.4億歩×14ns＝**清算ループの本体はすでに「比較しかしていない」**。手2（着値配列）・PairRiskメモ化・連結リストで
  取れる無駄は取り切った。
- §3の国別二段階（上下界枝刈り）は**ビット恒等と両立しない**ことが判明：現行の次善（secondDeliver）は走査順依存の
  近似（§4-1）で、枝刈りは「次善に影響しない」ことを証明できない売り手を飛ばせない。飛ばせるのは着値既知の売り手だけ＝
  現状の1歩14nsと同コスト。**二段階は「挙動を変えてよいラウンド」（#17系）の選択肢として保留**。
- 残る大きな時間は (a) 各国の日次 216秒＝43%（別キャンペーン・国ローカル並列は済んでいるはず）
  (b) 成約1.56億件という**物理量そのもの**（貿易復活の代価。1成約の量子を大きくする＝挙動変更＝#17系）。
- 日次相は確認済み＝`Parallel.For`（国ローカル並列・POB_PAR非常口）で**並列化済み**。210秒は並列後の残余。
- 最終実測＝**604Q1試合≈604秒**（清算ループ111秒・国際市場196秒/40%）。§3二段階・§6の残段はここで打ち切り＝
  次に速くするなら「挙動を変えてよいラウンド」で（成約量子・二段階の近似次善）。

⚠ 計器は POB_TIME=1 のみ有効（通常走行はifの分岐1個＝実測ゼロ差）。
