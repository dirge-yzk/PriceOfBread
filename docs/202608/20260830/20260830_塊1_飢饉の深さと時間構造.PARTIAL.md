## 3. ★★★ 確定した設計（作者裁定 2026-08-30「その解放でよい」）

### 3-1. 作法＝`GrainChain` と同じ「Tierから独立した1本のフラグ」

★ 現物に前例がある：**`GrainChain: true`** は「穀物法の課税客体か」を Tier から独立させた別フラグ（麦・小麦粉が該当）。同じ作法で **`Nutrition`** を足す。

```
GoodDef / Good に  double Nutrition  を追加
  既定 = (Tier == Staple ? 1.0 : 0.0)   ← ★これで現行と厳密恒等
```

★★ **新しいマジックナンバーは要らない。**⚠ 量は既に `BaseNeed` が持っている（加工肉0.12・干物0.10は較正済みの値）。
　栄養フラグは「食べ物か否か」の 1.0/0.0 で足り、**何単位食べるかは BaseNeed が決める**。

### 3-2. 段0（データのみ・コード変更ゼロ）＝符号の是正

★ `goods.json` の主食5種の `elasticity` を **0** にする。
```
selfFactor = (rp/p)^0 = 1  ＝ 価格に反応しない（必要量は生理的に決まる）
```
★ 買えるかどうかは**予算制約が決める**＝買えなければ `FoodMet < FoodNeed` で飢える（既存の会計がそのまま働く）。
★ ⚠**主食どうしの乗り換えは残る**（`priceFactor = Clamp(1 × subst, 0.4, 1.4)`）＝パン高騰→芋への移行は生きる。

⚠ ★★ **段2（弾力性を負にする＝素朴なギッフェン）は棄却。**数値を反転させるだけで機構がなく、価格下落でも需要が下がる病理（発散）を持つ。「壁でなく逓減」「マジックナンバー禁止」の両方に反する。

### 3-3. 段1a（配線のみ・厳密恒等）＝栄養フラグの導入

| 場所 | 変更 |
|---|---|
| `Catalog.cs` GoodDef | `Nutrition` 列を追加（既定＝Tier由来） |

★ 既定（主食のみ1.0）では **1.0 の乗算＝ビット恒等**。
◇ **要判断**：`region.LastSubsistenceOutput += sub`（自給）を栄養フラグへ広げるか。

### 3-4. 段1b（本体・測定つき）＝肉を食料にし、交差弾力へ参加させる

**(a) 栄養を与える**
```
加工肉(63) Nutrition = 1.0
干物(64)   Nutrition = 1.0
肉(48)     Nutrition = 0     ← ★中間財のまま（生肉は加工してから食べる＝19世紀として正しい：塩漬け・干物・缶詰）
```

**(b) 総食料を中立に保つ（★前例あり）**
⚠ そのままだと `FoodNeed` が 1.10 → 1.32（**+20 %**）＝`FoodFill` が即座に下がり扶養力が落ちる。
★ **野菜(108)を足したときと同じ処理をする**——現物のコメント：「野菜(108)の追加で総食料を概ね不変に保つため 0.80→0.55（差分は野菜へ）」。

| 財 | 現 BaseNeed | 案（比例で 0.22 を譲る） |
|---|---|---|
| パン(62) | 0.55 | **0.44** |
| 野菜(108) | 0.25 | **0.20** |
| 米(102) | 0.20 | **0.16** |
| ジャガイモ(115) | 0.06 | **0.048** |
| トウモロコシ(116) | 0.04 | **0.032** |
| 合計（主食） | 1.10 | **0.88** ＋ 動物性 0.22 ＝ **1.10（不変）** |

★ 意味：**バスケットに肉が入ったので穀物の取り分が減る**＝経済的に正しい（肉も栄養を供給する）。

**(c) 交差弾力の参加資格を栄養フラグへ**
```
:1122  if (g.Tier == GoodTier.Staple && ...)   →   if (g.Nutrition > 0 && ...)
:1153  bool staple = Tier == Staple            →   bool food = good.Nutrition > 0
:1159  if (staple && ...stapleN > 1)           →   if (food && ...foodN > 1)
```

★★★ **これでギッフェン効果が創発する**：
> 肉が高くなる → 肉の価格比が食料群の幾何平均を上回る → 肉の需要が落ち、**その分がパンと芋へ流れる**

⚠ **新しい機構も新しい係数もゼロ。**既存の交差弾力（`CrossElasticity=0.6`）の参加者を2人増やすだけ。

**(d) ゲート**
★ `FoodIncludesAnimalProtein`（0/1・既定0）で (a)(b)(c) をまとめて切り替える＝0で厳密恒等・A/B可能。
⚠ (b) の BaseNeed 再配分もゲートの内側に置く（データを直接書き換えると OFF 側が作れない）。
