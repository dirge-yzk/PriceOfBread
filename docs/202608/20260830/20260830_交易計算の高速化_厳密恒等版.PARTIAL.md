## 2. ★★★ 手1：州間距離のメモ化

### 2-1. ★ 純関数であることの証明

★ 現物（`BilateralMarket.cs:214-232`）
```csharp
double PairKm(int a, int b)
{
    double viaSea = double.PositiveInfinity;
    if (tr[a].seaOk && tr[b].seaOk)
    {
        double sea = Geo.SeaDistanceKm(tr[a].lat, tr[a].lon, tr[b].lat, tr[b].lon,
                        suezOkN[tr[a].nation] && suezOkN[tr[b].nation],
                        panOkN[tr[a].nation] && panOkN[tr[b].nation]);
        viaSea = sea + tr[a].landKm * terrCost[a] * landRatio[a] + tr[b].landKm * terrCost[b] * landRatio[b];
    }
    if (!(c.LandRouteEnabled > 0)) return viaSea;
    int na = landNode[a], nb = landNode[b];
    if (na < 0 || nb < 0) return viaSea;
    double raw = PathGraph.LandMatrix()[na * PathGraph.Nodes.Length + nb];
    if (double.IsPositiveInfinity(raw)) return viaSea;
    double viaLand = (raw + landGraft[a] + landGraft[b]) * 0.5 * (terrCost[a] * landRatio[a] + terrCost[b] * landRatio[b]);
    return Math.Min(viaSea, viaLand);
}
```

★ 依存する量とその確定時点：

| 量 | 確定する場所 | 財ループ中に変わるか |
|---|---|---|
| `tr[].seaOk / lat / lon / landKm / nation` | `BilateralMarket.cs:167` で `tr` 確定 | ⚠**変わらない** |
| `suezOkN[] / panOkN[]` | 国ループ（`:76-83` 付近） | ⚠**変わらない** |
| `terrCost[] / landRatio[]` | `:172` 以降で州ごとに1回 | ⚠**変わらない** |
| `landNode[] / landGraft[]` | 同上 | ⚠**変わらない** |
| `PathGraph.LandMatrix()` | 静的（全点対の事前計算） | ⚠**変わらない** |
| `c.LandRouteEnabled` | 係数 | ⚠**変わらない** |

★★★ **財ループ（`:341`）が始まる時点で全入力が凍結している ⇒ `PairKm(a,b)` は Step 内で純関数。**

### 2-2. ★ 対称性

★ `viaSea` の各項＝`suezOkN[a] && suezOkN[b]`（対称）・両端の陸脚の**和**（対称）。
★ `viaLand` ＝ `(raw + landGraft[a] + landGraft[b]) × 0.5 × (terrCost[a]·landRatio[a] + terrCost[b]·landRatio[b])`（`raw` は最短路＝対称、他は和）。
⇒ ★ **`PairKm(a,b) == PairKm(b,a)`**。上三角で足りるが、実装の単純さを優先して全表でよい。

### 2-3. ★ 実装

```
場所：BilateralMarket.cs — tc 確定（:167）＋ terrCost/landRatio/landNode/landGraft の算出後、
      かつ 財ループ（:341）の前
形  ：double[] kmTab = new double[tc * tc];
       for a in 0..tc-1: for b in a..tc-1:
            double v = PairKm(a, b);
            kmTab[a*tc + b] = v; kmTab[b*tc + a] = v;
置換：PairKm(x, y) の全呼び出し → kmTab[x*tc + y]
```

★ 置換対象は現時点で3箇所：
- `BilateralMarket.cs:478`（**S4のON経路**の走査）
- `BilateralMarket.cs:560`（旧経路の走査）
- `BilateralMarket.cs:576`（診断の全探索・`TradeReachDiag` ON時のみ）

⚠ `:565` 付近の「取引が1件も立たなかった州の距離」など、**`PairKm` を使わない距離計算はそのまま**（`landKm × LandSeaCostRatio`）。

### 2-4. ◇ 見積り

| | `PairKm` の実行回数／清算 |
|---|---|
| 現在 | 財120 × 買い手302 × 反復3 × 走査深さ30 ≈ **約330万** |
| メモ化後 | tc(tc+1)/2 ≈ **約4.6万**（★**財の数に依存しない**） |

## 3. ★★ 手2：買い手ごとの着値の配列化

### 3-1. ★ 不変であることの根拠

★ S4のON経路（`:470-500` 付近）のロールオーバー `while` の中で変化するのは：
- `left[bestA]`（残量）
- `skipS[bestA]`（この単価では出さない売り手の印）
- `capLeft[]`・`budgetLeft[]`（容量と予算）

⚠ **`deliver[s]`（着値）を決める量——`sellers[s].Price`・`km(s,t)`・`wedge`・`blockadeBias`——は1つも変化しない。**
⇒ ★ 買い手 `t` が同じあいだ、`deliver[s]` は**定数**である。

### 3-2. ★ 実装

```
買い手ループの先頭で1回だけ：
    for s in 0..sellers.Count-1:
        deliver[s] = sellers[s].Price * (1 + margin(kmTab[...]) + wedgeS + blockadeBias);
ロールオーバーの各反復では deliver[] を読むだけ（再計算しない）
```

★ 副産物：運賃マージンは**距離の1次式**である。
```
margin = TransportMargin×(1 + DistanceMarginScale×km/D)×adValoremRev + weightAdd×(km/D)
       = A_g + B_g × km      （A_g, B_g は財ごとの定数＝財ループ先頭で1回計算）
```
⇒ 内側は **乗算2回＋加算数回** に縮む。

### 3-3. ⚠⚠ 変えてはいけないもの

⚠ **走査の順序（売り手の価格昇順）と打ち切り条件（`:431` と S4側の同型の行）は一字も変えない。**
　配列を作るのは「値の取得元」を変えるだけであり、**どの売り手を何番目に見るか・どこで打ち切るかは現行のまま**。
　（理由は §5。）

## 4. ★★ 手3：国別の分枝限定（作者案・上下界版）

### 4-1. ⚠ 「平均」では挙動が変わる。「上下界」なら変わらない

⚠ 国別の**平均価格**で成立判定をすると、実際には成立するペアを落としうる＝**近似**＝世界が変わる。
★★★ **保守的な境界**を使えば、落とす枝に解が存在しないことが保証され、**厳密恒等**になる。

### 4-2. ★ 境界の取り方（財 g・売り手国 A・買い手国 B）

| 量 | 保守側の取り方 | 根拠 |
|---|---|---|
| 売値 | `minSell(A)` ＝ A の売り手州の**最安**価格 | 実ペアの売値はこれ以上 |
| 買値 | `maxBuy(B)` ＝ B の買い手州の**最高**価格 | 実ペアの買値はこれ以下 |
| 距離 | `minKm(A,B)` ＝ A×B の州ペアの**最短** | ★kmTab から作る |
| 楔 | `minWedge(B)` ＝ B の買い手の**最小** wedge | 関税・穀物法・買い手方針 |
| 危険料 | **0** | ★`PairRisk ≥ 0`（`:234`） |
| 封鎖バイアス | **0** | ★`BlockadeStapleBias × PairRisk ≥ 0` |

**枝刈りの条件**
```
minSell(A) × (1 + A_g + B_g × minKm(A,B) + minWedge(B))  ≥  maxBuy(B)
    ⇒ A の州から B の州へは、どの組み合わせでも lp > deliver が成立しない
    ⇒ A × B を丸ごと飛ばす
```

★★★ **admissible の証明**：任意の実ペア (a∈A, b∈B) について
`Price_a ≥ minSell(A)`、`km(a,b) ≥ minKm(A,B)`、`wedge_b ≥ minWedge(B)`、`risk ≥ 0`、`bias ≥ 0`、`lp_b ≤ maxBuy(B)`。
したがって `deliver(a,b) ≥ 左辺 ≥ maxBuy(B) ≥ lp_b` ⇒ `lp > deliver` は偽 ⇒ **成約しない**。
⇒ **落とした枝に解は存在しない ＝ 結果は1ビットも変わらない。**

### 4-3. ★ コスト

| 計算 | 回数／清算 |
|---|---|
| `minKm(A,B)` 表（61×61） | kmTab の走査 ＝ **tc² ≈ 9.1万回の比較**（Step ごとに1回） |
| 財ごとの `minSell / maxBuy / minWedge` | ★**既に平均価格の計算で州を1周している**（`:341` 直後）ので、その中で同時に取れる＝追加コストほぼゼロ |
| 判定 | 財120 × 61² ≈ **45万回の比較** |

### 4-4. ◇ 効き目

◇ 枝刈り率は未実測。効きやすい＝**価格が参照価格の近くに密集している財**（＝多くの財）で、**距離の下界が大きい遠方の国対**が落ちる。
⚠ 逆に価格差の大きい財では効かない。
⇒ ★ **手1の測定後に、必要と判断してから入れる**（手1だけで足りる可能性がある）。

## 5. ⚠⚠⚠ 最大の罠：早期打ち切りは「最良には厳密・次善には近似」

★ 現物（`BilateralMarket.cs:431` と S4側の同型の行）
```csharp
if (sellers[s].Price * (1 + minFreightMargin + pruneWedge) >= bestDeliver) break;
```

★ 売り手は**価格昇順**なので、打ち切り以降の売り手は `deliver ≥ 下界 ≥ bestDeliver` ＝ **最良にはなれない**（最良は厳密）。
⚠⚠ **しかし「次善」は違う**：打ち切った先に、`bestDeliver` と `secondDeliver` の**あいだ**に入る売り手が存在しうる。

★ そして成約単価は次善で決まる：
```csharp
unit = Math.Min(lp, secondDeliver);   unit = Math.Max(unit, sellers[best].Price);
```

★★★ ⇒ **「全探索してソートする」形に置き換えると `secondDeliver` が真の第2位になり、単価が変わり、世界が変わる。**
⇒ ⚠ **本ラウンドでは走査規則を一切変えない。** 変えるのは値の取得元（kmTab・deliver[]）だけ。

★ 手3の枝刈りも**この規則を壊さない**：国ごと落とすのは「その国の売り手は最良にも次善にもなれない」ことが上下界で保証される場合だけである。
⚠ ただし実装では**枝刈りした売り手を `secondDeliver` の候補からも外す**ことになるので、上下界が `lp` に対して張られている（＝そもそも成約対象外）ことを確認すること。
　★ `deliver ≥ maxBuy(B) ≥ lp` なら、その売り手は `lp > deliver` を満たさないので**元の走査でも `best` にも `second` にもなれない**——
　⚠⚠ **いや、`secondDeliver` は `lp > deliver` の判定より前に更新される**（`:439-440`）。したがって**枝刈りは `secondDeliver` を変えうる**。
　★★★ ⇒ **手3を入れるなら、枝刈りした売り手も `secondDeliver` の更新にだけは参加させる**か、または **手3を見送る**。§7の順序で手1・手2を先にやり、手3は必要になってから改めて設計する。

## 6. ★ 前提と制約

### 6-1. ★ 決定論
★ kmTab は `PairKm` と同じ値を同じ順で埋めるだけ＝浮動小数の演算順も不変。
⚠ 並列で埋めない（順序が変わらなくても、埋める側で別経路の演算をしないこと）。

### 6-2. ⚠ 量子化キャッシュの不変条件
★ `Geo.SeaDistanceKm` → `SeaGraph` は量子化キャッシュを持つ（既知の教訓「キーが量子化なら値も量子化入力から計算する」）。
★ kmTab は**その戻り値をそのまま保存する**だけなので、キャッシュの性質を変えない。

### 6-3. ⚠ 並列化は不可
★ 国際市場は `StepDay` の**逐次相**（月次決算・四半期末と同じ）にある。
⚠ 国をまたぐ在庫と貨幣の移動そのものなので、日次相のような国ローカル並列は**原理的に不可能**。
