# 1. ★★★ 着手前に知るべき5つの事実

## 1-1. ★★★ 与信の制御器が、返済を1年余りで機械的に取り消す（最大の急所）

```csharp

Credit.cs:119   adjSpd = CreditAdjustSpeed / div        // 0.05 / 30 ＝ 1/600（日）

```


★★★ **しかも再創造された貨幣は、返済した家計ではなく首都州の投資家POPへ渡る。**

⚠⚠ **したがって家計債務を `bank.Loans` と同じストックに載せると、デレバレッジは1年余りで取り消され、実体は「家計→資本家への遅延移転」に化ける。負債デフレは原理的に起きない。**

### ★ 解決＝家計債務を別ストックにする


★★ `World.cs:275` の `OutstandingLoans` は **与信を `BaseMoney` へ接続する唯一の地点**なので、ここを拡張すれば新ストックが自動で恒等式に入る。

⚠ **ただし `docs/202607` §8-5 の原則**（新軸が正当化されるのは賛否連合が既存のどれとも違うときだけ）を機構に当てると、受益者連合（困窮POP）は4出口の当事者と**完全に同一**なので、原則どおりなら「畳め」の側である。

> **判定＝「既存の遅延版であり、かつ新しい因果でもある」＝条件付き採用。**
> **条件① 返済が実際に将来の予算を食うこと**
> **条件② 返済不能が別の帰結を持つこと**
> ⚠ **返済が無痛なら、それは4出口を一律に弱める倍率にすぎず却下対象である。**

# 2. 機構の形

## 2-1. 状態（新設は2本）

| 置き場所 | 名前 | 寿命 | 保存則上の扱い |
|---|---|---|---|
| `Pop` | **`Debt`** | **永続** | ★**貨幣ではない。** `HouseholdLoans` の内訳（誰の分か）を持つ記録 |
| `Bank` | **`HouseholdLoans`** | **永続** | ★**貨幣。** `World.OutstandingLoans` に算入する |

⚠ **`Pop.Debt` を `OutstandingLoans` に足してはならない。** `Bank.HouseholdLoans` と両方を足すと**貨幣が二重に消える**。
★ 前例が明文化されている——`Coefficients.cs:832-834`「繰入は `bank.Loans` を増やすだけで `MoneyConservation` の恒等式に Loans は入らない＝貨幣を作らない」。

★ `Pop.Debt` に最も近い前例は `Model.cs:135-137` の `NationalConsciousness`（国スカラーのPOP属性化）。**「主フラグ0では誰も読み書きしない＝厳密恒等。初期値0のまま」という注記の形までそのまま流用できる。**

## 2-2. 入口A — 損失の記憶

```csharp
Simulation.BackstopNegativeSavings（Simulation.cs:1795-1806・銀行あり経路）

    現行   Bank.Loans += -p.Savings;  World.LossFinanced += -p.Savings;  p.Savings = 0;
    新     ↑はそのまま
         ＋ if (c.PopDebtDriven > 0) { p.Debt += -p.Savings × c.PopDebtLossShare; }
```

★ **記録を併記するだけ。** `Bank.Loans` 側は1ビットも変えない＝**貸し手は現状のまま**。
⚠ `PopDebtLossShare` は「損失のうち個人が背負う割合」＝**有限責任の度合い**。1.0 で全額、0 で現行（社会化）。

### ⚠ 銀行のない世界では債務を積まない

```
Simulation.cs:1807-1838（銀行なし経路）＝①最富裕POPが底打ち→②他の正貯蓄POPから比例徴収→③シニョリッジ
```
★ ここには**対応する貸し手がいない**（純移転とシニョリッジ）。⚠ **`Debt` を積むと `Σ Debt` の対応先が消える。**
★★ **銀行のない世界では積まない**（前近代・試験世界）。これは自然でもある——質屋も施しも**その場で完結する非公式信用**であって、証文の残る債務ではない。

## 2-3. 入口B — 消費者信用

```csharp
EconomyStep.cs:928   double affordable = p.RemainingBudget / buyerPrice;
```
★ **予算の書き込み口は1（`:148`）、読み口は1（`:928`）、引き口は2（`:995` 役務／`:1045` 財）——入口はこの4点だけで足りる。**

```
借入枠  cap = c.HouseholdCreditMonths × （そのPOPの月次所得）
条件    主食（Staple）の tier を買う段でのみ発動。日用・奢侈・役務では借りない
発動    RemainingBudget が尽き、かつ FoodNeed が残っているとき
記帳    p.Savings += x;  Bank.HouseholdLoans += x;  p.Debt += x;  p.RemainingBudget += x;
```

⚠ **`RemainingBudget` は予算キャップにすぎず、現金は動かない。** `Savings` を同時に増やさないと**貨幣が湧く**（返済時に消える）。★ 逆に `Savings` だけ増やして `RemainingBudget` を増やさないと**その月には使えない**。**両方を書くこと。**

★ **主食に限る理由**：質屋・掛け売りは食い扶持のための信用であって、奢侈のための信用ではない。tier を限ることで、**新しい優先順位規則を書かずに**史実の形になる。

## 2-4. 出口 — 返済規律

★★★ **挿入点は `EconomyStep.cs:145` と `:146` の間で、`RemainingBudget` ではなく `Savings` 自体を削る。** これが**唯一整合的な位置**である。

```
理由：投資家だけが二重の予算を持つ
  :152  消費予算 ← RemainingBudget ×= (1 − IndInvestmentFrac)
  :448  投資予算 ← IndInvestmentFrac × Savings
  ⚠ RemainingBudget 側だけ削ると投資予算が削れない
  ⚠ :448 側だけ削ると消費予算が削れない
  ★ Savings を先に削れば両者が同じ縮んだ値を読む＝自動的に整合
```

```csharp
// EconomyStep.cs:145/146 の間（月初・消費の前）

{
    double pay = Math.Min(p.Debt, Math.Max(0, p.Savings) * c.DebtRepayFrac);

```

★ これは backstop の**厳密な逆操作**であり、`BaseMoney = TotalMoney + Treasury − OutstandingLoans` を1ビットも動かさない。

### 刻みは月次

⚠ 利息は日次（`Credit.Step` が `Simulation.cs:1013` から呼ばれ年率を /360）だが、`Earned`/`Paid` は月次リセットのため **Credit 側は既に「月次利潤を /30 して日次に揃える」という不自然な補正を強いられている**（`Credit.cs:162-169`）。★ **返済を日次にすると同じ歪みを再導入する。月次でよい。**

### ⚠ 税との順序は純粋な裁定事項

```
現行の月次順序 ＝ 先に買い（EconomyStep）→ 後で稼ぎ（:1665）→ さらに後で課税（Fiscal.cs:65-75）
```
★ 返済を月初に置くと、**国家は債務に劣後する**（借金を返してから税を払う）。逆にしたければ返済を `Fiscal` の後へ移す。⚠ **順序だけで結果が変わる**（§11-1）。

## 2-5. 返済不能

★ 条件②（返済不能が別の帰結を持つ）を満たすための最小の形。

## 3-4. ⚠⚠ `Σ Debt == Bank.HouseholdLoans` は必ず破れる

```
MultiNationSim.cs:169-180   分離独立    ← Savings しか運ばない
Diplomacy.cs:2052-2058      割譲        ← 同上
```
★ 州が国から国へ移ると、POPは移るが `HouseholdLoans` は元の国の `Bank` に残る。

**採る道は2つ。**
- **(a) 恒等式を主張しない**：`Pop.Debt` は「そのPOPが背負っている記憶」、`HouseholdLoans` は「その国の銀行の債権」で、**領土移転で乖離するのが正しい**（債権は残り、債務者は他国へ去る＝史実の外債問題）。★**推奨。**
- (b) 移転時に `HouseholdLoans` も按分して運ぶ。⚠ 新しい移転経路を2本足すことになる。

★ (a) を採るなら、**乖離量を診断として出す**こと（§10）。⚠ 乖離が単調増加するなら、それは (b) が必要だった証拠になる。
