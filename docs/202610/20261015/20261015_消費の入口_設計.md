## 1. 予算の3層

### 1-1. 今の形【確】
- 月初に `p.RemainingBudget = p.Savings.Value`（`EconomyStep.cs:544`）＝**予算は貯蓄の全額**。所得は予算に入らない（所得は月の中で貯蓄に入り、翌月の予算になる）。
- 財の順＝階層（Staple→Daily→Luxury→…）が第1キー・安い順が第2キー（`:1466-1475`）。各 POP は `min(欲しい量, 予算÷買い手の値段)` を買う（`:1641-1642`）。欲しい量＝`BaseNeed×Size×価格の弾力`（奢侈品は ×所得の弾力 `Pow(r, ε)`・`:1580`・`LuxuryIncomeElasticity = 0.5`）。
- 主食の配給で買えなかった分も予算から引く（`:1824-1827`）＝食料の分は下の層へ回らない。今もある〈食料が先〉の部品。
- 満足度の台帳の重み：食料 0・日用品 `DailyNeedWeight 0.5`・奢侈品 `LuxuryNeedWeight 0.2`（`:1802`）。奢侈品は分母にも満たした分だけを足す（`:1869`）＝奢侈品が無くても満足度は下がらない。
- 基線の事実（実装ログ）：英の大衆の Paid÷Earned は (327)（窃盗の基数の修正 `CrimeVictimBasis=1` を採った回）の後も **1.69**（Q5〜Q40・(327) の T＝旧 1.77）＝所得の 1.7 倍を払っている。窃盗の支えはほぼ消えた（窃盗÷大衆の Paid 0.586→0.004）＝残りの支えは大きな貯蓄の在庫の取り崩しと他の移転【推】。大衆の貯蓄は月収の 61〜133 か月（(258)・t6・(327) より前の値）。r334 以後の値は測っていない＝段 A の計器で取り直す。
- 先例の失敗：(273) 段5〈予算＝min(予算, 前月の所得＋貯蓄×d)〉は、d＝1/36 で大衆の Paid÷Earned が 0.57〜0.80・歳入÷年GDP 0.027・不履行 5/5 になり外した（機序は未分類・実装ログ (319) の記録）。**所得だけを予算にする層は、この崩れをそのまま繰り返す恐れが高い。**

### 1-2. 新しい形（AI の推奨）
記号：`Y`＝使える所得（前の月の確定値・定義は §8 Q1）・`S`＝月初の貯蓄（資本の予算〔下〕を引いた後）・`p_g`＝買い手の値段・`n_g`＝必需の割合（§4）。
- ⚠ 時刻【確】：月末の `Pop.SettleMonth`（`Model.cs:355-358`・呼び手 `EconomyStep.cs:2627`）が `貯蓄 += 所得 − 支払い` を足す＝**月初の `S` は前の月の所得を既に含む**。`Y＋S` と書くと前の月の所得を2度数える。下の表は `S` を手元のお金の全額（全ての層の上限）として書く。

| 層 | 籠・予算 | 取り崩し | 買う物 |
|---|---|---|---|
| 1 食料 | 籠＝主食（と動物性の食料）の `BaseNeed×Size×(1−自給)`・予算＝`S`（＝手元の全額・前の月の所得を含む）（＋家計の与信） | **する**（作者「貯蓄を切り崩してでも購入する」） | 主食・食料 |
| 2 日用品 | 籠＝`Σ n_g×BaseNeed_g×Size×価格の弾力`・予算＝`max(0, min(Y, S) − 層1の支払い)` | しない（作者「貯蓄を切り崩す程ではない」） | 日用品と、各財の必需の部分 |
| 3 余り | 余り `X＝max(0, Y−層1−層2 の支払い)`・予算＝`min(a×X ＋ r×S′, S−層1−層2 の支払い)`・`S′＝max(0, S−Y)`（前の月の所得を除いた蓄え） | `r×S′` だけ（利回りで暮らす富裕層） | 奢侈品（各財の贅沢の部分 `1−n_g`）と持って効く財 |
| 残り | — | — | 月末の `SettleMonth` が `所得 − この月の支払い` を貯蓄へ足す（新しい書き手は作らない） |

- 作者「食料+日用品を満足に買えたPOPのみ、手を出す。」は閾値にしない。`X＝max(0, …)` の連続の形にする。籠を満たせない POP は `X＝0`＝層3 の `a×X` は 0 になる（`r×S′` は残る）。
- `min(…, S−…)` は上限の錠でなく、手元に無いお金は払えないという保存則（予算は全ての層で `S` を超えない）。
- 作者「奢侈品を買って貯蓄が増えないのも違和感がある。」＝`a＜1`。値の候補 `a＝0.5`【推】（限界消費性向の桁）。
- `r` は貯蓄の年あたりの割合を月に直した値。候補 年 4%【推】（英のコンソル公債の利回り 3〜5% の桁＝利回りで暮らす家計）。`r` と `a` は財の表でなく係数（全階級に同じ）。
- 層3 の中の配り方：財ごとの重み `w_g＝BaseNeed_g×RefPrice_g×(1−n_g)×価格の弾力` の比で予算を分け、量＝`予算×比÷p_g`。所得に比例する（作者「奢侈品については完全に所得比例」）。歯止めは値段（弾力）と持って効く財の飽和（§2）。
- ⑨（二重計上）：層3 が所得の比例を運ぶので、`LuxuryIncomeElasticity`（`Pow(r, ε)`）は層3 を入れる腕で 0 にする。
- 投資と事業の支払いは消費の層の外：投資家の控除 `IndInvestmentFrac`（`:548`）・再点火の発注（`:1400-1414`）・反乱の武器（`:1200-1257`）は `S` から先に引く＝今と同じ〈資本の予算〉。上の `S` はその残り。

### 2-2. 形（AI の推奨）
- 作者「腐敗率は必要だろうか。耐久度を0に近い値にすれば、腐植率も出ると思うのだが」＝**1本の d で足りる**（AI の答え）。腐敗の率は `1−d`。
- ⚠ 恒等の罠：`1−(1−0.06)` は double で 0.06 にならない（`0.06000000000000005`）。〈d＝1−旧の値を表に書く〉は恒等でない。
  - 恒等の段：財の表（`GoodDef` の新しい欄・goods.json は dumpgoods で作り直す）には**旧の値（月の損耗）をそのまま**置く。`d` は読み口1本（`Durability => 1−損耗`）で出す。読み手は今の式（`×(1−spoil)`）のまま。冷蔵の式（`:566`）も触らない。証明＝帯3本の全行バイト一致。
  - 置き直しの段（挙動）：値を出典の耐用年数から入れ直すときに、表の欄を d へ切り替える。
- 財の使われ方を表の欄で2つに分ける：

| 使われ方 | 買ったとき | 毎月 | 例 |
|---|---|---|---|
| 使って消える | その月に効能（満足度・闘争度など）を出して消える | — | 食料・酒・煙草・茶・砂糖・石鹸・灯油・ガス・薬・新聞・書籍 |
| 持って効く | POP の手元の在庫へ足す | 在庫×d で減る・効能＝在庫÷望む量 | 家具・時計・宝飾・楽器・自転車・自動車・ラジオ・電化製品・冷蔵庫 |

- 状態は**持って効く財の POP ごとの手元の在庫だけ**（作者「状態を増やしますが、消費財と耐久財を持った方が良いのではないだろうか」）。市場の在庫・建設の資材・軍艦の隻数は今の欄のまま、同じ d を読む。
- 望む量 `D＝BaseNeed×Size÷(1−d)`＝定常で毎月の買い替え `D×(1−d)` が旧の毎月の量 `BaseNeed×Size` と同じ（新しい数を作らない）。開幕の手元の在庫は `D`（定常）で置く＝初月に 200 か月分を買う跳ねを作らない。
- 買う量＝`max(0, D×価格の弾力 − 在庫×d)`（層2 の必需の部分）＋層3 の配り。耐久財の需要は在庫の調整になる＝景気で大きく揺れる（史実の形・加速度の効き）。
- 効能の読み手：ラジオの充足 `p.RadioFill`（`EconomyStep.cs:1663`）を `在庫÷D` へ。満足度の台帳（`:1866-1869`）も在庫÷D を読む。新聞は使って消えるのまま。
- 住居（`HousingId`）は家賃の流れのまま＝この回の外。

## 4. 大衆化（必需の割合 n_g）

### 4-1. 形（AI の推奨）
- 財ごと・州ごとの必需の割合 `n_g`（0〜1）。必需の部分 `n_g×BaseNeed` は層2、贅沢の部分 `1−n_g` は層3（§1）。
- 導き方（新しい積分の状態なし）：前の月の POP ごとの1人あたりの購入 `c_p` を、上流と比べて人口で重みづける。
  - `c_ref＝min(c_max, b)`。`c_max`＝その州で最も多く買う POP の1人あたり・`b`＝籠の1人あたり（`BaseNeed×価格の弾力`）。
  - `n_g＝Σ Size_p×min(c_p, c_ref) ÷ (ΣSize×c_ref)`。
  - 〈上流〉は最も多く買う POP で読む（階級の順の表を作らない）。富裕層の層3 の買い増しで `c_max` が籠を超えても、`b` で止めて数える＝広く籠を満たしているかを測る（富裕層が多く買うほど n が下がる誤りを避ける）。
- 主食は `n＝1` に固定。後から現れる財は購入の記録が無い＝`n＝0` から。
- 決め打ちの階層は**開幕の出発点**へ格下げ：記録の無い最初の月だけ `Staple/Daily→1・Luxury→0` を使う。助走の間に各国の値へ動く。
- 歯止め：値段（籠の需要が増えると値が上がり、買えない POP の `c_p` が落ちて n が下がる）と飽和（`b` まで）。同じ門で上がり下がりする＝片方向の錠でない。

### 4-2. 記録と計算量
- 記録の置き場は2案：
  - (a)〈推奨〉市場の欄 `Market.LastNecessityShare`（州×財の1つの値）を、消費の支払いのループ（`:1803-1871`）の中で `Σ Size×min(c_p, c_ref)` と `c_max` を足して月末に書く。数える件数は増えない（既存の POP×財の中で2演算）。前の月の記録＝`LastRation`（`:1879`）と同じ種類（毎月まるごと書き直す・積分しない）。
  - (b) 既存の `m.PopBought`（階級ごとの量・`Model.cs:834`）から読むときに導く。SaveGame は反射で `PopBought` も書く【確】。ただし月初に null へ戻る（`EconomyStep.cs:581`）＝その前に読む必要・階級の人数も要る＝州×財×階級の走査が月ごとに増える（POP×財と同じ桁＝推定 ＋数秒【推】）＝計算量の線を越える。
- (a) は欄を1つ足す。⑩の〈導ける量は貯めない〉との関係：導く元（前の月の POP ごとの購入）は残っていない＝記録として持つ。

### 4-3. 危険
- 月ごとの往復（n が高い→需要が増える→値が上がる→n が下がる…）。記録の列に `n` の符号の反転の数を足して測る（平滑の状態は足さない）。
- 植民地の州も同じ式＝州ごとに違う n になる（国の平均にしない＝英本国と印で茶の n が別に出る）。

- **Q1 層の〈所得〉に何を入れるか**：前の月の Earned だけか、前の月に受け取った移転（福祉・年金・窃盗・送金・利子）も入れるか。**推奨＝移転も入れる**（基線の英の大衆は Paid が Earned の 1.69 倍＝Earned だけにすると (273) と同じ崩れ【推】）。あわせて段 D（初期値＝大衆の大きな貯蓄の在庫と取り崩しの置き直し）を E の前に置く。
- **Q2 衣料を〈持って効く財〉に入れるか**：衣料は産業革命の綿の需要の中心＝在庫の調整にすると需要の形が大きく変わる。**推奨＝最初は〈使って消える〉のまま**（今の損耗 0.02＝平均 4.2 年が流れとして近い）・F の後に別の腕で試す。
- **Q3 習慣の在庫の粒度**：州×習慣の財か、POP×習慣の財か。**推奨＝州×財**（今のアヘンと同じ・状態が小さい・⑩）。階級の差は困窮の門と必需の割合が運ぶ。
- **Q4（確認だけ）**：「いいえ、現在の作りで問題ないと思います。一任します。」を〈§3-3 の4段は AI に任せる〉と読んだ。〈今のアヘンの仕組みは直さない（③④をしない）〉の意味なら、①②（恒等）だけで止める。
