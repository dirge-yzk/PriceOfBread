- ★★ 作者の裁定（承認した推奨を含む）が原因で、判定の線（F1）・史実の向き・史実比較の桁に掛かる、または実装が遠回りになったり歪む（例外の枝・外科的な補正・承認の形を守るための回り道）と分かったら、**裁定を待たずに推奨の形で直して進める**。 〔§1-7・§1-8〕
- ★ 直したら**報告の先頭と実装ログ**に書く：どの裁定（作者の言葉を「」で）・何がうまくいかなかったか（数字）・どう直したか（AI の推奨）。00一覧の作者の裁定の表のその行に打消し線と日付で「→ 推奨の形で直した」を足す（行は消さない）。 〔§1-7・§1-8〕
- ⚠ 原因が裁定だと言うのは、測りか現物で示せたときだけ（推測なら【推】と書いて腕で確かめる）。裁定と関係の無い所で失敗したのを、裁定のせいにしない。 〔§1-7・§1-8〕
- ⚠ 安全の決まり・破綻の線・お金と人の保存・設計思想10則・作業の決まりはこの対象ではない。順位は今のまま（破綻しない＞正しい挙動＞バランス）。史実と食い違う裁定に証拠つきで反論する決まりも続く。 〔§1-7・§1-8〕
- ★ 作者「カオス的であることは性質上仕方ないですが、人間に認知できないカオス性、因果と結果が読めない状態であることは望んでいません。カオスを意図して生む意図はありません。実装はなくべく制御できる方向で進めてください」 〔§1-7・§1-8〕
- ★ 読み（AI の整理）＝**結果が予測できないのはよい・後から因果を説明できないのは不可**（史実と同じ＝出来事の一つ一つには理由があり、長い先は読めない）。 〔§1-7・§1-8〕
- ★ 閾値で0か1に反転する判断より、**入力の大きさに応じた判断**（反転が要る法などは上げる線と下げる線を分ける＝状態で決める・タイマーにしない）。 〔§1-7・§1-8〕
- ★ 片方向にしか動かない錠より、**同じ門で戻れる状態の変化**（上げると下げるを同じ費用で）。 〔§1-7・§1-8〕
- ★ 暴走の歯止めは上限や減衰の定数でなく、**値段と費用で効く負のフィードバック**（思想⑧と設計の P3 と両立させる）。正のフィードバックの鎖（例：兌換停止→不履行）は鎖の各段を計器で読めるようにし、歯止めの無い段を直す。 〔§1-7・§1-8〕
- ★ 1つの効果は1つの経路（思想⑨）・係数の掛け算を重ねない・決定には理由を残す（Explanation）。 〔§1-7・§1-8〕
- ★ 測りで、種ごとの値が二つの山に割れる・組み合わせでだけ出る結果は、**原因（どの出来事・どの切り替え）を特定してから**採否を決める。報告では、入れた変更の効きを原因→結果の鎖（数字つき）で書く。 〔§1-7・§1-8〕

## 単位とスケール・財は名前で引く（§1-9）
- ★ 作者「単位またはスケールのことなる変数同士を比較したり加算することに起因する不具合が何度も起きています。専用の型を作るか、変数名を工夫するのはどうですか？」→ AI の案（名前の規則と単位の表を先に・専用の型は失敗が集中する中心から）に「はい、そのような規則を加えましょう。」 〔§1-9〕
- ★ **名前に時間の基準と規模を入れる**：`…PerMonth`・`…PerQuarter`・`…PerYear`（流れ）／接尾辞なしは在庫（ストック）／`…K`（千人）／`…Share`（0〜1 の割合）／`…ToGdpYear`（年GDP 比）／`…PerCapita`（1人あたり）。計器と読み手の出力の列名にも同じ規則を当てる。 〔§1-9〕
- ★ **主要な量の単位の表**（単位・時間の基準・定義＝何を含むか〔例：`World.GdpPerMonth` は中間財を重ねる総産出で付加価値ではない・資本家の `EarnedPerMonth` は粗利潤の全額〕）を1枚に置き、史実の統計と比べるときは定義を揃えてから比べる。 〔§1-9〕
- → README §1-9
- ★ **専用の値型**（`readonly record struct`・中身は double 1つ＝速度は変わらない）を、失敗が繰り返し出た中心（財政・貯蓄・所得・軍の規模）から入れる。候補＝在庫のお金・月の流れのお金・期間（月）・人口（千人）・割合・1人あたり。異なる型どうしの加算と比較はコンパイルが通らない形にし、月と年の換算は名前のある関数だけにする。 〔§1-9〕
- ⚠ 型の導入は挙動を変えない変更＝計算の順序を変えずに包み、10種の全行バイト一致で証明する（§1-3）。セーブの書き出しは値の型ごとの分岐＝新しい型は分岐を足して savetest で往復を確かめる。 〔§1-9〕
- ⚠ 型は「次元の誤り」（在庫と流れ・月と年・千人と人・絶対量と人口あたり）を防ぐ。「定義の誤り」（総産出と付加価値など）は型では防げない＝名前と単位の表で防ぐ。 〔§1-9〕

## ヘルパー（§1-10）
- ★ 作者「「新しいヘルパーを作らない」規則は、必ずしも守らなくてはならないものではない、と明記してください。似たようなヘルパーが量産された経験から規則に入れていますが、規則を守るために品質を下げる必要はありません。不必要にヘルパーを作らない、作る際は必要性を確認すること、程度でよいです。」 〔§1-10〕
- ★ 2026-09-02 の「過度な分割は好みません。既存のソースコードを削減する方向で作業してください。」は方向として続く（重複は片方を消して既存の1本を呼ぶ）。 〔§1-10〕
- ★ ただし**規則を守るために品質を下げない**。新しいヘルパー・型・ファイルは、作る前に必要性を確かめる（既存の1本で足りないか・似たものが無いか grep する）。足りなければ作ってよい。作ったら報告に理由を1行。 〔§1-10〕
