## 1-2. ⚠⚠ 測定の作法（★ これを外すと事故る）

### ★★★ 回す前に＝必要性の確認（2026-09-26）

⚠ **ソースから自明なことを、テストや計測で証明しない。** ★ 予定の実行を1本ずつ次の3列に分け、⚠ **答えがソースから決まらないものだけを回す。**

| 問い | ソースで答えられるか（根拠の行） | 回すなら最小の大きさ |
|---|---|---|
| 不変の表に対する純粋な関数を記憶させた。結果は変わるか | ★ 答えられる＝鍵と値が同じ入力から出る・表を書く行が無い（grep の結果を報告に書く） | 回さない |
| 計器・コメント・診断の出力だけを変えた | ★ 答えられる＝計器の分岐の外で値を読む行が無い | 回さない |

| 係数や式を変えた。帯はどう動くか | ⚠ 答えられない | canary（`selfplay 1 N`）→ `selfplay-batch 10` |

★ 根拠の行を書いた報告が、その計測の代わりになる。

### ★★ 回し方

| # | 規律 | ⚠ 根拠 |
|---|---|---|
| ★★★1 | **必ず `measure.sh` を使う**（`SOURCE-HASH` 入りの `.manifest` が出る） | ⚠ 作業ツリーを複数セッションが編集する。直接ビルドすると他人の編集が混入する（★実際に起き、原因特定に1時間） |
