★★★ **136財のサプライチェーンの終着点として、原爆を置く。**

⚠ **巨大建造物にはしない。** 財の連鎖そのものを終端まで伸ばし、**深さでなく幅と量**で難しさを作る。

|---|---|

# 2. 現物の確認（★ 2026-08-15 に実測した事実）

⚠ **設計はこの6点に全面的に依存している。** 着手前に再確認すること。

## 2-1. ★★★ 連鎖の深さは「最長経路」であって「合計」ではない

```
Complexity = 1 + max(入力の深さ)          Catalog.ComputeComplexity
```

⚠⚠ **入力を10本に増やしても深さは1しか増えない。幅は深さに対して無料である。**

⇒ **2つのレバーは完全に別物**：

| レバー | 決めるもの |
|---|---|
| **深さ**（最長経路） | **いつ解禁されるか** |
| **幅と量**（入力の本数と係数） | **作るのがどれだけ大変か**（解禁時期には無関係） |

## 2-2. ★★ 解禁は深さから自動導出される（暦年ゲートは存在しない）

```
onset  = 0.7 × (深さ − 6)                 ComplexityFreeDepth=6.0 / ComplexityOnsetScale=0.7
解禁度 = clamp((技術 − onset) / 1.0, 0, 1)  AdvancedTechWidth=1.0
```

★ カタログ自身の記述＝「技術は本ゲームで概ね **0→3** で推移する」。`FrontierCeiling=6.0` は安全上限で「逓減で実際は届かない」（`InnovationScale=3.0`）。

**現在の深さ分布（実測）**

| 深さ | 件数 | onset | 代表 |
|---|---|---|---|
| 0〜5 | 119 | — | 原料・加工 |
| 6 | 4 | 0.0 | 精密工作機械・汽船・機関車・軍艦 |
| 7 | 4 | 0.7 | 発電機・機関銃・装甲艦・内燃機関 |
| 8 | 6 | 1.4 | 電力・送電網・戦車・弩級戦艦・飛行機・自動車 |
| 9 | 2 | 2.1 | 電化製品・戦闘機 |
| **10** | **1** | **2.8** | **ラジオ（現在の最深）** |

⚠⚠ **深さ12（onset 4.2）以上は設計として使えない。** 技術が届かず、永久に建造不能になる。

## 2-3. ★ 電力は輸送できない

`Model.cs` — `GridCapacity`＝「送電容量（地域内）。**電力はこの容量までしか工場に届かない**」。
`goods.json` — 電力は `NonTradeable`。

⇒ **電力を大量に要る財は、巨大な発電を持つ州でしか作れない。**

## 2-4. ★★ 戦災が送電容量を削る

`Diplomacy.cs` — `rz.GridCapacity *= 1.0 - wear`（工業化・港湾・鉄道・商船と同時）。

⇒ **爆撃で敵の核計画が遅れる。** 新しい機構を1つも書かずに出る。

## 2-5. ★ 施設名は表示だけの文字列

`Producer.RecipeName`＝「複数レシピの表示名（例：電力の『石炭火力』『石油火力』）」。`Simulation.cs` に「**表示のみ＝エンジンの読み手ゼロ**」と明記。

⇒ **「原子炉」は `RecipeName` で出せる。** 新フィールドも enum も要らない。

## 2-6. ★ 終局暦年は定数から導出される

```
Calendar.EndYear = StartYear + Coefficients.GameQuarters / QuartersPerYear    ＝1783 + 604/4 ＝ 1934
```

★ 暦年分岐は全域で **0件**（`Year >= 18xx` の類は存在しない）。⇒ **1945への延長は定数1本。**

## 3-2. ★ なぜ深さ10（ラジオと同層）にするか

1. ★★★ **史実がそうだから。** マンハッタン計画の難しさは「新しい物理」ではなく**途方もない量の既知の工業**だった。1939年には物理は分かっていて、難しかったのは濃縮工場と電力である
2. **到達可能性が実証済み。** ラジオが onset 2.8 で1934拡張から稼働している。深さ11（onset 3.5）は未検証で、外れると「誰も作れない財」になる
3. ★ **後から深さ11へ動かせる。** 電化製品を原爆から核分裂物質へ1本移すだけで深さが1上がる ⇒ **不可逆な選択をしない**

⚠ **深さ10でも原爆は簡単にならない。** onset は「解禁されるか」しか決めず、作れるかは幅と量が決める。

# 6. 1945への延長

```
Coefficients.GameQuarters   604 → 648        （EndYear は導出値なので他に触る所は無い）
```

★ 忠実度の較正は**やり直しにならない**。史実参照表は1914年断面のみ（`Polity1914` / `HomeProvinces1914` / `ColonyProvinces1914` / 列強軸 / 人口成長倍率1783→1914）で、`08_バランス調整方針` の裁定は「判定断面＝1914年12月／1934年終局＝**狂気チェックのみ・史実一致は問わない**」。

⚠⚠ **ただし測っていない区間が20年→31年（+55%）に伸びる。** そして1914以降を見る唯一の窓＝**跳躍ダイジェストは未実装**、ハーネスのゲート1〜8も0本（`20260815_サルベージ判定.md` S級）。

★ **延長より先に計器を立てること。** 逆順にすると、1945年に何が起きても誰も気づかない。

# 7. ⚠⚠ 導入手順

## 7-1. 財の追加は「厳密恒等」が原理的に取りにくい

⚠ 財を1つ足すと `Catalog.Goods.Length` が変わる。これを読む箇所が**22ある**（市場配列・反復回数・集計）。⇒ 思想③の「1ビットも変わらないことを証明してから点火」を**そのままの形では適用できない**。

★ 代わりに**段階を切って、各段でビット一致を測る**。

| 段 | 内容 | 判定 |
|---|---|---|
| **0** | **5財**（ウラン鉱・核分裂物質・原爆・爆撃機・空母）を `goods.json` と `Catalog.cs` に追加。⚠ **生産者ゼロ・賦存ゼロ・軍需配列に入れない** | `selfplay 1 200` の前後 diff ＝ **0行を狙う**。⚠ 0行でなければ差分の出所を特定してから進む |
| **1** | ★ **戦闘機・爆撃機・空母のストックを積む**（`BomberStrikeScale=0`＝読み手ゼロ＝艦隊ストック段Aと同型） | diff 0行 |
| **2** | 爆撃機・空母を `MilitaryAirGoods` / 艦隊調達へ入れる（調達が分散＝挙動が変わる） | 帯・硬性ゲート |
| **2b** | ★★ **`FleetLossAirWeight` を点火（制空を失った艦隊が沈む）** ⚠ 単独バッチ | 帯・**上陸の成否** |
| **2c** | `NavalAirWeight` を点火（戦闘機が海戦力へ） | 帯 |
| **2d** | ★ **轟沈/中破の分岐＋スクラップ**（`RepairCostFraction`・`ScrapReturnFraction`）⚠ 在庫の検算に回収項を足す | 帯・**造船業の稼働** |
| **3** | `BomberStrikeScale` を点火（厭戦のみ・`BomberWearScale=0`） | 帯・**戦争の長さ** |
| **4** | `BomberWearScale` を点火（戦略爆撃＝経済への打撃） | 帯・**工業化の推移** |
| **5** | ウラン鉱の賦存を4州へ置く（下流に生産者が無いので需要ゼロ） | 帯・硬性ゲート |
| **6** | 核分裂物質の生産者を置く（`RecipeName = "原子炉"`） | 帯・**電力の奪い合いを観測** |
| **7** | 原爆の生産者＋トグル＋投下＋モーダル | 帯・硬性ゲート |
| **8** | 電力係数の較正（4.0を動かす） | 「何カ国が何発持つか」 |
| **9** | `GameQuarters` 604→648 | 狂気チェック（破綻0・デッドロック0） |

★★ **段1〜4（爆撃機）を段5〜7（核）より先に置くこと。** 核は爆撃の式に乗るだけなので、**土台の較正が終わっていないと核の強さを測れない。**

⚠ 各段で `savetest`（セーブ/ロードのビット一致）と全テストを通す。★ **新しいフィールド型を足したら `savetest` は必須**（`SaveGame` はリフレクション直列化で、switch に無い値型は無限自己再帰でセーブが全滅した前例がある）。

## 9-3. ★★★ 設計 — 分子を書き換えるだけ

```csharp

  陸上機の到達 = 1 / (1 + DistanceWarDecay × km / DistanceNormKm)     // 遠いほど減る
  空母係数     = min(1, 空母ストック / (戦闘機ストック × CarrierAirPerHull))
```

⇒ 標的州も抑止も作らない。⚠ **忠実度の判定断面は1914年12月**なので、原爆は構造的に計器の外側にある。

## 10-1. ★ レバー＝トグル1本

```csharp

```

| | |

## 10-2. ★★★ 投下条件 ＝ 爆撃が成立していること（★ 作者裁定 2026-08-15）

★ **「原爆投下は爆撃が行われる状態に限る」。** ⇒ 条件を**爆撃の条件へ一本化**する。専用の述語を1つも書かない。

```
投下する ⇔ 交戦中
         ∧ UseAtomicBomb
         ∧ 原爆の在庫 ≥ 1
         ∧ 爆撃が成立している    ← §9-3 の 優勢度 > 0 かつ 爆撃機ストック > 0
```

★★ **「航空優勢が取れている」は §9-3 の `優勢度 > 0` がそのまま表す。** 互角以下では通常爆撃も0なので、核も落ちない。

⚠⚠ **これにより、旧案の「海戦に勝利し、相手の領土での陸戦ができる状態」は条件から外れる。** 核は「陸で勝った後の止め」ではなく「**空で勝った後の止め**」になる。⇒ 到達をどう扱うかは §9-6 と下の未決2で決める。

## 10-3. ★★★ 効果 — 専用の式を書かない（§9-7 の1行だけ）

```csharp
strike += AtomicEquivalentBombers × BomberStrikeScale;   // その月の爆撃力へ加算
原爆の在庫 −= 1;
```

⚠⚠ **原爆に専用の効果を1つも書かない。** §9-3・§9-6 の爆撃の式がそのまま走り、結果として：

| 起きること | 出どころ |
|---|---|
| **厭戦が上限1.0へ張り付く** | 既存のクランプ `Math.Min(1, …)` |
| **工業・送電・港・鉄道が同時に飛ぶ** | §9-6 の戦災項（陸の接触なし） |
| **降伏・割譲・復讐心** | ★ 下記のとおり既に定義済み |

★★ `WarPeaceExhaustion = 0.9` のコメントが、厭戦1.0を既にこう定義している：

> 早期白紙講和を遅らせ戦争が**一方の崩壊（厭戦≥1.0＝決定的）**まで続く＝決定的決着→割譲→復讐心の発火を可能に

⇒ 原爆は「新しい終わり方」を作らず、**既に定義済みの終着点へ一足飛びに送る**だけである。★ これが「雑に強く、破滅的」の最も安い実装。

⚠ **較正で動かすのは `BomberStrikeScale` の1本だけ。** 核は `AtomicEquivalentBombers`（＝何機分か）で自動的に追随する。

## 10-6. ⚠⚠ 裁定が要る点 — 爆撃はどこまで届くか

★ **空軍には距離の項が1つも無い**（`AirPower = Military × MilitaryAirFill`）。⇒ 現状のまま爆撃を実装すると、**内陸の小国が地球の裏側を爆撃できる。**

| 案 | 式 | 得るもの／失うもの |
|---|---|---|
| **A（推奨）** 距離だけ | `到達 = 1 / (1 + DistanceWarDecay × km / DistanceNormKm)`（`Projection` の距離項のみ） | ★ 遠い相手ほど爆撃が弱い。⚠ 制海権は問わない ⇒ **バトル・オブ・ブリテンが成立する**（独は制海権なしで英を爆撃した） |
| **B** `Projection` をそのまま | 距離減衰 × 海越えなら `SeaControl` | ★ 新しい式を1行も書かない・マリアナ→テニアン→B-29 の筋が出る。⚠ **バトル・オブ・ブリテンが成立しない** |
| **C** 到達なし（現状のまま） | — | ★ 最も簡単。⚠⚠ 内陸国が地球の裏を爆撃する |

★ **推奨はA。** 「爆撃は空の話で、制海権の話ではない」が史実に最も近く、原爆の条件（§10-2）も「空で勝った側が落とす」で一貫する。

⚠ どの案でも**既存の空襲厭戦（到達条件なし）より厳しくなる** ⇒ 挙動が変わるので、思想③どおり `AirReachGate = 0`（＝到達1.0＝現状）で入れて点火する。

# 11. ★★★ 使用と抑止 — 作者裁定 2026-08-26（**§10-1 のトグルを撤回する**）

## 11-1. ★★★ 核のための機能を作らない ＝ 投下は全自動

★ 作者指示（原文）：

> マップで「投下」を押したくない。核のための機能は作りたくない。プレイヤーが介入せずとも、勝手に投下すべきか。

⇒ **§10-1 の `World.UseAtomicBomb` トグルは撤回。** レバーは1本も置かない。

| 撤回の理由 | |
|---|---|
| ★ UI最小主義 | 「自動化できるレバーは置かない」（恒久指示）。押す/押さないに**コストが無い**トグルは偽のレバー＝押さない理由が存在しない |
| ★ AI＝プレイヤー対称 | AIが `SelfPlay` で自動的に立てるなら、プレイヤー側だけ手動にする理由が無い |
| ★ 専用述語ゼロ | §10-2 の条件（交戦中 ∧ 在庫≥1 ∧ 爆撃成立）は**既に完全**。トグルはその上に乗る4つ目の項でしかない |

⇒ 投下条件は §10-2 から `∧ UseAtomicBomb` を落としただけになる。**モーダル（§10-4）は残す**＝落とした/落とされた事実は通知する。プレイヤーが選ぶのは「原爆を作るかどうか」＝サプライチェーンへの投資であり、**そこが唯一の意思決定点**である。

## 11-2. ★★★ 抑止 ＝ 保有そのものが緊張を下げる

★ 作者の問い（原文）：「核保有そのものが緊張を緩和する。というのは雑過ぎるか？」→ **雑ではない。** ただし**単独保有**では逆に緊張を上げる（優位を得た側は押せる）。緩和するのは**相互保有**である。

★ 作者の位置づけ（原文）：

> これは現代の国際情勢に似ていると思います。核抑止は存在し、核保有国に侵略されないためには核を持つしかない。

⇒ 抑止は**2項**で書く。どちらも既存の量に足すだけで、新しい機構を作らない。

### ① 相互確証破壊 ＝ 双方の保有量の小さい方に比例して緊張を下げる

```
緊張の緩和 += NuclearDeterrenceRelief × min(A の原爆ストック, B の原爆ストック)
```

★ **`min` であることが全て。** 片方だけが持っていても0＝抑止は生まれない。両方が持って初めて効く＝相互確証破壊そのもの。

### ② 核を持つ相手には攻め込めない ＝ 屈服線に相手の保有量を足す

```
SubmitLine(target, c) += NuclearSubmitLinePerBomb × target の原爆ストック
```

★ 侵略の要求余剰戦力は `ExpansionWillCap / (1 + ColonizeForce/SubmitLine)`（2026-08-23 の国力比化）なので、屈服線が上がれば要求は跳ね上がる ⇒ **核保有国は事実上侵略できない。** 「核保有国に侵略されないためには核を持つしかない」がここで閉じる。

⚠ どちらも既定0で厳密恒等（休眠フラグの規律）。点火は空軍ストック化と財追加が終わってからの実測ラウンドで。

## 11-3. ★ 講和条件に「核開発の禁止」を加える

★ 作者指示：勝利時の講和条件に **核開発の禁止** を追加する。

| | |
|---|---|
| 効果 | 敗者は原爆（および核分裂物質）の生産者を建てられない・既存の棟は操業停止 |
| 期限 | ⚠ 未決 ＝ 恒久か有限か。**条約港の自然失効と同型で書けるなら「状態の持続条件」で解く**（脱出動詞を作らない） |
| 位置 | 既存の講和条件リストに1行足すだけ＝専用の講和処理を作らない |

## 11-4. ★ 1934〜1950 の静けさは許容する

★ 作者裁定（原文）：

> これはそのままでよいと思います。この時代はどちらかというと、植民地の独立が主なので。実装が本格化すれば、この時代に独立が頻発する機構を考えます。

⇒ 時代延長（`GameQuarters 604→668`）で1934以降が薄くなることは**このラウンドでは問題としない**。この時代の主題は軍事ではなく**脱植民地化**であり、独立が頻発する機構は**別ラウンドの課題**として立てる。

⚠ したがって忠実度ハーネスの断面は 1914 に固定したまま（A3裁定）で、1934以降は**測らない**。
