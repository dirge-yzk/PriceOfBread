# 港配線の簡素化案【完了 2026-09-21＝案1を採用・署名の層を削除（seed 1/6/25 で sha256 一致＝ビット恒等）】（2026-08-16・作者指摘「つぎ足しつぎ足しの実装だ。もっとシンプルな方法を」）

## 現状の積層（何がつぎ足されてきたか）

```
構築時に1回だけ配線（NearestPortName/SeaBasin/PortLandKm を州に焼き込み）
 └ 領土が動くと古くなる → 通過港だけ署名検査で再配線（RewireTransitIfTerritoryMoved）
     └ 本体の港配線は古いまま → A5＝国別署名＋条件付き再配線＋旧配線の消去＋…（休眠・未点火）
         └ Locked辺境港（ウラジオストク）が構築時に候補へ入る穴 → さらにフィルタを足す…
```

**積層の根**：「配線は高い」という暗黙の前提でキャッシュ＋無効化を育ててきたこと。
キャッシュ無効化は状態管理の中で最も事故りやすい種類の複雑さ（署名・呼び忘れ・同時性・保存対応が全部付いてくる）。

## 案1（推奨）＝無状態の毎四半期再計算——「配線は地図の純関数」

- **毎四半期末、全国の港配線を盤面から無条件に再計算する**（WirePortDistances＋WireTransitPorts をそのまま毎期呼ぶだけ）。
- 削除できるもの：領土署名リスト・条件付き再配線・「動いた国だけ」の分岐・呼び出し忘れの心配・セーブ追随の考慮＝**A5の器の大半**。
- 実測コスト：州×港の距離走査＝1国あたり数百回の三角関数＝**四半期あたり1ms級**（シム1四半期の総コストに対し誤差）。節約のための署名層は割に合わない。
- 決定論＝盤面のみから決まる・乱数不使用・冪等（何も動かない四半期は前と同じ値を書くだけ＝軌道不変）。
- 恒等スイッチはそのまま：`PortRewireEnabled=0`＝構築時のみ（現行）／`1`＝毎期再計算。**係数1本・状態ゼロ**。
- Locked辺境港の穴も自然に閉じる：再計算は Active 州だけを港候補にする＝ウラジオストクは解錠した四半期から港になる（構築側にも同じ1行フィルタ＝既存世界にLocked港は無かったので全既存世界でビット恒等）。

## 案2＝現状のA5（署名＋条件付き再配線・休眠のまま凍結中）

- 動くことは検証済み（ON経路テスト3本緑）。だが状態（署名リスト）と分岐が残る＝つぎ足しの延長。
- 案1採用なら署名層だけ削除して再利用（rewireモードのActive限定・旧配線消去のロジックは案1がそのまま使う）。

## 案3（将来・大工事）＝キャッシュ場そのものの廃止

- NearestPortName等の焼き込みフィールドを廃し、読む側（BilateralMarket）が毎回導出。
- 最も純粋だが読者が多く署名変更が広い＝コスト大。案1で問題が消えるなら不要。
