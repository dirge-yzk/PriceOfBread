# 銀行の破綻と取り付けの引き金 — 仕様（2026-09-06・作者採用）— 設計・未着手

## 0. 問い
作者「（銀行がバランスシートを見ずに取り付けが起きる件）これは良い方法があるか？」→ **ある。新しい状態を1つも作らず、既存の2つの観測量と1つの対称な会計で解ける。**

## 1. 根＝取り付けの引き金が銀行を見ていない
`Credit.cs:96`：
```
run = Clamp(BankRunSensitivity × Max(0, ConfidencePivot − avgSat), 0, BankRunMax)
```
`avgSat` は**大衆の平均充足度**。つまり現行の取り付けは「**生活が苦しくなると銀行から金が逃げる**」という形で、銀行の資産が痛んだかどうかを1ビットも見ていない。**1907年型（銀行の資産劣化→預金者の逃避）が原理的に出ない。**

さらに `Bank.cs` は Gold / Loans / HouseholdLoans / Confidence / Heat の5つしか持たず、自己資本も不良債権も無い。倒産した工場の負債は帳消しされない（`Coefficients.cs:104`「負債は帳消ししない・倒産は産出0のみで貨幣非接触」）＝**銀行は決して損をしない**。取り付けが起きても与信が縮むだけで、**預金者は1円も失わない**。

## 2. 直し方①＝引き金に「銀行が支払えるか」を足す（新しい量を作らない）
支払能力の観測量は**既に2つある**。
| 観測量 | 既存の場所 | 意味 |
|---|---|---|
| **カバー率** `BaseMoney / BroadMoney` | `Credit.cs:88-93` の `GoldCoverCreditRestraint` が既に計算している | 預金を正貨で賄えるか（兌換の可否） |
| **レバレッジ** `bank.Heat = Loans / 実効上限` | `Credit.cs:105` で毎日計算・株式ユーフォリアが既に読む | 準備に対して貸し過ぎているか |

```
run = BankRunSensitivity × max(
        Max(0, ConfidencePivot − avgSat),                    ← 現行（生活困窮）＝残す
        RunFromLeverage   × Max(0, Heat − 1),                ← 新（貸し過ぎ）
        RunFromCoverBreak × Max(0, GoldCoverMin − カバー率)   ← 新（兌換割れ）
      )
```
- **`max` で束ねる**（和にしない）＝疫病の伝播（近接／交易／戦争の max）と同じ作法。どれか1つが致命的なら取り付けは起きる。
- 新しい2係数は**既定0＝現行と厳密恒等**。
- これで「好況の末期に貸し過ぎた銀行が、生活が苦しくなる**前に**倒れる」（1907年・1873年型）が出る。

## 3. 直し方②＝銀行が損をする（保存則に触れずに預金が消える）
**貨幣保存を破らずに預金を毀損できる。**恒等式は
```
BaseMoney = TotalMoney + Treasury − OutstandingLoans
```
なので、**不良債権の償却（`Loans` を減らす）と同額の預金の消滅（POP の `Savings` を減らす）は `BaseMoney` を1ビットも動かさない**。これは会計として正しい（銀行の資産＝貸出と負債＝預金が同時に消える）だけでなく、この engine の恒等式にとって**厳密に対称**である。

```
取り付けが致命的（run が上限に達し、かつカバー率が割れている）なら：
    償却額 = Loans × BankFailureWriteoffRate
    bank.Loans      −= 償却額                     （資産が消える）
    POP の Savings   −= 償却額（Max(0,Savings) 比例で按分）  （負債＝預金が消える）
    → BaseMoney 不変・TotalMoney と Loans が同額減る＝資産デフレ
```
- 按分の重みは**既存の利息分配と同じ** `Max(0, Savings) / Σ`（`Credit.cs` の分配と同形）＝新しい分配規則を作らない。絶対額では富裕層が最も失う＝史実の資産デフレの形。
- 償却の副産物として `Heat` が下がり、次の与信が正常化する＝**恐慌の底打ちが機構から出る**（今は与信が縮むだけで底が無い）。

## 4. これで「最後の貸し手」に歯が生える
LOLR は既に live（`LolrStrength=0.7`・`LolrReserveBoost=0.5`・点火2026-07-18）。現状は「run を減らす」だけで、救っても救わなくても**預金は元から安全**だったので効果が薄い。②を入れると：
- **中央銀行があり財政が健全な国**＝救済されて償却が起きない（1890年ベアリング＝イングランド銀行が救った）。
- **無い国／財政が破綻している国**＝預金が飛ぶ（1907年の米＝中央銀行が無くモルガンが即席で代役、1931年のクレディットアンシュタルト）。
**バジョットの原則が、初めて「守らなかったときの罰」を持つ。**

## 7. 罠
- **償却が連鎖しないこと**：預金が消える→充足が落ちる→ run が上がる→さらに償却、の正帰還がありうる。`BankFailureWriteoffRate` を小さく取り、**償却は Heat を下げる**（=次の run を下げる）方向に効くことを確認する。
- **ハイパーインフレとは別問題**：物価は `PriceLevelCeil=4.0` でクランプされている（一覧 §0-5 N7）。ここは触らない。
- **分子と分母**：カバー率は `BaseMoney/BroadMoney`。`BroadMoney = TotalMoney` なので、償却で両方が動く＝**同じ月の中で順序に依存しないよう、償却は run の計算の後に置く**。
- **企業債・金融POP・個別銀行は作らない**（一覧 §0-5 N8＝いずれも経済コアの前提に触る L）。本設計は**銀行1個・POPは既存のまま**で成立する。
