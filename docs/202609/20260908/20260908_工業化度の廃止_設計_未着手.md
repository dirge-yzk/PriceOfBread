## 1. なぜ廃止するか

### 1-1 作者の言葉（2026-09-08）

> 「大規模な作業になりますが、工業化度は廃止したい。これは大手術なので、設計書を作ります。工業化度は盤面から推定可能です。また、廃止すべきバフ・デバフの温床です。」

同日の関連裁定（`docs/202609/99_実装ログ_20260903.md` 末尾）：

> 「国家建設も資本家の投資も同等に建設コストを支払う。可能な限り経路を減らし、同一のメソッドを使用させる」
> 「投資プールも不要な可能性がある。これは資本家（及びその他、投資できる人材）の余剰資産から計算できる」

この2つは同じ結論の別の面である。建設を1本にすると資本は盤面（棟）に立つ。棟に立てば工業化度は盤面から読める。読めるなら状態量として持つ理由がない。

対して、**工場（`Producer.BuiltScale`）が実際に増えるのは World.cs:1476 の1箇所だけ**（`p.BuiltScale += Coef.FactoryBuildScale`）。資本家の投資が RGO の作付面積を広げる唯一の枝（EconomyStep.cs:1745）は `StateShareCounterOnly=1.0`（Coefficients.cs:2825）で1命令も走らない。

帰結として、**1783年の英国は工場を1棟も持たないまま全生産者の能力が ×2.08 になっている**（`Industrialization = 1.4 × IndShare`／`indMult = 1 + 1.2x/(1+x/2.5)`）。これが「盤面に無い工業化度」の最も純粋な実例。

さらに実測（indprobe 40Q・1793年断面）では**民間投資の寄与は国家建設の 0.17〜2.3%**（英ロンドン＝民間累積 0.003 対 国家累積 1.792）で、資本家は 300万〜970万の貯蓄を抱えたまま実質何も積んでいない。積んだ量の 60% は減価で消えている（ロンドン＝投入 2.215 に対し現在値 0.877）。

## 3. 廃止するバフとデバフ

### 3-1 消す（盤面に対応物が無い＝置き換え不要）

| 消すもの | file:line | 理由 |

## 4. 導出の式

### 4-0 何を導出量にするか

**据付**と**稼働**の2つの読み口を持つ。現行の `TotalIndustrialization`／`ProductiveIndustrialization`（Model.cs:449-450）の後継で、意味だけ正しくなる（座礁＝「古い技術」ではなく「採算で止まった設備」）。派生キャッシュとして Region に置き、**書き手は月次の州パス先頭とロード直後の1本だけ**、直列化しない（ロードで再計算＝量子化キャッシュの罠を踏まない）。

### 4-1 1棟が抱えている資本の量（束単位）＝ **建てるときに実際に買った量と同じ式**

```
cpuRef = ConsSteel·RefP[鋼] + ConsMachine·RefP[機械] + ConsCement·RefP[セメント] + ConsLumber·RefP[製材]
       = 1.0×2.1760 + 0.15×4.3948 + 0.4×1.1060 + 0.5×0.8660 = 3.7106      （refprice 実測）

Bundles(g) = FactoryMaterialFrac × FactorySpec(g).Cost / cpuRef
           × (1 + FactoryTierMachinePerDepth × max(0, Complexity[g]−1) × RefP[機械] / cpuRef)
```

右辺は EconomyStep.cs:2496-2514（`AccumulateFactoryBuild` の束見積と階層加算）と**同じ式**。これを1本のヘルパへ畳む（現状 World.cs:1434-1437 と EconomyStep.cs:2496-2497 に二重定義がある）。「建設の帳簿」と「据付資本の帳簿」が同じ1本になる＝**分子と分母の非対称**（本プロジェクトで最も再発するバグ型）を構造的に封じる。

相対資本装備 `w(g) = Bundles(g) / Bundles(軽工業)` は**係数を1つも足さずにカタログから出る**：

| 施設 | `FactorySpec.Cost`（Catalog.cs:493-504） | w(g) |
|---|---|---|
| 軽工業 | 30,000 | 1.00 |
| 重工業（製鉄・化学・窯業） | 70,000 | ≈2.34 |
| 機械・工具・蒸気機関 | 110,000 | ≈3.75 |
| 高級軍需 | 150,000 | ≈5.1 |
| 先端（発電機・電力・機関車・汽船・送電網） | 180,000 | ≈6.2 |
| 超重軍需 | 320,000 | ≈11 |

「電力設備の工場1棟は繊維工場6棟ぶんの資本」が**施設構成そのものから**立ち上がる。旧スカラーが要約したふりをしていた「工業化の深さ」がこれである。

### 4-2 州の資本量

```
Units(p) = BuiltScale_p / FactoryBuildScale                （World.cs:1989-1993 の StateUnits と同じ式）
grid(r)  = GridCapacity_r × RefP[送電網] / (Bundles(軽工業) × cpuRef)

K(r)   = IndPerFacility × [ Σ_{p: !IsRgo, 非役務} Units(p)·w(g_p)                                  + grid(r) ]   ← 据付
Kop(r) = IndPerFacility × [ Σ_{p: !IsRgo, 非役務} Units(p)·w(g_p)·(1−Mothball_p)·(Bankrupt?0:1)     + grid(r) ]   ← 稼働
MeanK  = active 州の K の人口加重平均（World.cs:2172-2178 の式の形は変えない）
```

送電網を入れる理由＝`GridCapacity`（Model.cs:464）は既に「市場から買う（EconomyStep.cs:797,1942）→積む→毎月劣化（:1945 `GridDecayRate`）→戦災で摩耗（Diplomacy.cs:2240）→建造物で加算（Megaprojects.cs:224）」という**完結した実在ストック**として動いている＝盤面の資本財の一部であり、参照価格で束へ換算するだけで新しい係数が要らない。RGO と役務を外すのは「畑と役所は工業でない」＝現行 `Industrialization` が畑を数えていなかったのと同じ扱い。

`K − Kop` ＝ 休止・倒産中の設備 ＝ **旧 `StrandedVintage` の物理版**。

### 4-3 生産者ごとの資本装備（`indMult` の置換）

```
k_p     = IndPerFacility × Units(p)·w(g_p)·(1−Mothball_p) / max(Scale_p, ε)
boost_p ×= 1 + IndProductivityGain × k_p / (1 + k_p / IndProductivityScale)     （EconomyStep.cs:481 の同じ位置）
pr.Mechanization = LaborSaveRate>0 ? k_p/(k_p+LaborSaveIndHalf) : 0             （EconomyStep.cs:414-415 の州複製を廃止）
```

`BuiltScale` を持たない生産者（自営農・役務）は `k_p = 0` ＝ **倍率が存在しない**。RGO は既存の `EffBoost×EffFill`（肥料）で伸びる。関数形も2係数も現行のまま＝新しい形を較正し直さない。

### 4-4 減耗と保守を物にする

```
maintenance   = InfraMaintRate × K(r)                       （EconomyStep.cs:775・式の形は不変）
maintFill(r)  = 実際に賄えた保守量 / 望んだ保守量            （EconomyStep.cs:776 のクランプ比＝既存量）
BuiltScale_p ×= 1 − IndDepreciation × (1 − maintFill(r))    （EconomyStep.cs:396-397 の置換）
```

払えていれば朽ちない・払えなければ朽ちる。`DevelopmentMemory`／`DevelopmentPeak` はこれで存在理由を失う。

⚠**訂正（2026-09-08・§8-1 (2)／§8-4）＝この `maintFill` の定義では成立しない。**EconomyStep.cs:776 の `Math.Min` は比を1つも保持していないし、実際に買えた量は決済側（EconomyStep.cs:1907-1932）で財ごとに別々の `ration[財]` で削られる。さらに `budget = 0.05 × 投資家 Savings`（所得の700〜1200倍）なので予算クランプはほぼ効かず `maintFill ≈ 1` が常態＝**減耗が発火せず棟が永久に朽ちない一方通行のラチェットになる**。⇒ 条件先は予算でなく**市場の配給率**：`maintFill(r) = min over 財 (ration[財])`（既存の正しい型＝`InfraFill`・EconomyStep.cs:2150／建設の Leontief 最小・EconomyStep.cs:1676-1682）。

### 4-5 唯一の換算定数 `IndPerFacility`（＝ `IndPerConstruction` の置換・定数は増えない）

意味＝**軽工業1棟が持つ工業化度**（人が読める量）。値は手で置かない。段0の計器で 1850年・1914年の全州について「現行 `Ind`」対「`Σ Units·w`」を対応づけ、**中央値比**で置く（固定値でなく既存の較正済みの量に絡める＝2026-08-01 方針）。

⚠**訂正（2026-09-08・§8-4）＝値を決めるのは段0でなく段5。**段2〜4で棟の数が桁で変わるので、段0の世界で測った中央値比は「もう存在しない世界の定数」になる。段0は式と計器だけを作り、値は段4の世界を走らせて固定する。合わせ先は**読み手が実際に読む量**＝参照国の `MeanK` 対 `MeanIndustrialization`（人口加重・World.cs:2172-2178）と、首都州の最大値（Validation.cs:110 が読む量）の**両方**（中央値だけ合わせても最大値も人口加重平均も合わない＝分子と分母の非対称の再演）。

**ここが本設計の安全装置**である。現行には約 **97倍の断層**がある：束1単位＝旧単位 0.01（州上限 5.0 まで 500束＝参照価格 1,855）に対し、軽工業1棟＝材料 18,000＝**4,851束**（旧単位換算 48.5）。つまり**繊維工場1棟ぶんの材料費で、州の全生産者の産出倍率を ×1.0 → ×3.0 にする買い物が 9.7 回できる**。閾値群（`RefrigerationIndOnset=1.0`／`MonopolyDissolveInd=0.3`／`EpidemicSanitationHalf=1.5`／`WageClampIndScale=1.0`／`GoldStandardIndThreshold=3.5`／`DecayLockinIndustrialization=1.0`／`CapitalIndTarget=4.0`／`CreditDevScale=0.4`／`UrbanPerInd=0.08`／`IdeologyGateIndScale=3.0`）は全て「0〜5のスカラー」前提で較正済みなので、**換算点を1箇所に集めない限り閾値の取り残しが必ず起きる**。

### 4-6 1783年の初期条件（逆写像）

現行 Simulation.cs:914 の `cfg.Industrialization × IndShare` を、同じ一次データから**初期の棟**へ翻訳する：

```
Units_seed(r) = cfg.Industrialization × IndShare_r / IndPerFacility
→ その州の非RGO・非役務生産者へ w(g) 重みで配分し BuiltScale へ直接播く
```

構成上 `K(1783) ≡ Ind(1783)` が恒等になる（段3は帯を1ミリも動かさずに入る）。⚠**訂正（2026-09-08・§8-4）＝恒等ではない。**恒等なのは K の**値**だけで、`BuiltScale` を播いた瞬間に読み手6本が全部動く：所有 `StateProfitShare`（World.cs:1877）／操業規模の床（EconomyStep.cs:2308）／休止の適格条件 `BuiltScale > Eps`（:2299）／**倒産免除 `s.BuiltScale <= Eps`（:2336）**／`StateUnits`・`PrivateUnits`・`FactoryCounter`（World.cs:1990-2015）／恐慌の解体（Simulation.cs:1976-1979）。⇒ 所有の分離を必ず先に済ませ、受け入れ基準を「帯は動かない」でなく「破綻0＋記録」にする（新しい段番号では段5）。1783年の英が持っていた工業化度が「立っている工場」として盤面に現れ、プレイヤーが最初の画面で数えられる。

### 4-7 却下した案と理由

| 却下案 | 理由 |
|---|---|
| **1人あたり（K÷人口）を唯一の物差しにする** | 「工業化度」の史実の物差しは確かに1人あたりだが、(i) 25箇所の閾値の**単位が一斉に変わる**＝物差しと挙動を同時に動かす禁じ手、(ii) 人口が増えて棟が増えない州で「人口増 → 工業化度低下 → 都市化天井低下」の逆向きループが立つ、(iii) 保守費・安全保障の質量・移民の引力は**絶対量**を要求している。⇒ 1人あたりは `MeanK` の読み口として残せるが、**主たる導出量はストック**にする |
| **`Catalog.Complexity` の深さだけで棟に重みを付ける** | 建設で実際に払った量（`FactorySpec.Cost`）と別の式になる＝立っている資本と建設の帳簿が別規則＝分子と分母の非対称の温床。`Cost` から出せば1本で済む（深さ加算は `FactoryTierMachinePerDepth` として既に `Cost` 側の式に入っている） |
| **`φ_p = BuiltScale/Scale ∈ [0,1]` を生産性の入力にする** | 自然に飽和して係数が1本減る利点はあるが、**尺度不変**なので繊維1棟の工房も電力20棟の複合も φ=1 になり「工業の深さ」の次元が消える。`k_p`（費用重みつき・Scale で割る）なら深さが残り、既存の飽和カーブ2係数をそのまま使える |
| **スカラーを残したまま毎月盤面と同期させる（同期版）** | 二重記帳が残る＝恐慌・戦災・減価で2つの表がずれる型のバグ（現に Simulation.cs:1973 と :1979 で発生している）が消えない。作者裁定の「廃止」でもない |

| **鉄道ストックを本ラウンドで新設する** | 保守費の正しい比例先だが（§7-2）、新しい state を1本増やす＝射程が広がりすぎる。**次ラウンドへ切る**。本ラウンドは保守の読み口を `K` へ差し替えるだけにする |

## 5. 建設の一本化との整合（同日裁定）

### 5-1 現物

|---|---|---|

### 5-2 統合後の形

**建設のメソッドは1本。違うのは払い手だけ。**

```
着工（財の選択＝期待収益に比例・乱数なし）
  → ConstructionLeft（工期）
  → 毎日：材料を市場から買う（同じ束）＋ 工賃を払う（工員 pop の Savings へ）
          払い手 ＝ StateTarget > Units(p) なら国庫 ／ そうでなければ投資家 pop の Savings
  → 完成で1棟（BuiltScale += FactoryBuildScale）
```

- 投資できる金は投資できる階級の余剰から**毎回計算**する（プールという新しい state を持たない＝作者追記）。原資は既存の EconomyStep.cs:627（`IndInvestmentFrac × 投資家 Savings`）。⚠**訂正（2026-09-08・§8-4）**＝その `budget` は**建設・保守・送電網の共通財布**（EconomyStep.cs:655, 774, 795）。`freeCapital` は保守と送電網の取り分を先に引いてから建設に回す（順序を変えると保守が飢える）。
- 「投資を約束した金の取り置き」の役割は**建設中の建物そのもの**が果たす＝着工した工場は完成まで盤面に立ち、工期のあいだ材料と工賃を実際に払う。
- AI ＝ プレイヤー対称：両者とも同じ `World.BuildFactory`・同じ `FacilityBuildScore`（SelfPlay.cs:886 付近）・同じ着工ゲートを通る。

### 5-3 所有の付け替え（一本化の会計上の前提）

現行 `StateProfitShare`（World.cs:1877）は `BuiltScale / Scale` ＝ **`BuiltScale` が同時に国営持分**。段2を先にやると資本家が建てた工場の利潤が国庫へ流れる（EconomyStep.cs:1721 のコメントが同じ罠を過去に踏んだ記録を残している）。よって：

```
stateFrac = min(StateTarget, Units(p)) × FactoryBuildScale / max(Scale, ε)      （Producer.StateTarget ＝ Model.cs:261-263）
World.cs:1476 の StateTarget 引き上げは「国庫が払った工事」のときだけ
```

`BuiltScale` ＝「立っている棟（誰が建てたかを問わない）」、`StateTarget` ＝「そのうち国が持つ棟」。**フィールドは1つも増えない**（意味の割り当てを直すだけ）。併せて払い下げ（World.cs:1960）が `BuiltScale` を削っている点も直す（導出後は「民営化すると国の工業化度が下がる」という誤りになる潜在バグ）。

## 6. 段階と受け入れ基準（**確定版**・2026-09-08）

### 6-0 順序の裁定 ＝ **建設の一本化が先。導出量の差し替えは後。**

理由は3つ。いずれも実測でなくコードの構造から出る（本確定では実行を1つもしていない）。

1. **K は `BuiltScale` から導出される。ところが `BuiltScale` が正に増える経路は World.cs:1474-1477 の1本しかない。**私的投資（EconomyStep.cs:1710）も国家の主経路（EconomyStep.cs:1817）もスカラーを積むだけで棟を1棟も建てない。導出量を先に差し替えると、K は §4-6 で播いた1783年の値のまま**凍る**＝工業化が二度と起きない世界になる。
2. **所有の二重表現**（`StateProfitShare = BuiltScale / Scale`・World.cs:1875-1882）を先に解かないと、資本家が建てた棟の利潤が国庫へ流れる。これは建設一本化の前提であり、導出量とは独立に片づく。
3. 段2の最大の危険（資本コストの断層・§7-4）は導出量と独立に測れる。逆順にすると「棟が増えない」と「読み手が変わった」が同じ走行に乗り、切り分けが不能になる。

**逆向きの律（設計の既存分・維持）**：`Scale` は**絶対能力ではなく労働の取り分**である（`fraction = prodW[pi] / laborTotalW[lp]`・EconomyStep.cs:454 → `Capacity = Pops[lp].Size × fraction × Productivity × boost`・EconomyStep.cs:532）。州の労働プールは固定なので、**棟を建てても州の絶対産出はほとんど増えない**（動くのは加重平均の移動ぶんだけ）。絶対能力を上げているのは `indMult`（EconomyStep.cs:417-419 → :481）＝工業化度スカラーだけである。よって `k_p` の点火（段7）までは民間資本は物理的に薄い買い物をする。段2〜6は二重書き（スカラーも従来どおり積む）で橋を架け、段7で渡し切る。⇒ **`indMult` の削除と `k_p` の点火は同一ゲートで同時**。

## 7. 危険と番人

### 7-1 都市化天井（最初に成立させるべき1点）

PopDecision.cs:43-50 と Meritocracy.cs:478 の `BaseUrbanCap(0.20) + ind × UrbanPerInd(0.08)` は都市人口の**上限そのもの**。置換を外すと天井が消えて都市化が発散するか、0になって都市化が止まる。どちらも破綻ではないが人口・識字・スコアが全滅する。平滑ストック `UrbanIndSmoothed`（`UrbanCapFollowSpeed=0.02`・時定数 ≈4年）が挟まっているので、駆動量を差し替えると時定数の意味が変わる点にも注意。

### 7-2 減耗と保守（本設計で物理が唯一不完全な場所）

保守（EconomyStep.cs:775）は本来「敷設済み鉄道の延長」に比例すべきだが、線路・機関車は毎月買うだけの**フロー**で在庫がない。`GridCapacity` だけが完結したストックになっている。本設計は保守を `K` 比例のフローのまま残す（新しい state を作らない制約を優先）ため、**「工場は建てたが鉄道が無い国」と「鉄道網だけの国」を区別できない欠落は残る**。正しい形は `GridCapacity` と同型の鉄道ストック1本か、鉄道を輸送役務の生産者として建てること＝**次ラウンド**（§4-7 の却下理由と同じ）。

⚠**訂正（2026-09-08・§8-1 (2)-b／§8-4）＝この前提は誤り。**線路・機関車は在庫のあるストックとして**既に存在する**：`World.RailCapacity`（World.cs:885）は線路(56)と機関車(88)を買って積み（Transport.cs:48,109,145）・毎月2%減耗し（`TransportDecay`・Transport.cs:14）・戦災で摩耗する（Diplomacy.cs:2243）。`PortCapacity`（`PortDecay`・MultiNationSim.cs:1264）も同型。**減耗を持たないのは棟（`BuiltScale`）だけ**である。⇒ 新設は不要＝「新しい state を1本増やす」という却下理由が前提ごと消える。保守の比例先に既存の `RailCapacity` を含めるかは休眠係数1本（既定0＝K比例のみ＝恒等）で段7に入れ、点火は段9で判断する。

減耗を保守充足に条件づける（§4-4）と、貧しい州が保守を買えず設備が朽ちる死のスパイラルがありうる（属国化した英が工業0になる旧病理の別形）。段5で indprobe の棟数系列と batch の脱工業化件数を必ず見る。

### 7-3 忠実度の帯と較正
