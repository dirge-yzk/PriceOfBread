## ⚠ J-006 の差し戻し（実装側から作者へ・2026-09-03）

★裁定「データ側で名前を変えましょう」を実行しようとして、**前提が成り立たないことが実測で分かった**。

```
world.json の実測： 州 225件／ユニーク 225   植民地 77件／ユニーク 77
  ・州名の重複            → 0件
  ・州名と植民地名の同名  → 0件
  ・植民地名の重複        → 0件
```

⇒ **一次データに同名は1件も無い**。⚠つまり「データ側で名前を変える」対象が**存在しない**。

★では実測の「衝突1件」は何か＝ガードが見ているのは「**奪う側が既に同名の州を持っているか**」である。
名前は全世界で一意なので、これが真になるのは
**同じ領土が「州」と「植民地オブジェクト」の両方の姿を、時間をまたいで往復したとき**だけ。
（＝仕様書 §9 が「悪い形の第14種＝**二重の実体**」と呼んでいるもの。）

### ★推奨（差し戻し案・1つ）＝**往復をやめる**

名前を変える（データ側・機構側のどちらでも）のは**症状への対処**で、往復が続く限り別の名前でまた起きる。
⇒ 一度「州」になった領土は**二度と Colony オブジェクトに戻さない**。これは従属の一般化の到達点そのもので、
　衝突という現象が**クラスごと消える**（ガードも計器も要らなくなる）。

⚠作者判断が要る点：この差し戻し案でよいか。⚠往復を止める作業は Colony 型の撤去（実行計画のV4）と同じ範囲に入る。
