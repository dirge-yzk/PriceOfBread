## 0. 先に潰すべき2件 — 実装すると壊れる

### ★★★ ① 電信網の財ID＝**起動即死**

doc §6-2 は電信網を `new(139, "電信網", ...)` として追加する。しかし：

```
Catalog の最大 id は 136（goods.json は137件）
Catalog.cs:588-605 ComputeRefPrices と :431 ComputeComplexity は
  new double[Goods.Length] に rp[g.Id] = ... を左辺**無ガード**で書く（境界ガードは投入側だけ）
```

⚠ 137/138 を飛ばして139だけ足すと `Goods.Length=138` に対し添字139で
**静的初期化が `TypeInitializationException` ＝起動した瞬間に死ぬ**。

→ **id は連番で詰めること**（無線137・光学機器138・電信網139 を同時に足すか、電信網を137にする）。

### ★★★ ② 距離の駆動源の差し替え＝**live な機構を無言で殺す**

doc §6-3 は `EraFactor(worldTech, k)` の第1引数を `TelegraphFill` へ差し替えると書く。しかし：

```
worldTech は 1.7〜2.9 の範囲（TransportRevolutionOnset=1.7 / Span=1.2）
TelegraphFill は 0..1

差し替えると ramp = (fill − 1.7) / 1.2 が常に負 → Clamp で 0 → 戻り値が恒久 1.0
```

⚠ **1.0 は恒等値なので、Era群6本が全部死んでもテストは全部緑のまま通る。**
これは「[[pob-gate-green-is-not-working]]（何もしない機構は何も壊さないので必ず緑になる）」の最悪形。

→ 正しい形は**引数の差し替えではなく1行の乗算**：`ramp *= Clamp(telegraphFill, 0, 1)`（新定数ゼロ・fill=1 で厳密恒等）。
