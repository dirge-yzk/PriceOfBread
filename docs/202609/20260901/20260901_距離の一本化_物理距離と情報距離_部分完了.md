## §0 結論

**新規発明ではなく、抽出である。** 事実上の距離は既に存在し、交易モジュールの中に閉じ込められている。

| | 決定 |
|---|---|
| 名前 | **物理距離**（質量が動く）／**情報距離**（報せが動く） |
| 物理距離の実体 | `BilateralMarket.PairKm` を共有サービスへ**抽出**する（新規に書かない） |

## §1 現物の棚卸し — 良い距離は既にある

### §1-1 `PairKm` は既に事実上の距離である

```csharp
BilateralMarket.cs:250  double PairKm(int a, int b)
    // 海路（SeaGraph の経路グラフ＋扼者ゲート）と 陸直行（PathGraph.LandMatrix）の min
    //   陸脚に terrCost（地形）× landRatio（鉄道の実効比）を掛ける
    //   別陸塊なら +∞ ＝ 自動的に海が選ばれる
```

問題は**メソッド内のローカル関数**であること。`tr` / `terrCost` / `landRatio` / `suezOkN` / `landNode` を捕捉しているため、交易以外の誰も呼べない。

### §1-2 他の全機構は素の距離を使っている

| 機構 | 使っている距離 | 地形 | 鉄道 | 陸路 | 扼者 |
|---|---|---|---|---|---|
| 交易 | `PairKm` | ✓ | ✓ | ✓ | ✓ |

| 侵略・割譲（`LandReachKm` / `CessionMaxDistanceKm`） | 大圏 | ✗ | ✗ | ✗ | ✗ |
| 革命の波（`RevolutionWaveDistanceKm`）・派閥合流（`FactionMergeRangeKm`） | 大圏 | ✗ | ✗ | ✗ | ✗ |

## §2 なぜ1つの数にできないか — 2チャネルの根拠

1866年に大西洋横断電信が通った後も、師団を1つインドへ送るには3週間かかった。
**1つの数にすると電信が師団を運び始める。**

そしてこの区別は「帝国のパラドクス」そのものである：

```
電信を敷く → 統治の応答が速くなる（情報距離↓）→ 支配度↑
           → 現地の識字層が世界を知る（情報距離↓）→ 民族主義が伝播 → 闘争度↑
兵の展開は速くならない（物理距離は変わらない）→ 鎮圧の費用は下がらない
```

**1つの数にすると、このパラドクスが原理的に書けない**（電信が鎮圧も安くしてしまう）。

## §3 定義

### §3-1 物理距離

```
物理距離(A→B) = min( 海路, 陸直行 )
  海路   = SeaGraph の最短路（扼者の開閉を辺フィルタで反映）＋ 両端の陸脚
  陸直行 = PathGraph.LandMatrix（別陸塊なら +∞）
  いずれも 地形係数 terrCost × 鉄道の実効比 landRatio を陸脚に掛ける
```

**＝ `PairKm` の式そのもの。** 段1では一字も変えずに抽出する。

### §3-2 情報距離

```
情報距離(A→B) = 物理距離(A→B) / (1 + InfoTelegraphWeight × 電信到達(A,B))

  電信到達(A,B) = min( TelegraphFill(A), TelegraphFill(B) )
                  ＝ 両端が敷かれていなければ届かない
```

- `InfoTelegraphWeight = 0`（既定）で **情報距離 ≡ 物理距離**＝厳密恒等
- 電信が無い1783年の世界では、報せは船と馬で運ばれる＝物理距離と一致するのが正しい形
- 壁でなく逓減（1/(1+kx)）。閾値を1つも置かない

### §3-3 誰がどちらを読むか

| 消費者 | チャネル | 理由 |
|---|---|---|
| 交易・輸送 | **物理** | 財が動く |
| 治安維持費の**駐屯**部分 | **物理** | 兵・石炭・糧食が動く |
| 治安維持費の**統治**部分 | **情報** | 命令と監督が動く |
| 侵略の投射・割譲の射程 | **物理** | 軍が動く |
| 移民・招聘 | **物理** | 人が動く |
| 緊張の伝播・革命の波 | **情報** | 報せが動く |
| 技術伝播（`DiffusionWeight`） | **読まない** | §3-4 |

### §3-4 技術伝播は消費者に入らない

```csharp
MultiNationSim.cs:870
  double link = c.DiffusionWeight * (pf[a][b] / worldFlow) * media[a] * media[b];
```

**貿易フローを読んでいる。** 貿易フローは既に `PairKm` で形が付いているので、技術伝播は距離を**間接的に継承済み**である。ここへ距離を直接足すと二重計上になる。

## §4 実装上の急所 — キャッシュの境界

`PairKm` は「1 Step 内で純関数」だからメモ化できている。`SeaGraph.DistCache` も `(suezOpen, panamaOpen)` の4スロット固定である。

⚠ 実効距離を**国ごとの状態**（誰が電信を敷いたか・誰が封鎖しているか）に依存させると、キャッシュキーが破裂する。

```
規律：幾何はキャッシュ、国ごとの修飾はキャッシュの外で乗算する。
      物理距離(幾何・キャッシュ可) × 国ごとのスカラー
      情報距離 = 物理距離 / (1 + w × 電信到達)   ← キャッシュの外で1回割るだけ
```

量子化キャッシュの不変条件（キーが量子化なら値も量子化入力から計算する）と同じ規律。
