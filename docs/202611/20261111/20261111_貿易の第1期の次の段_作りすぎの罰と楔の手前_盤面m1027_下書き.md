## §3 案〈全て AI の案・確証なし〉

### 案 A（推奨）：〈売れる量〉を州の外への売りと買いで両側に直す

- 形：EconomyStep.cs:962 の `sellR = max(LastDemand, TargetStockFloor)` を、旗 1 で `sellR = max(LastDemand + PrevExport − PrevImport, TargetStockFloor)` へ。〈州の生産者が実際に売れた量〉＝州の需要−輸入で埋まった分＋州の外へ売れた分。
- 新しい係数 0（旗 1 本だけ・既定 0）・新しい状態 0（PrevExport・PrevImport は Model.cs:835-836 にある・:900 で写す）・閾値 0・床は既にある TargetStockFloor（今の式と同じ）。
- 読む欄は **PrevExport・PrevImport**（LastExport・LastImport は :901 で 0 になった後＝常に 0）。LastDemand と同じ前の月の量＝次元が合う。
- 良い所：
  - 値段の側（P3・2026-08-30 点火）は既に輸出を見る＝量の側を同じにするだけ。州の中の需要と外への売りを同じ扱いにする（等価の原則・README §1-8 の対称）。
  - 両側＝輸出する州は労働が来る・輸入で埋まる州の生産者は労働を手放す。片方向の錠を作らない。
  - 輸入の側は史実の型〈安い輸入が国内の生産を置き換える〉（material §1・1846 年の後の英の麦〈AI の記憶・要出典〉）の経路になる。今は値段→操業規模（P4・RGO は速さ×0.25）の遅い経路しか無い。
  - 1 行・計算量はほぼ 0（ただし貿易が増えれば眠りから起きる行が増える＝清算の行の費用が増える。下の門）。
- 難しい所：
  - 墓標 ExportDemandWeight（Coefficients.cs:53-55・2026-08-22〈価格に輸出が載るので次元不整合〉）。〈AI の読み〉あれは量の項が無い重み（準レント×単位能力）への別建ての加算。是正3（2026-08-23）の後の重みは〈準レント×量〉＝量の項の中身を州の中の需要から〈売れた量〉へ替えるのは、別の項を足すことではない（⑨ の二重計上に当たらない理由）。州の中の需要も値段と量の両方に載っている＝輸出だけを値段だけにするほうが非対称。
  - 主食の不作の月：輸入が増えた翌月に、州の農の労働の重みが下がる。平滑 0.15 と値段の高さ（rentR）が打ち消す側〈推〉。門 U3 で見る。
  - 正の帰還（輸入→州の生産が減る→不足→輸入）で特化が進む。止めるのは値段（rentR）と運賃と関税＝費用の側（§1-8 の〈歯止めは値段と費用で〉）。発散は止める線。
  - EconomyStep.cs の労働の塊＝lw（労働力の重み・作者 2026-11-11）と同じ塊。次の段の挙動の線は lw の実装と同じ波に置かない。
  - 案 B（eb・EndowmentCostFollowsAbundance）は非産地の単位費用を上げる＝非産地の操業規模が縮み不足が出る→輸入→案 A の輸入の側が効く＝**掛け合う**。門の閾値は〈eb の採否の後に決める〉。

### 案 A′（退ける）：輸出だけを足す（`sellR = LastDemand + PrevExport`）

- 良い所：主食の不作の月の危うさが無い。
- 難しい所：片側＝輸出する州は得をし、輸入で埋まる州の生産者は罰を受けない＝〈国内の生産は外国の品に置き換えられない〉が残る（量の段で余りの大きな財が閉じている型に届かない）。§1-8 の片方向。

### 案 B（後ろ・第1期の後半か案 A の後）：買い手の量の規則の〈物理の腕〉を見直す

- 形：BilateralMarket.cs:843（行の門）と :988-989（X の xNeed）。値段の静止点 xPrice が物理の不足 xNeed を超えて買えるようにする＝安い外国の品が直接に国内の生産を置き換える。
- 良い所：閉じた行の 63% に直接に届く唯一の案。
- 難しい所：xNeed は〈安すぎる着値で静止点が無い穴を塞ぐ〉腕（:986 の注）＝外すと過剰発注の振動（価格振動の根② の型）。:843 は高速化の飛ばしの門でもある（需要なしの行を走査しない）＝走査の行が増える＝計算量の余り約 17.5 秒を超える見込み〈推〉。案 A で州の生産が動くと、xNeed そのものが動く＝案 A の後に要否を読む。
- 推奨：実装は案 A の採否の後（eb の後でもある）。**設計の材料は今から並べる**（計算量の払い方・振動を止める形・:843 の飛ばしを残したまま xPrice が xNeed を超える量を読む計器）。使った額の約 2/3 に届くのは案 B（か X の同じ働きの直し）だけ。

### 案 C（退ける）：楔の手前の門（眠り・在庫の取り置き）

- 眠り（R0・ClearingIdleSearchQuarters＝4・Coefficients.cs:2348）：眠る行は〈前の月に輸入が無く、不足が無いか主食でない〉行＝起こしても大半は需要なしで閉じる〈推〉。起こすほど計算量が増える（高速化の段で入れた門）。

- 売り手の段の〈その他の門〉.355 の中の P6 の分は計器で分けられない（C4a）＝分けてから要否を読む。
