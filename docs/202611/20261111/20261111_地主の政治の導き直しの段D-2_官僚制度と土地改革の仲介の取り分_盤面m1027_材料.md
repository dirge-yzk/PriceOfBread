## 2. §3-2 の取り直し（問い 1・lordstat1032_out.txt）

### 2-1 旧の紙の〈2 倍〉と〈1 を超える千件〉の正体＝数え方の誤り〈実測＋ソースの読み〉

- 旧の紙 `rulecut1016.py:85`〜`:88` は rule_s の `ruleCutPerMonth` を州の行ごとに足した。この列は国の LastRuleCut を州の全ての行に書いた値（`InstrumentsRule.cs:84`）＝**分子が州の数の倍に膨らむ**。州の多い国（露・オスマン・マラータ）が和を占め、どの国が〈動く組〉にいるかは腕ごとに違う＝和÷和が腕で揺れ、1 を超える行が千件の桁になる。
- 分母が 0 以下の行は少ない（class_s の貴族と聖職者の所得が 0 以下の行は種 1 の 29946 行中 13 行）＝0 か負の分母は原因ではない。正の小さい分母の寄与は分けていない。示せたのは州の数の倍に膨らむ分子（上）。

## 3. 二重計上の読み（問い 2・思想⑨）

- 分子が重ならない条件：LordStake の分子は地代（`EconomyStep.cs:747` が LandRentPerMonth に書く）・S_mid の分子は取り分（`Model.cs:333` が EarnedPerMonth にだけ書く・LandRentPerMonth には書かない）。地代と取り分はともに EarnedPerMonth の部分で、互いに重ならない（grep `LandRentPerMonth +=`：`EconomyStep.cs:747`・`Simulation.cs:996`・`Colonial.cs:161` の 3 か所だけ＝取り分の移しは無い）。
- 式：Rent0＋Cut ≦ Income0（POP ごとの負の所得を除く）より、LordStake の取り分の部分と S_mid の和は (ΔRentShare÷RentShare)×Rent0÷Income0＋ρ×f̄×ΔI÷I×Cut÷Income0 ≦ (Rent0＋Cut)÷Income0 ≦ 1。
- 軸の間：ある時点で I を下げる一段は、max の大きい側の軸だけ（E＞L なら官僚制度だけ・L＞E なら土地改革だけ・E＝L ならどちらも 0）＝同じ取り分を 2 本の軸で同時に数えない（表 §2-3 の各行で、官僚制度の次と土地改革の次の少なくとも片方は I のまま）。
- 国教（D-1b）の十分の一税との重なり：十分の一税の受け手は聖職者・取り分の受け手は貴族＝分子の POP が違う。
