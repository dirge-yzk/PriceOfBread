## 0. 先頭（設計から外れる所と推奨の要約）

- **設計の置き場から外す推奨（名乗る）**：峠の削除（設計 §15 :653〜:660＝段 R の中の 1 項）は**段 R の腕から外し、R の後の別の挙動の線**にする。
  - 理由：陸の直行の換算 km は両端の州の地形しか見ない（BilateralMarket.cs:108）。PathGraph の辺に地形の重みは無い。遮断だけを消すと、途中の山脈は費用に一切現れない。
  - 峠の読み手は貿易の外にもある（ArmyShape.cs:225・Geo.cs:86・MultiNationSim.cs:224）。R の門（貿易の物差し）では測れない。
- **設計の中の食い違いの扱い**：敷き方は、後に書かれた §13（作者が「推奨でよい」で採った〈今ある建設の 1 種として敷く〉）と §15（地形で敷く費用）に合わせた案 R3 を推奨する。§3-4 :175〈国の買いを配る・建設の 1 種は採らない〉の形（案 R1）は採らない側に置く。作者の採った物は上書きしていない。
- 段 R の推奨：案 R3＝州の線路の在庫 T_r を、送電網（`Region.GridCapacity`）と同じ形で州の投資家がその州の不足へ買って積む。国の `RailCapacity` は Σ T_r から導く。
- **指示と設計の門から外す所（名乗る）**：
  - 案 R3 は、指示と設計 §8 :457 の門〈保存＝Σ T_r が旗 0 の RailCapacity と同じ買いの量〉を捨てる。R3 は州の不足へ買い、置換の項で定常の買いが約 13% 増えるので、旗 0 と同じ量にならない。代わりに財の台帳から独立に数える保存（§3 の G2）を置く。この門を残したいなら案 R1 になる。
  - 設計 §3-4 :176 の〈戦災は交戦した州だけ〉は入れない。州ごとの前線の量が今の木に無いので、今と同じく劣勢の国の全ての州に同じ率を掛ける。
- 段 R の最大の危険＝計算量：陸/海の比が州ごとに毎月動くと、距離の表の持ち越し（BilateralMarket.cs:383〜433）が鉄道の時代に効かなくなる。実の CPU は +9〜23 秒の見積もり。引き直しの回数は .cost の数える項に無いので、推定の秒には出ない＝**止める線（推定 248.5 秒）が働かないまま重くなる**。**段 R の線の最初の恒等のコミットで、距離の表を〈対ごとの成分〉で持ち越す形に組み替え、数える項も足す**（ビット恒等にできる・+0.3〜0.9 秒の見積もり）。
- 段 C′ はまだ事前登録を閉じられない。理由は 3 つ。
  - S1 の数（Vb の厳密・q_t の下の影の外国）が空欄。
  - 門〈O の世界の取り分の最大が 0.3 未満〉が、旗 0 の影で既に赤（清 0.6〜0.9・3 腕とも）。
  - i の循環の切り方が未決。
- **波105 の推奨＝段 R を先にする**（BilateralMarket.cs に触れる 1 本＝R）。C′ は 106 以降に回す。

## 1. 段 R の案（新しい状態・新しい係数を作らない形から）

### 案 R2：新しい状態なし（国の在庫のまま・充足を連続に）

- 形：
  - 国の充足 g_n＝RailCapacity_n ÷ target_n。
  - 陸の脚の比を、国の発見の 0/1（:345〜346）から g_n へ替える。
  - 届きには g_n × s_n(r) を使う。
- 良い所：新しい状態 0・新しい係数 0。割譲の移し（Territory.cs:313〜321）はそのまま。差分は最小。
- 難しい所：
  - **州の違いが出ない**。清算の州の容量は `RailCapacity × share_r`、要る線路は `target × share_r` で、比を取ると share_r が約分される（g_r＝g_n）。
  - 作者の言葉〈州に引いた量〉と〈満州で鉄道を奪われる〉が出ない。線路の場所を覚える量が無いので、潜在量が動けば線路も一緒に動く。
- 置き場：段 C′ を R より先にする場合の仮の形（設計 §8 :455 の〈国の充足〉）。

### 案 R1：T_r（州の double 1 本）・国の買いを州へ配る（設計 §3-4 :175 の形）

- 形：
  - 今の BuyToward の量・門・値段は変えない。
  - 増えた容量を、国の州へ潜在量の比（`Transport.RegionShare`）で配って T_r に足す。
  - 減耗と戦災は州の T_r に掛ける。割譲では T_r が州について行く。
- 良い所：
  - 潜在量が動かず割譲も無い間は、Σ T_r が旗 0 の RailCapacity と同じ式で積まれる（減耗・戦災・買いが全て線形）。
  - そのため、保存の門が鋭くなる。
- 難しい所：
  - 州 A の投資家が払った線路が州 B に敷かれる（払い手と場所が別）。
  - 地形の費用（§15）を掛けると、Σ T_r と国の買いの量が合わなくなる。
  - 作者が採った §13〈建設の 1 種として敷く〉と形が違う。

### 案 R3（推奨）：T_r・州の投資家がその州の不足へ買って積む（送電網と同じ形）

- 形：
  - BuyToward の鉄道の枝の中だけを替える。
  - 州 r の欲しい単位＝［BuildRate × max(0, need_r − T_r) ＋ TransportDecay × T_r］ ÷ CapPerUnit × 地形_r ÷ 財の数。
    - need_r＝target_n × share_r。
    - 地形_r＝`TerrainRailCost`。
    - 第 2 項は維持の置換（`GridReplaceRate` の先例）。
  - その州の投資家が、その州の市場から `Procure` で買う（今と同じ買い手・同じ市場）。
  - 積むのは T_r ＋＝ 買えた量 × CapPerUnit ÷ 地形_r。
- 良い所：
  - 今ある州ごとの在庫の形（送電網：EconomyStep.cs:1336〜1338・:2493〜2504・戦災 Diplomacy.cs:2622）を写すだけ＝新しい仕組みでない。
  - 払い手・場所・地形の費用が同じ州で閉じる（§13・§15 と合う）。
  - 線路は需要（潜在量）のある州に積まれる。シベリアの通過の州は潜在量が小さく、線路も薄い（設計 §3-4 :181 の限界はそのまま残る）。
  - 置換の項で、十分に買える州の定常は T_r＝need_r（今の国の形は、減耗 0.02 と BuildRate 0.15 で 0.88 × target に止まる）。
- 難しい所：
  - 買いの総量が旗 0 と変わる（州の不足の和 ≧ 国の不足・置換の項で定常 +約 13%）。保存の門は〈旗 0 と同じ量〉でなく、財の台帳から独立に数える形にする（§2）。
  - 線路の財の需要が増え、値段を通して工業に波及する（記録）。
- 新しい状態：T_r（州の double 1 本・物の在庫）。国の `RailCapacity` は Σ_{自国の州} T_r を返す読み口へ（国 1 本 → 州 1 本で、二重に持たない）。
  - 導けない理由（思想⑩の〈本当に必要な場合〉）：
    - 国の在庫と取り分の規則からは、州ごとの充足が出ない（案 R2 の約分）。
    - 割譲で線路が州について行くこと（作者の言葉）には、場所の記憶が要る。
- 新しい係数：0（BuildRate・Decay・CapPerUnit・TerrainRailCost・RailCostFraction・LandSeaCostRatio は既にある）。
