# 2. 何を直そうとしているか（問題の連鎖）

## 2-1. 発端＝イギリスが開幕16年で軍を失う

`chronicle 1` の実測：1783年にスコア37で**世界1位**（工業化0.33＝2位以下は0.00〜0.12）だったイギリスが、**1799年に軍0.0**。1787年から仏・ハノーファー・墺・普・日・**イエメン**・清・**ブハラ**・マイソールに次々敗れ、3回属国化される。本国5州のうち4州を1787-1792の6年で失い、**151年間1つも回復しない**（batch10 平均で領土×0.22）。

## 2-2. 第1の原因＝平時の均衡兵力が人口だけで決まる

```
Military.cs:63  desired = MilitarySpending × MaxSoldierFraction(0.04) × manpower   ← 農民+労働者+現兵士のみ
```
財政も工業も技術も入っていない。イギリスは初期兵1125に対しこの式が**90**しか許さず、毎月8%（`SoldierMigrationRate`）で復員し、**最初の戦争（1786年）の時点で初期値の8〜22%**しか残っていない。**戦争で溶けたのではなく、戦争前に消えていた。**

実測（`armydump`）：初期軍÷均衡の比は 蘭45.2 / 普22.5 / 英12.5 / 仏2.0 / 日1.2 / **清0.1**（中央値7.2）。**`world.json` の `military` 値が数年で意味を失う。** 清だけは逆で、開幕から軍が10倍に膨れる。

## 2-3. 第2の原因＝残余予算のカスケードが構造的にゼロになる

```
EconomyStep.cs:537  afford    = min(1, MilitaryBudget / estCost)
EconomyStep.cs:553  remaining = max(0, MilitaryBudget − estCost × afford)
```
`afford < 1` のとき `estCost × afford = MilitaryBudget` なので **`remaining` は厳密に0**。上位軍需（機関銃・装甲艦）→ tier3（戦車・弩級戦艦）→ 空軍（戦闘機・化学兵器）の3段が**すべて残余から調達**されるので連鎖して全部ゼロになる。

そして `MilitaryScale = MilitaryUpkeepScale × SoldierSize × warMult`（`Simulation.cs:1242`）で **`estCost` は軍の大きさに比例**する一方、`MilitaryBudget = 軍事費 × MilitaryRevenueShare × 歳入`（`Simulation.cs:1246`）は**軍の大きさに依存しない**。

→ **軍を大きくした国は、数学的に一切の近代装備を持てない。**

実測（`deadend`）：戦車は最大需要0.07に対し最大生産9.47、弩級戦艦0.02/8.87、戦闘機0.00/16.09、化学兵器0.00/22.81。**生産されているのに需要がゼロ。**

## 2-4. ★両端は同じ1つのバグ

`afforddump 200`（1833年断面・57カ国）：

```
afford ≥ 1（上位装備に残余が出る）:  17 / 57
afford < 1（近代装備を一切買えない）: 40 / 57
```

| 残余が出ている国 | 兵数 | afford |
|---|---|---|
| アメリカ | **7** | 91.98 |
| マダガスカル | 107 | 1.98 |
| シク連邦 | 186 | 1.88 |
| エチオピア | 191 | 1.83 |

| 残余ゼロの国 | 兵数 | afford |
|---|---|---|
| オスマン | **2755** | **0.010** |
| ネパール | 1808 | 0.074 |
| マイソール | 796 | 0.021 |

★**「残余が出ている国」は成功例ではなく、軍が崩壊した国。** `afford ≥ 1` は装備予算の指標ではなく**軍が壊れているかの指標**である。
人口大国は装備不能な規模の軍を持ち、人口小国と崩壊国は軍がゼロになる——**2-2 と 2-3 は同じバグの表裏。**

## 3-3. 試行5そのものの欠陥（代数で確定）

```
Military.cs:90  sustain = Math.Min(hr.MilitaryAffordRaw, hr.SoldierPayAffordRaw);
```
- 装備信号 `MilitaryAffordRaw = MilitaryBudget/(Scale×rate×Price)`、`Scale ∝ SoldierSize` → **∝ 1/兵数＝生きている**
- 給与信号 `SoldierPayAffordRaw = SoldierPayBudget/(size×Price)`、`SoldierPayBudget = min(Treasury, size×civWage×SoldierPayMult)`（`Simulation.cs:1313`・`SoldierPayMult=1.0`）
  → 国庫非拘束時は **size が完全に約分で消え**「民間賃金 ÷ 兵力価格」を測っている＝**支払能力を測っていない**

`Math.Min` がこれを選ぶと `desired` が兵数を見なくなり制御が凍結する。

> **原則：軍量の式をこれ以上増やさない。** 6つ目の式を書いても `EconomyStep.cs:553` の残余カスケードがある限り同じ検査で落ちる。

## S3a（実装済み・**測定未完了**）軍需予算を宣言どおり「上限」にする

`MilitaryRevenueShare = 0.25` のコメントは**「軍需調達の上限」**と書いているのに、実装は**常にその額を割り当てる固定額**だった。同じ軍事支出の中で**給与だけが既に `min()` 形**（`Simulation.cs:1313`）で、装備だけが取り残されていた。

```
MilitaryBudget = min(軍事費 × MilitaryRevenueShare × 歳入 × 現金クランプ,  実際の必要額)
```

- 実装＝`Simulation.cs:1246` 付近＋`Fiscal.cs:153` の `militaryClaim` も**同じ式に揃えた**（揃えないと「使いもしない軍事費が福祉・インフラを圧迫する」）

## S3b（未着手）恒常性の信号を装備側だけにする

```
Military.cs:90  sustain = Math.Min(hr.MilitaryAffordRaw, hr.SoldierPayAffordRaw);
              → sustain = hr.MilitaryAffordRaw;
```
給与信号は兵数を見ないので外す（3-3）。すると均衡が
```
均衡兵数 = MilitaryBudget / (MilitaryUpkeepScale × rate × Price)
```
に定まり、**「1兵あたり装備費」が軍の規模を決める唯一のつまみ**になる＝較正できる形になる。

⚠**この時点で軍は壊滅的に小さくなるはず。そこで止めないこと。** つまみを1つにするのが目的で、水準は S3c で当てる。
⚠ `SoldierSustainDriven` を 1.0 に戻す必要がある（いま0）。

## S3c（未着手）`MilitaryUpkeepScale` を技術の関数へ

`MilitaryUpkeepScale = 0.18`（`Coefficients.cs:1168`）は**定数であってはいけない**。
掃討基準の問い「1783年と1934年で同じ値でよいか？」の答えが明確に **NO**。滑腔マスケット→後装ライフル→無煙火薬→機関銃→速射砲→戦車で、1兵あたり装備費は19世紀を通じて実質で大きく上昇した。
★**そしてそれこそがゲームが描くべき転換**＝「大軍を安く維持する時代」から「小さな精鋭を高く維持する時代」へ。ロシアの砲弾不足はこの転換に財政が追いつかなかった事例。

定数のままだと較正は「1783年に合わせるか1914年に合わせるか」の二択になり、**どちらを選んでも片方の時代が壊れる。**

**実装形**（既存の慣習に倣う＝暦年を書かず内生 `TechLevel` で駆動）：
```
1兵あたり装備費 = 基礎 × (1 + 技術係数 × TechLevel)
```
実測アンカー＝英 1806年 t1.00 / 1858年 t1.80 / 1913年 t2.92。

# 7. 記録の教訓（今日追加したもの）

- **「呼び手0件は効果0件を意味しない」**（既存の「file:line はその時点のブランチの座標」に追加）。フィールドへの直接代入・別名ヘルパ・インライン展開で効果は成立する。判定は**その状態を書く経路が1つでもあるか**で行い、`grep "\.Field ="` と `+=` `-=` `*=` を必ず併用する。
- **測定は単独で走らせる。** 1回の交絡（3/10 vs 2/10）で「5回の判定の土台が揺れている」という誤った結論を出しかけた。
- **リミット（上限下限クランプ）が要る時点で設計を疑う。** クランプは折れ点を作り、その折れ点が試行1・2でハーネスを壊した。その反省で作った試行3・4に**新たな折れ点を2つ持ち込んでいた**。
- **較正の目標値は「実際に維持されている量」から取る。** 試行1は「初期軍を保存」を目標にしたが、それは一度も維持されたことのない値だった。
