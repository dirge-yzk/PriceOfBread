# 1. 何をするか

**輸送容量の目標を「人口×定数」から「払えているか」の判定に置き換える。**

## 1-1. ★★★ これは軍とまったく同じ病である

★ 2026-07-31 に軍で同じ誤りが見つかり、修正された：

| | 軍（修正前） | 輸送（現在） |
|---|---|---|
| **目標の式** | `軍事費 × 4% × (農民＋労働者)` | ★`TotalPopulation × TransportTargetPerPop` |
| **費用項** | ⚠**なし** | ⚠**なし** |
| **帰還経路** | ⚠**なし** | ⚠**なし**（★人口が減らない限り目標は同じ） |
| **分布の歪み** | ★清が人口だけで世界最大の軍 | ★**清が人口だけで世界最大の鉄道・海運目標** |
| **欠けているもの** | ★★**「富で軍を養う」** | ★★**「富で船を持つ」** |

★★★ **作者の指摘がそのまま当てはまる**——「**イギリスは人口の割に小さな陸軍でしたが、
富で世界最大の海軍を維持しました**」。⚠ **英も蘭も、人口の割に桁違いの商船隊を持っていた。**

## 1-2. ★ 軍の修正で確立した形

> **給料と装備を払えているか？　余裕があれば増やす。足りなければ減らす。**

★★ **上限・下限のリミットが1つも要らなくなった。** ⚠ そして「大きい方を採る」（`Math.Max(式A, 式B)`）は
**拮抗する国で支配側が切り替わるたび不連続に飛ぶ**ので**採らない**——★軍の3回目の失敗の教訓。

# 2. 診断（現物の実測・★2026-07-31 時点／検証は §7）

## 2-1. ★★★ 目標が人口だけで決まる

```csharp
Transport.cs:14-15   RailCapacity *= (1 − TransportDecay)     // ★減耗 0.02/月
                     ShipCapacity *= (1 − TransportDecay)
Transport.cs:16      ★double target = w.TotalPopulation * c.TransportTargetPerPop;   // 「経済規模に応じた目標容量」
Coefficients.cs      TransportTargetPerPop = 0.08   ⚠ 外的アンカーなし
```

⚠ **コメントは「経済規模に応じた」と書いているが、式には人口しか入っていない。**

★ 混雑シグナルの接続は**あるが休眠**：

```csharp
Transport.cs:19-24   if (c.TransportCongestionWeight > 0) target *= 1 + Weight × 平均(1 − LastTradeThrottle)
                     ⚠「既定0＝不読＝厳密恒等」＝★点火されていない
```

★★ コメント自身が問題を認識している——「★**交易集約の小国は容量を積み増し、
交易の乏しい人口大国は使わない容量へ資金を誤配分しない**」。⚠ **配線済みだが休眠。**

## 2-2. ⚠ 財布の制約は「購入」にはあるが「需要」には無い

```csharp
Transport.cs:52   ★m.LastDemand += perGood;        // 「在庫が無くても需要を計上＝生産を駆動」
Transport.cs:53   if (m.Stock <= 1e-9 || m.Price <= 1e-9) continue;
Transport.cs:54   double buy = Math.Min(m.Stock, perGood);
Transport.cs:56   ★if (pay > investor.Savings) { pay = Max(0, investor.Savings); buy = pay / m.Price; }
```

★ **買い付けには財布の制約がある**（軍にはこれが無かった）——⚠ **だから貧しい国は破綻しない。**

★★★ **しかし歪みは残る**：`:52` で**買えなくても需要が計上される**ので、
**清は買えない鉄道・船の需要だけを市場に出し続け、線路・機関車・帆船・汽船の価格を吊り上げる**
——⚠ **買える国（英・蘭）の調達費を、買えない国が押し上げる。**

## 2-3. ★ 定常が目標に張り付く（別調査の実測）

```
定常容量 ＝ 目標の 88.24%（帆船のみ）〜 92.92%（汽船混在）
```

★★ **採算が判定されていないことが数字に出ている**——**買えるだけ買い、目標の9割で止まる。**

## 2-4. ★ 支払い手と保存則

```csharp

                  ★鉄道＝投資家（資本家）／船＝商人が負担

```

★★ **保存則の作法は既に正しい。** ⚠ 目標の決め方だけが問題。

## 2-5. ★ 容量が実際に効く先

```csharp
InternationalMarket   cap = 港州 ? shipEff : min(inlandRail, shipEff) ＋ 港湾ボーナス
```

# 3. 設計

## 3-1. ★★★ 目標を廃し、収支で増減させる

```
旧   target = 人口 × 0.08                    → 目標へ向けて買う → 減耗 0.02/月
新   ★毎月：容量の維持と拡張を払えているか？
       払えていて余裕がある → 買う（拡張）
       払えていない        → ⚠買わない（減耗が勝って自然に縮む）
```

★★ **軍と違う点が1つある**——⚠ **軍は俸給（フロー）で養い、輸送は資本財（ストック）を買う。**

★★★ **したがって判定対象が違う：**

| | 軍 | 輸送 |
|---|---|---|
| 払う対象 | ★俸給・装備（**維持費**） | ★**減耗の補填 ＋ 拡張の購入** |
| 判定 | 「維持費を払えているか」 | ★**「減耗を補填してなお余裕があるか」** |

★ **減耗（`TransportDecay = 0.02/月`）が既にある**ので、**維持費に相当する量が既に定義されている**
——★★ **減耗ぶんを買い戻せなければ縮む。買い戻してなお余るなら伸びる。**

## 3-2. ★★ 「余裕」をどう測るか — 3案

| 案 | 形 | 評価 |
|---|---|---|
| **A** | ★**買い手の貯蓄に対する購入額の比**（`pay / investor.Savings`）が閾値未満なら拡張 | ⚠閾値が要る（★根拠のない定数が復活） |
| **B** | ★★**混雑シグナル**（`LastTradeThrottle < 1` ＝容量が交易を絞っている）なら拡張 | ★★★**既に配線済み**（`TransportCongestionWeight`・休眠）。⚠ **需要側の信号であって採算ではない** |
| **C** | ★★★**限界価値と費用の比較**（`Colonial.cs:83-87` と同型）＝**容量を1単位増やしたときの交易利得 vs 価格** | ★★**正しい形**だが⚠**限界交易利得の算出が要る** |

★★★ **推奨＝B を点火し、その上で A/C を検討する。**

★ 理由：**B は既に配線済みで係数1本（0→正値）＝思想③の形**。★★ そして
**「使わない容量へ資金を誤配分しない」というコメントの意図そのもの**。

⚠ **ただし B だけでは「富で船を持つ」が入らない**——★ 混雑は需要側の信号で、**支払い能力を見ていない**。
★★ **B で分布の歪み（清が過大・蘭が過小）が改善するかを測り、足りなければ C へ進む。**

## 3-3. ⚠ 需要の計上を見直す

```csharp
Transport.cs:52   ★m.LastDemand += perGood;   // 買えなくても需要を計上
```

★ **意図は正しい**（「在庫が無くても需要を計上＝生産を駆動＝鶏卵回避」）。
⚠ **しかし「買えない国の需要」まで交易に載る**のは別の話（★ 2026-08-12以降は二国間交易）。

★★ **案：支払い能力で頭打ちにする**——`perGood` を `investor.Savings / m.Price` で上限。
★ **鶏卵回避は保たれる**（在庫0でも貯蓄があれば需要が立つ）が、⚠ **無い袖の需要は消える。**

★★★ **これ単独でも、価格の歪み（買えない国が価格を吊り上げる）が消えるはず。**

## 3-4. ⚠ 「大きい方を採る」形は採らない

★★ 軍の修正では**3回目に判明した**——⚠ `Math.Max(式A, 式B)` は
**2つの式が拮抗する国で支配側が切り替わるたび、値が不連続に飛ぶ**。

★ **輸送でも同じ**：「人口目標」と「採算目標」の大きい方、という形にしない。★★ **片方に統一する。**
