# 1. 結論

```
巨大建造物 ＝ 運河テンプレ（個体・完成判定・持分台帳・配当）
            × StateBuildQueue（市場で実物を買う）
            × ConstructionLaborViaMarket（労働を買う）
```

| 要件 | 満たす機構 | 現状 |
|---|---|---|
| 個体として存在し、完成判定を持つ | `Chokepoint` + `BuildProgress >= BuildCost` | ✅ 稼働中 |
| 外資の持分と配当 | `InvestorShares` + `DistributeCanalDividend` | ✅ 稼働中（`CanalInvestReturns=0.5`） |
| 特定の州に紐づく | `Host` + `ResolveOwner`（四半期ごと再解決＝**征服で保有者が動く**） | ✅ 稼働中 |
| **大量の資材を食う** | `StateBuildQueue` → `EconomyStep.cs:418` | ⚠ **運河は使っていない** |
| **大量の労働を食う** | `ConstructionLaborViaMarket` | ❌ **休眠（0.0）** |
| **恐慌時に雇用を吸う** | 上2つ＋不況を読む発動条件 | ❌ **反景気循環の機構は皆無** |
| 威信 | — | ❌ **受け止めるスカラーが存在しない** |

# 2. ★運河テンプレ単体では要件を満たさない（最重要）

**運河は「カネしか消費しない」。**

```csharp
// MultiNationSim.cs:500-502
inv = CanalInvestFrac(0.03) × その国の全活性州の投資家貯蓄
cp.BuildProgress += inv;
p.Savings += inv * (p.Size / tot);   // ← 同じ四半期に全popへ Size 按分で丸ごと還流
```

- **鋼・セメント・木材の市場需要はゼロ**
- **労働需要もゼロ**（`UnemploymentRate` に一切触れない）
- 国内の純貯蓄は不変＝**投資家→全popの再分配にすぎない**

そして決定的なのは、**投資額が投資家の貯蓄に比例する**こと。不況で貯蓄が縮めば投資も縮む＝**プロシクリカル（好況ほど建つ）**。

> **ニューディールの真逆である。** 運河テンプレの骨格をそのまま使うと、要件のうち「大量の資材と労働」「恐慌時の雇用」の2つが原理的に成立しない。

## 対して `StateBuildQueue` は実物を買う

```csharp
// EconomyStep.cs:360-364, 418
costPerUnit = ConsSteel×鋼価 + ConsMachine×機械価 + ConsCement×セメント価 + ConsLumber×製材価
stateConstruction = region.StateBuildQueue / costPerUnit
```

国庫が予約額を積み、翌四半期に**市場から建設束を購入**する。買えた分だけ建設され、残予算は国庫に残る。

**この2つの骨格は現状どこにも合流していない。** 合流させるのが本設計の中身。

# 3. 労働の前提＝先に片付ける2件

## 3-1. `ConstructionLaborViaMarket = 1.0` を点火する

現状、**工場建設すら労働を市場から買っていない**。`investDemand` に立つのは資材4種だけで、工賃は `conWorker` の `Savings` へ直接加算（`EconomyStep.cs:997`）。

配線は完成済み（`EconomyStep.cs:415` に `investDemand[Catalog.LaborId] += conLaborUnits;`）。**係数1本で点火できる。**

★ 旧記録の「未完成スカフォールド」という注記は**誤り**で2026-07-12に台帳訂正済み。

## 3-2. 労働不足で建設が止まるようにする

資材は既にリービッヒ律速が効いている（`EconomyStep.cs:993`）。

```csharp
built = Min(Min(sEff/ConsSteel, mEff/ConsMachine), Min(cEff/ConsCement, lEff/ConsLumber));
```

**しかし労働は律速に入っていない。** `ConstructionLaborViaMarket > 0` の枝は `labQ = conLaborUnits * ration[LaborId]` で**買えた分だけ払うだけ**で、`labQ` は `built` の計算に一切入らない（しかも `built` は労働決済より前に確定済み）。

→ **労働の充足率を `built` の最小に1項足す。** 工場の拡張も同じ `construction` 量から来るので、この1箇所で拡張にも効く。

★ 資材は繰り越せるが**労働は繰り越せない**（今月雇えなかった大工は今月働いていない）。この非対称は正しい。

## 3-3. これで出るもの

```
労働が逼迫 → 建設が進まない → 工業化が止まる → 賃金↑ → 他の生産者から労働を奪う
```

**「資本があっても人がいないと工場は建たない」が復活する。** そして巨大建造物にとって決定的で、**建造物と工場が労働を取り合う**——好況時に建てると民間から奪い、不況時に建てると遊休を吸う。**同じ機構が景気局面で逆の意味を持つ＝ニューディールの本質**を別途書かずに済む。

⚠ **3-1 と 3-2 は同じバッチで入れる。** 3-1 だけだと「労働を買うが律速しない」中途半端、3-2 だけは需要が無いので不能。帯は動く（工業化テンポが全国で変わる）。

# 4. 巨大建造物の設計

## 4-1. データの置き方＝同定キーを一本化する

★**現在スエズ/パナマの同定キーが4系統に散っている。**

| 系統 | 場所 |
|---|---|
| name 文字列 | `world.json` の `chokepoints` |
| `CanalKey` enum | `{None, Suez, Panama}` |
| 部分一致定数 | `MultiNationSim.cs:32-33` の `SuezNameFragment="スエズ"` |
| 完全一致定数 | `Diplomacy.cs:142` の `SuezName="スエズ運河"` |

さらに `Geo.cs` に `SuezWp`/`PanamaWp` の座標がハードコード。**1個体追加＝enum＋係数2本＋コード分岐**で、N件にスケールしない。

→ **`BuildCost`/`TechGate`/効果をデータ側へ移し、id は文字列1本にする。**

⚠ 既存コメントは「JSONに値を複製しない（係数が真実源）」という方針を明言しているので、**この方針との衝突は裁定が要る**。ただし「多数の個体を持つデータ」は係数表に置く対象ではないので、資源賦存と同じ扱いにするのが筋。

## 4-2. 着工条件

| 条件 | 現状 |
|---|---|
| 技術 | `TechGate`（運河が既に持つ） |
| **州の所有** | ⚠ 現在の `Host`/`ResolveOwner` は**収益と封鎖権の帰属**であって**着工条件ではない**。着工ゲートは `TechGate` だけ |
| 追加したいもの | 州を領有していること・（威信型なら）首都であること |

★**「フランスが全州にエッフェル塔」問題は site が1つしかないので構造的に起きない。** 禁止ルールを書く必要がない。

★**これは台本禁止に抵触しない。** 「この州はスエズ運河の建設地である」は「この州には石炭がある」と同じ**データ**であり、「フランスは建設速度1.3倍」のような**倍率・特例**ではない。資源賦存のデータ化は倍率排除キャンペーンで既に受理された前例。

## 4-3. 支払いの経路＝3つの出し手

| 出し手 | 経路 | 消費 |
|---|---|---|
| **国庫** | `StateBuildQueue` 同型（予約→翌期に市場で購入） | **資材＋労働** |
| **自国の資本家** | `IndInvestmentFrac` の budget カスケードの末尾に第4の消費先として挿す | 同上 |
| **外国** | `InvestorShares` の持分台帳（運河が既に持つ） | 同上 |

⚠ **運河は投資家 `Savings` から `CanalInvestFrac` を直接抜いており、`IndInvestmentFrac` の budget を経由しない＝二重取りになりうる。** 新機構では budget カスケードに寄せること。

## 4-4. 外資を募るかの選択 ★単純化する（2026-07-28 裁定）

### 既存の持分表は使わない

現在の `InvestorShares` は `Dictionary<PowerId, 累計拠出額>` で、**全経済国が無条件に自動拠出**する（唯一の分岐は「扼者と交戦中なら停止」）。結果は

> スエズ運河（仏40% / 英30% / 独10% / …）

という多者の持分表になる。**UIとして美しくなく、入札ギミックも要らない。** よって**拡張ではなく置き換える。**

### 単一の外資パートナー方式

```
建造物は「外資を入れるか」の bool を1本だけ持つ
入れる場合、外資パートナーは 1カ国だけ・持分は係数で固定（例 0.5）
```

| | |
|---|---|
| **表示** | 「スエズ運河（外資：フランス 50%）」＝**名前1つ・数字1つ** |
| **持分** | 交渉しない。係数で固定 |
| **相手の決め方** | **決定論のargmax**（乱数なし・入札なし） |

パートナーの選定規則は「**資本余剰が最も大きい列強**（自国と交戦中を除く）」を素案とする。距離でタイブレーク。

⚠ この規則はスエズで仏でなく英を選ぶ可能性が高い（史実では英は当初パーマストンが反対して参加せず、後から株を買った）。**史実の当事国を再現することは目的にしない**——決定論・単一・可読の3条件を満たすことを優先する。

### スエズの劇はイベント1つで足りる

多者の持分表が無くても、史実の核心は**持分が一度だけ他国へ移る**ことで表現できる。

```
1875年型：別の列強が外資持分を買い取る（1回の移転。市場も入札も不要）
条件＝国庫に余裕があり、その建造物の恩恵が大きく、保有国が財政難
```

これで「エジプトが借金で株を手放し、英が握った」が出る。**持分は常に1カ国だけなので、表示も常に名前1つ。**

### トレードオフ

| 選択 | 帰結 |
|---|---|
| **自前** | 遅い・財政を圧迫・**果実は全部自国** |
| **外資を入れる** | 速い・**完成後も収益の半分が恒久的に外へ**・債務不履行時に**外国の介入口** |

### 副産物＝既存コードが減る

`InvestorShares` の Dictionary と `DistributeCanalDividend` の持分比ループが消え、**単一パートナーへの送金1本**になる。運河の既存実装も同時に単純化される。

| 選択 | 帰結 |
|---|---|
| **自前** | 遅い・財政を圧迫・**果実は全部自国** |
| **外資を募る** | 速い・**完成後も収益の一部が恒久的に外へ流れる**・債務不履行時に**外国の介入口**になる |

★**スエズがそのまま出る。** フランス資本で掘り、イギリスが株を買い、エジプトは債務で破綻して保護国化。そして**矯正講和（`ImposeRegimeEnabled`）は点火済み**なので、介入の帰結まで既存機構で繋がる。

★**土地の領有と収益の帰属を分けること。** `ResolveOwner` は四半期ごとに再解決されるので州は征服で移るが、`InvestorShares` は移らない＝**建造物が「外国が握る資産」になる**。これが史実の形。

## 4-5. 効果の2型

| 型 | 例 | 効果の出し方 |
|---|---|---|
| **機能型** | スエズ・パナマ・水力 | 既存の量に効く（海路距離・電力容量）。運河は `Geo.SeaDistanceKm` の経由点として既に実装済み |
| **威信型** | エッフェル塔・水晶宮 | **財を1つも産まない。** 正統性／国民意識／列強スコアへ |

⚠ **威信を受け止めるスカラーが存在しない。** 既存の `Legitimacy`/`NationalConsciousness` に載せるか、新設するかの判断が要る。

### ★裁定（2026-07-28・ユーザー）＝**正統性・国民意識にのみ載せる。威信スカラーは新設しない**

> 「威信はやや面倒な気がしてきた。**マルコフ性に反する**。正統性や国民意識にのみ乗せよう」

**理由＝マルコフ性（規約7）。** 威信ストックは「過去に何を建てたか」の履歴を抱える状態で、現在の盤面から再構成できない。スコア第5項として新設すると、その履歴依存が列強判定にまで波及する。

**実測で確定した前提**：`NationalScore.Of = Military + Wealth + Finance + Tech`（`SelfPlay.cs:19`）の入力は
`SelfPower.Military` / `Gdp` / `MeanIndustrialization` / `MeanSatisfaction` / `Colonies` / `Bank.Loans÷人口` / `TechLevel` の7つのみで、
**`Legitimacy` も `NationalConsciousness` も読んでいない**。よって本裁定の下では **威信は列強スコアに一切届かない**。
§4-5 末尾の「列強一致13%問題への回答」という副産物は**成立しない**＝この動機は放棄する。

**実装上の制約（実測）**：
- **`NationalConsciousness` は避け、`Legitimacy` に載せる。** NC の蓄積は `headroom = max(0, lawCeil×min(1,avgLit/0.6) − prev)` で天井を持つが最終クランプは [0,1] のみ（`CrownParliament.cs:198-213`）。天井の外から直接加算すると教育法・識字が届かない水準まで恒久的に嵩上げされ、**「公教育×識字で買う」という P9 の購入モデルが無効化される**。
- **`w.Explain?.Add("Legitimacy", …)` が必須。** `ExplainTests` が「Explain の Legitimacy 内訳合計 == `w.Legitimacy`（誤差1e-9）」を全断面で検査する硬性ゲート。未記帳だとテストが赤化する（`Diplomacy.cs:1617-1619` に前科あり）。
- **加算位置は `Politics` の再計算の外**。`Politics.cs:356-370` は「前期値−侵食+再生 → マンデート減算 → クランプ」の固定順で、この前後どちらに挟むかで最終ビットが変わる。既存前例の `Formations.cs:384-388`（統一の威信 `FormationLegitimacyBoost=0.1`）に倣い、`Politics` の外で clamp 込みで足す。
- **副作用の把握**：`Legitimacy` を上げると ①`ReformFromAbove`（上からの改革）は `Legitimacy<0.4` が発火条件なので**止まる** ②`CrownRollback`（反動的後退）は `>0.7` が条件なので**起きやすくなる** ③自然回復項が `Rate×max(0,1−Leg)` なので高Legほど効きが薄れる（限界効用逓減が自動＝利点）。

★ ただし雛形はある＝`JointStockApplied`/`RailwayApplied`（`Institutions.Step`）が「**一度きりのブーストを適用済みフラグで管理し、割譲・征服のたびに毎期整合を取る**」型。完成した建造物の恒久効果を州に貼るのにそのまま使える。

★**威信型は恐慌対策として機能型より純粋。** 経済的リターンがゼロなので、ケインズの「穴を掘って埋める」がそのまま表現できる。

★ 副次的に**列強一致13%問題への回答**にもなる。威信が列強スコアに効くなら「工業化と人口だけが大国を決める」現状に別の軸が入る。**列強スコア式（P13）に触れずに、建造物側から効かせられる。**

## 4-6. 反景気循環（ニューディール）

**既存機構の拡張では出てこない。** 新規に「不況を読んで国家建設の支出を増やす」読み口が要る。

読める既存量＝`World.GdpDrawdown`（恐慌の検出）／`p.UnemploymentRate`／`FinancialHeat`。

発動条件の型は既存に前例がある——`Bank` の最後の貸し手が `crisis && FiscalFundingRatio > 閾値`。同じ形で「**恐慌 かつ 財政に余裕**」を条件にできる。

⚠ ただし史実のニューディールは**赤字財政**で成立した。「財政に余裕」を条件にすると不況時に発動しない。→ **国債で建てられるようにする**のが筋で、既存の起債・債務/GDP・信認割引と直結する。

**1 → 2 は逆順にできない**（2は挙動不変なので先でもよいが、1が無いと3以降の効果が測れない）。

## 8-2. 鉄道・トンネル

> ### ★★ トランスコーカサス鉄道が最重要（2026-07-28 追加）
>
> **陸上障壁を貫く巨大建造物のうち、これだけが「無いと世界最大の油田が輸出できない」。**
>
> ```
> ① 資源の振り直し（03 §16）で バクーは世界の石油の約50%（1901年実績）を産む
> ② バクーが面するのは カスピ海 ＝ ★閉じた内陸湖。どの外洋にも繋がらない
> ③ カフカス山脈を貫く鉄道が無ければ、その石油は物理的に世界市場へ出られない
> ```
>
> 史実どおり：1883年のバクー〜バトゥーミ鉄道（後に1906年のパイプライン）が
> **ロシアの石油を輸出商品にした**。それ以前はヴォルガ河舟運で北へ運ぶしかなく国内消費に留まった。
> ノーベル兄弟とロスチャイルドが資本を入れた＝**外資パートナー方式（§4-4）の好例**。
>
> ★ 効かせ先＝**カフカスのバリアノードを貫く陸の辺を1本開通**（§7-2 の形）。
> ★ 開通した石油は黒海へ出て**ボスポラスを通る**＝ロストフの黒海接続・扼者・封鎖の議論と直結する。
> **露の石油輸出がオスマンの海峡に従属する**という19世紀後半の地政学がそのまま出る。
>
> ⚠ **Host の トビリシ は州として存在しない**（露12州にカフカスの州が無い）。**新設が要る**（`03` §15）。
> 暫定で バクー を host にしても機構は動くが、「山脈を貫く」という位置の意味が失われる。
>
> ### ★ 障壁は「貫く手段」が無くてよい場合がある
>
> バリアノードを**山脈の稜線だけに置くと、両端の海岸が自然に峠になる**。実測：
>
> ```
> マドリード → バレンシア → バルセロナ → マルセイユ → リヨン → パリ
>                           ↑ 地中海沿岸（ポルボウ）を自動的に回っている

## 8-2. 設計方針（ユーザー指示2026-07-28）＝**数値は密結合・モジュールは疎結合**

> 「数値は相互に密結合で、さまざまな要素が干渉しあうべきですが、モジュールは単体で動作する疎結合であるべき」

これに従い `Megaprojects.cs` を**独立モジュール**として切り出した（`Colonial`/`Crime`/`Institutions`/`Transport` と同じ規約）。
- **疎結合**：依存は `Diplomacy`（個体の台帳）・各国 `Simulation`（host 州の解決）・`Coefficients` だけ。運河・港湾・保険のどれにも依存しない＝**スエズ/パナマを移行しなくても単体で成立する**（段5を最後に回せた根拠）
- **密結合**：建設は工場と同じ鋼/機械/セメント/製材と労働の市場を奪い合い、同じ国庫を食い、同じリービッヒ律速に服す。完成効果（耕地・送電容量・工業化度）は既存の経済がそのまま読む＝**新しい状態を1つも作らない**

## 8-3. ★設計書からの逸脱（いずれも実測にもとづく）

**(a) §4-4「既存の InvestorShares を単一パートナーへ置き換える」→ 置き換えない。**
現在スエズには**53カ国が拠出**しており、2カ国に絞ると `BuildProgress` が桁で落ちて**開通しなくなる**（海路距離経由で植民地維持費・交易マージン・侵略船要求・投射が全部動き帯が崩れる）。外資は**建造物だけが使う独立機構**とし、運河は既存のまま残した。
また単一パートナー方式では扼者が持分を持たないため、§4-4 が期待する「エジプトが株を手放す」は**そのままでは出ない**（出すなら「外資なし→Bの新規取得＋対価を扼者の国庫へ」の形が要る）。

**(b) §5 実装順 5→6→7 → 6→7→5 に変更。** 段6/7は建造物モジュールの内側で完結し既存機構に触れないが、段5は既存の運河を壊しうる。段5を最後に回すことで、失敗しても先行成果が守られる。

**(c) §4-1 の `Geo.SeaDistanceKm` N経由点一般化 → 採らない。** `Geo.cs:37` が同一海域系なら大圏を返すため、キール/コリントス/ヨータは**原理的に距離を1kmも縮められない**。海路に効く個体はスエズ/パナマだけで今後も増えず、一般化は払いゼロで決定論（Min の適用順）のリスクだけが残る。

## 8-4. 実装後の自己レビューで見つけた3件（設計書§6の地雷そのもの）

崩壊判定（破綻0・169緑）は**これらがあっても通っていた**。判定基準が「致命的に崩壊しないこと」である以上、静かな規則違反は自動では捕まらない。**実装後に自分のコードを読み直す工程は省けない。**

1. **工業化の州上限が素通り**（地雷#4）：`IndustryInvestRegionCap=5.0` は投資の入口3箇所（`World.cs:626`／`World.cs:701`／`EconomyStep.cs:424`）でしか効かず、状態への直接加算は抜ける。この上限はコード上「プレイヤー/AI共通のルール」と宣言されているので建造物にも適用した。
2. **国庫拠出の有界化の式が無意味**：`Min(Frac×T, Cap×T)` は Frac=0.02 / Cap=0.5 で右辺が常に大きく**一度も効かない**。1国あたりの**総額**で有界化する形へ（征服で建設地が集まると現実に踏む）。
3. **予約のゼロ化が条件分岐の内側**：`StateBuildQueue` が持つ既知の永久滞留パターン（`if (cap && …)` の内側でゼロ化＝資本区画のない州や上限に張り付いた州で二度とゼロにならない）と同じ轍。無条件ゼロ化へ。

※3件とも今回の盤面では未発火（修正前後でバイト一致）だが、上限に張り付いた州や征服集中では確実に発火する。

## 9-3. ★外資が全件同一国（ネパール）になる件＝**機構の欠陥ではない**

当初これを「機構の退化」と報告したが、**見立てが誤っていた**。

1. **一極集中それ自体は史実的に正しい**。第一次大戦前の対外投資はイギリス一国が約4割を占めており、資本輸出は本来集中する。
2. 問題は「1国が支配すること」ではなく「**その1国が誰か**」で、それを決めているのは巨大建造物の機構ではなく**列強スコア**＝顔ぶれ一致13%という既知の別問題（#24）の現れ。
3. つまり**直そうとした場所が間違っていた**。

**試みた修正と結果**：
- 第1案「進行中の他事業へ拠出済みの元本を余剰から控除」→ **効かなかった**。建造物どうしは時期的にほとんど重ならず（1868-69／1885-86／1891-92…）、選定時点で進行中の他事業が無く控除が常に0だったため。
- 第2案「完成済みも含めて控除」→ 会計としては正しい（元本は外国資産に固定され利回りを生み続けている）が、ネパールの投資家貯蓄プールが元本より桁で大きく**順位は動かない**。

**現在の実装は第2案を採用している。回転を狙うためではなく、会計として正しいから。** この盤面でネパールが圧倒的に富裕な列強である以上、資本がそこに集中するのは経済的に正しい帰結であり、人為的にばらけさせるべきではない。
