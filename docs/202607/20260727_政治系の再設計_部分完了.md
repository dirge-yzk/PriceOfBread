# 1. 診断

## 1-1. ポート構成は正しい。壊れているのは規律

政治系が答えるべき問いは5つで、既存の P1〜P6 はこれにほぼ1対1で対応している。**アーキテクチャの設計は妥当**である。

問題は、**「1つの根は1つのポートから入る」という規律が存在しない**こと。実測では：

| 根 | 到達するポート数 | 経路 |
|---|---|---|
| `Legitimacy` | **4** | P5 圧政の乗数 ／ P4 遷移バー `PolityInertia×Legitimacy` ／ P6 `MandateMargin` の θ ／ CrownParliament の巻き戻し |
| `WarExhaustion` | **3** | P1 厭戦 ／ P3 天命 `dmWar` ／ P5 `warDrain` |
| `MeanSatisfactionPol` | **4** | P3 天命 ／ P3 一党支配ゲート ／ P4 独裁引力ゲート ／ P4 実績ストック経由 |
| `Suffrage` | **4** | P3 制度ギャップ ／ P1 発言権 ／ P1 政体座標の距離 ／ P3 議会侵食。**②と③は同じ P1 の式の中に2回現れる** |
| `p.Militancy` | **3** | P4 challenge ／ P4 窮乏チャネル ／ P4 実績ストック経由。**すべて同じ P4 の同じ s へ** |
| `PartySeats` | **3** | P3 立憲侵食＋一党支配侵食 ／ P4 独裁引力 ／ P6 議会法重み |

つまり**6ポートを名乗る完全連結グラフ**になっている。

## 1-2. 最悪の型は「二重」ではなく「複利」

一党支配（`maxSeat > 0.6` かつ `MeanSatisfactionPol < 0.66`）は、**完全に同一のゲート・同一の超過量**が2箇所へ入る。

- `Politics.cs:327-331` → 正統性を削る（`DominanceLegitimacyErosion=0.05`）
- `Politics.cs:473-484,505` → 独裁の引力点を上げる（`DominanceCoupWeight=2.5`）

そして遷移の判定式は `Politics.cs:515`：

```
best - cur > PolityInertia × w.Legitimacy
```

**同じ根が分子を押し上げながら、同時に分母（障壁）を削っている。** 二重計上ではなく乗法的に効く。設計者が意図した強度の何倍が出ているか、係数からは読めない。

## 1-3. 過去の対処が「係数の半減」だった

二重計上が気づかれたとき、経路を消さずに係数を割って辻褄を合わせている。

- `UnemploymentMilitancy` 0.8 → **0.4**（コメントが「旧0.8は二重計上」と自認）
- `WarWearinessMilitancy` 0.5 → **1.0**（別経路を殺した補償で倍化）
- 格差＝「二重計上しないよう gini そのものでなく差分のみ」（`Politics.cs:120-121` の自認）

**これが継ぎ足しの正体である。** 経路が残るので相互作用も残り、係数は単独では意味を持たなくなる。いま `UnemploymentMilitancy=0.4` を見ても「失業の不満は0.4」ではなく「二重ぶんを割った後の残り」であり、他の経路を触ると意味が変わる。

# 2. 再設計の3手

順序が重要。**引き算 → 一元化 → 経路整理**の順でやる。逆にすると差分が読めなくなる。

## 手1：削除（挙動不変・ほぼ無リスク）

死蔵64件と到達不能13件を落とす。**厳密恒等**（唯一の注意＝常時0との掛け算が消えるので浮動小数の順序が変わりうる。`chronicle` で確認）。

| 対象 | 効果 |
|---|---|
| ClassStance系 4本＋係数3本＋毎tickの読み手5箇所 | 53カ国×pop×毎tick の無駄な分岐と乗算が消える |
| `CoopArmyCrown` ＋孤児係数2本 | 重複計算1本と死蔵1本 |
| `SupportRate` ＋4つ目の `Build(w)` | 重複実装1本 |
| `legFlow` | 死荷重1本 |
| 到達不能ブランチ13箇所 | 読解コストが直接下がる |
| `p.Mil*` 8本 | **UI が読むので残すが、`#if` か診断フラグで囲って既定OFF**にする（全pop×毎四半期の書き込みを消す） |

**これだけで政治系の状態が15本前後減り、読解対象が目に見えて縮む。**

## 手2：四半期集計を1箇所・1回にする

**いま同じ量が複数の時点で流通しているのが最大の混乱源。** 四半期の頭で1回だけ計算し、不変の構造体として配る。

```
QuarterAggregates（四半期の頭で1回だけ算出・以後読み取り専用）
  AvgMassMilitancy / MeanSatisfaction / AvgConsciousness
  Coerce（= Coercion × 人口/1000）
  Challenge / ChallengeRatio（Clamp版を1つだけ定義）
  PolityCoord（参政権ドリフト適用済み）
  IdeologyFamily[9→3]（写像を1箇所に）
  EthnicUnity / Gini
```

**消えるもの**：全pop走査4回→1回、`coerce` 4実装→1、`challenge/coerce` 4回2型→1回1型、政体座標3回→1回、9→3写像3箇所→1箇所。

⚠ **これは挙動を変える。** 現在は「前期値を読む箇所」と「今期値を読む箇所」が混在しており、一元化すると片方が動く。**だから手1のあとに単独でやり、batch30 で測る。** 逆に言えば、この差分こそが「暗黙の1期ラグに依存していた箇所」の正体であり、洗い出す価値がある。

⚠ **`FamilyOf` のファシズム扱いに注意。** 現在3実装のうち1つはファシズムを暗黙に保守（0）へ落としており、他と偶然一致しているだけ。一元化するとき**どれを正とするか決める判断が要る**。

## 手3：一根一ポート（設計判断・1ポートずつ）

**規約**：ある根が2つ目のポートへ入るときは、直接の項を足すのではなく**1つ目のポートの出力を経由させる**。

裁定が要る主なもの：

| 根 | 現状 | 提案 |
|---|---|---|
| **一党支配** | P3 侵食＋P4 引力＝**複利** | **P4 のみ**に寄せる。P3 の侵食を落とす。「独裁が近づく」効果は引力点で十分表現され、障壁まで削る必要はない |
| `WarExhaustion` | P1・P3・P5 の3つ | **P1（闘争度）を正とする**。P5 の `warDrain` と P3 の `dmWar` は、厭戦が生んだ闘争度・正統性低下から従属させる |
| `MeanSatisfactionPol` | 4経路 | **P1（want 経由）を正とする**。P3/P4 のゲートは満足度でなく、その結果の正統性を読む |
| 失業 | Satisfaction 経由＋直接 | **Satisfaction 経由に一本化**し `UnemploymentMilitancy` を廃止（失業保険の緩和も満足度側へ） |
| 格差 | MilGap＋MilVoice | 差分化は緩和策。**どちらか一方に決める** |
| `Suffrage` の P1 二重 | 発言権と距離 | **これは残す**。物理的に別物（「言えるか」と「体制が自分から遠いか」）であり、明示すればよい |

**手3は1ポートずつ・1バッチずつ。** まとめてやると帯が動いたときに切り分けられない。

# 3. 引いたあとに足す1本＝統帥権

削って空いたところに、**本当に欠けている1本**を入れる。

`PolicyPreferences.OpposingPower`（`:182`）の抵抗の出所は現在2つだけ——3ブロックと議会議席。**軍が抵抗勢力として存在しない。** つまり軍事費をゼロまで削り、将校団が嫌う法を通しても、即時の抵抗はゼロである。

軍が効くのは `AllegianceCoupWeight`（クーデタ確率）と `CrownRollbackRate`（後退ゲート）の2箇所だけで、どちらも事後的・遅い。

**提案（新規状態ゼロ）：**
```
軍の力   = 兵士POPシェア × MilitaryReadiness × (1 − ParliamentControl)
軍の選好 = 軍事費↑に賛成 / 軍事費↓に強く反対 / 親軍法に賛成 / 徴兵制限に反対
```

`ParliamentControl` は定義がそのもの（「大臣責任・予算権の強度。**プロイセン/明治＝広いfranchise×低い統制力**を将来表現する軸」）なので、**統帥権の独立度 = 1 − ParliamentControl**。新スカラーは要らない。

これで出るもの：プロイセン憲法紛争1862（議会が予算を拒むが統制力が低いので軍が勝つ。逆方向の `ParliamentBudgetVeto=2.0` は既にある）／軍部大臣現役武官制（統制力が極端に低いとき内閣そのものを倒す硬いゲート）／イェニチェリ（軍を壊さないと改革が進まない）。

そして**「軍を従属させること自体が最初にやるべき改革になる」**——これは史実そのものである。

# 4. 継ぎ足しを構造で止める

再設計しても、同じやり方を続ければ数ヶ月で元に戻る。

## 4-1. 台帳を「書く」のをやめて「生成する」
`[PORT:Pn]` タグは既にコード中にある。Runner の動詞でタグと係数リテラルから台帳表を吐く。手で同期する限り必ず腐る——実際、制定3日で `AutocraticPolicyAgility` の現値がずれ、`Coefficients.cs:1325` の見出しは今も偽である。

## 4-2. 符号規約を統一する
政治系の全係数を「**0＝恒等・無効**」に揃える。現在 `ConservativePlatformMilitarism` は0が点火値、`StateBuildUnitsPerMonth` は0が無制限＝逆規約が混在し、機械照合が誤答を返す。

## 4-3. コメント規約
```
係数名 = 値;   // [状態:点火済み|休眠] [日付] 意味。点火時の帯＝exact__/near__/◎__。
```

## 4-4. 新項の受け入れ条件
> **新しい項をポートへ足すとき、その根が既に別のポートへ入っていないかを確認する。入っているなら、直接の項を足すのではなく既存の出力を経由させる。**

これを政治ポート台帳の規約6として追記する（既存5条＝周辺→コアはポート経由／離散インパルスに乗数を掛けない／同じ根を2ポートから叩かない／既定0で厳密恒等／`[PORT:Pn]` タグ）。

★**規約3「同じ根を2ポートから叩かない」は既に存在する。** 実測73件はその違反である。**規約が守られなかったのは、違反を検出する手段が無かったから。** 4-1 の生成台帳に「根の重複」を検出させるのが本質的な対策になる。
