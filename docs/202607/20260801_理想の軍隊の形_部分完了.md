# 理想の軍隊の形（Army Shape）— 統合設計書

作成日 2026-08-01 ／ 対象 `C:\Users\dirge\Documents\PriceOfBread\PriceOfBread.SimCore`

## 1. 一文の要約

**理想の軍隊 ＝「自国に向けられている他国の武力（＝相手の軍のうち自分に割り当てられた注意の分）と、自国が自力で守らねばならない資産（国内の秩序と海上の交易・植民地）の合計」であり、これを陸・海の2枝で立て、そこから求めた兵員目標と装備ストック目標に現有が届かない差分が、そのままモノ（装備の発注）・ヒト（徴募）・カネ（軍事費の請求）の需要になる。**

---

## 2. 理想の軍隊の形＝関数の定義

### 2-0. 記法と単位

* 戦力の単位は既存の**戦力ゲージ**（`Power.Military`）。`SoldiersPerMilitary = 250`（Coefficients.cs:1281）。
* 添字 `i` は自国、`j` は他国。`Nation == null`（抽象標的）は**脅威側からも注意配分の宛先からも除外**する（`Projection` が抽象標的に対し `HomeDefenseBonus` を返す分岐（Diplomacy.cs:1938）を誤用しないため）。
* 読む実体量はすべて既存 public。新しい観測量は一つも作らない。

### 2-1. 敵意 h（連続・閾値なし・クランプなし）

```
h(i,j) = d(i,j) × ( φ + (1−φ) × T(i,j) / (T(i,j) + T½) )
```

| 記号 | 実体 | file |
|---|---|---|
| `T(i,j)` | `Diplomacy.Tension(i,j)`（0..200） | Diplomacy.cs |
| `d(i,j)` | 同盟・宗主従属なら `1 − AllyAttentionDiscount`、他は 1 | `HasAlliance` / `IsDependentOf` / `Suzerain` |
| `φ` | 平時の敵意下限（無政府状態＝緊張0でも武力は武力） | 新係数 |
| `T½` | 敵意が半飽和する緊張 | 新係数 |

有理飽和形なので `h ∈ [φ, 1]` が構造的に有界。**上限下限のクランプを書かない。**

### 2-2. 到達 r（既存関数をそのまま読む）

* 陸：`r_land(j→i) = Diplomacy.Projection(j, i, c)`（Diplomacy.cs:1936-1946。距離減衰 `1/(1+DistanceWarDecay×km/DistanceNormKm)` ×海越えなら `SeaControl`）。
* 海：`r_sea(j→i) = Σ_b p̂_i[b] · p̂_j[b]`（`Power.BasinPresence`＝正規化済みプレゼンス。Diplomacy.cs:1869-1887）。

> ⚠ `BasinPresence` は L1 正規化済み（総和1・Diplomacy.cs:1881-1886）である。したがって**この内積を「英の海軍需要の水準」の根拠に使ってはならない**（分散する国ほど内積が小さくなり符号が逆転する。案1の該当主張は却下）。本設計では内積は**「j の海軍のうち i に向く分」を決める相対重みとしてのみ**使い、水準は §2-5 の通商保護項（絶対量）が担う。

### 2-3. 注意配分 a（★本設計の中核＝発散を構造で止める装置）

過去5回の失敗と提案4案すべてが壊れた地点は「脅威＝到達する他国軍の**総和**」で、これは現物の係数（1万kmで減衰0.5・首都53件中46件が同一陸塊 eurasia）では**行和が20を超え、内点の均衡が存在しない**（＝均衡が徴募プールのクランプになる＝『リミットが要る時点で設計が誤り』の再演）。

本設計は「和」を捨てず、**相手の軍は同時に全方位へは向けられない**という物理で正規化する。

```
a(j→i) = h(i,j)·r(j→i) / ( u(j) + Σ_k h(k,j)·r(j→k) )        （k は Nation≠null の他国すべて）
u(j)   = 不穏度(j) = Clamp(Politics.AvgMassMilitancy(j) × (1 − Legitimacy(j)), 0, 1)
```

* **Σ_i a(j→i) = 1 − u(j)/(…) < 1**（列和が真に1未満）。したがって世界の必要量の総和は世界の戦力の総和より必ず小さく、**軍拡ループは構造的に縮小写像**になる。減衰係数は新設せず、`u(j)`（内向きに使われる軍）が担う。
* 帰結（国名を一度も書かずに出る）：清は不穏度が高く対外注意が薄い＝周辺国は清を大きく恐れない／プロイセンは仏・墺・露の注意配分がいずれも高い＝多正面が**和として積み上がる**／米は誰の注意配分も極小＝軍を持たない。
* 分母は正で Eps ガードのみ（クランプではない）。全員が武力0の世界では分子も0＝連続。

### 2-4. 陸の任務

```
Need_land(i) = Σ_j a(j→i) × LandPower(j)              （Diplomacy.cs:18 の既存プロパティ）
Need_internal(i) = InternalGarrisonPerPop × 統治人口(i) × 不穏度(i)
```

`Need_internal` は**他国の力を一切参照しない外生アンカー**であり、これがあるおかげで縮小写像の不動点が 0 でなく正になる（＝「平時ゼロ軍の吸収状態」を機構で防ぐ。下限定数を置かない）。八旗・緑営、露の内地守備、オスマンの駐屯という19世紀常備軍の主任務がここに入る。

### 2-5. 海の任務

```
Need_sea(i) = Σ_j a_sea(j→i) × NavalPower(j)                       … 対抗項
            + SeaEscortPerTradeValue × V_sea(i)                     … 通商保護項（外生アンカー）
V_sea(i) = Σ_{r: Active かつ IsPort} r.LastPortThroughput  +  Σ_{col ∈ SelfPower.ColonyList} col.Value
```

`V_sea` は**絶対量**（正規化しない）。英の海軍が世界最大になるのは「守るべき海上価値が世界最大だから」であって、国別特例でも地理定数でもない。通商保護項は他国の海軍を参照しないので、対抗項と合わせて不動点が正になる（陸の内的秩序項と同型）。

### 2-6. 空は独立の枝にしない（★裁定）

`Need_air = Σ a×AirPower` 型は、全世界の AirPower が 0 の時代に**恒等的に0＝誰も最初の1機を買えない吸収状態**になる（設計①を守れず、必ず暦年ゲートか下駄を要求する）。したがって **空軍財（飛行機130・戦闘機131・化学兵器133）は陸・海それぞれの最上位世代として装備の内訳に置く**。`MilitaryAirFill` の意味と `Power.AirPower = Military × MilitaryAirFill`（Diplomacy.cs:421）は無改造。時代性は既存の `Catalog.DemandOnset` / `DefaultRecipeOnset`（技術水準ゲートであって暦年ゲートではない）が担う。

### 2-7. 質 Q（★装備充足・即応度を絶対に入れない）

```
Q(i) = techQuality × cohesion × militarism
     techQuality = TechMilLowFloor + (1−TechMilLowFloor)×Clamp(TechLevel/TechMilFullLevel,0,1)
                   × (1 − Clamp(DecayMilitaryWeight×InstitutionalDecay×正規化技術差,0,0.9))   ← Diplomacy.cs:417-419 と同一式
     cohesion    = 1 + UnityMilitaryQuality×(EthnicUnity−0.5)
     militarism  = Militarism ? MilitarismStrengthBonus : 1
```

`Q ∈ [約0.36, 約1.43]`。`MilitaryReadiness` と `MilitaryQualityFill` / `MilitaryTier3Fill` を **Q に入れない**のが規律の核である。入れると「装備が買えない → 必要兵数が増える → 予算がさらに人へ流れる → 装備がもっと買えない」という正のループが閉じる（案1・案4がここで死んだ）。**理想は原因だけで作り、症状は結果側にだけ出す。**

### 2-8. 理想の兵員と理想の装備

```
Need_men(i) = SoldiersPerMilitary × [ (Need_land + Need_internal) + NavalCrewPerGauge × Need_sea ] / Q(i)
```

`NavalCrewPerGauge < 1` ＝ 海軍は資本集約・陸軍は労働集約（英の常備陸軍が人口比で小さいことの本質）。これは**兵科のデータ**であって国別倍率ではない。

装備ストック目標（枝別・財別）：

```
陸の耐久財 g:  A*_g = u_g × N*_land ,   u_g = MilitaryUpkeepScale × rate_g / ArmsWearRate      [1兵あたり]
海の耐久財 g:  A*_g = v_g × Need_sea ,  v_g = NavalArmsPerGauge × rate_g / ArmsWearRate         [1ゲージあたり]
   N*_land = SoldiersPerMilitary × (Need_land + Need_internal)/Q
```

`u_g` は**新しい数値ではなく現行の平時消耗からの逆算**である。定常状態で `ArmsWearRate × A*_g = MilitaryUpkeepScale × rate_g × 兵数` ＝ 現行 `MilitaryScale × rate_g` に**厳密一致**する。これが段2の総量恒等式（帯を守る唯一の担保）。

### 2-9. 消耗品と耐久品を分ける（★弾薬にストックを当てない）

| 区分 | 財 | 需要の立ち方 |
|---|---|---|
| 消耗品（フロー） | 弾薬83・馬127・化学兵器133 | `MilitaryUpkeepScale × rate_g × 兵数 × warMult` ＝**現行式のまま**（1ビットも変えない） |
| 耐久品（ストック） | 陸＝小銃82・火砲81・自動車132・機関銃104・戦車122・飛行機130・戦闘機131／海＝軍艦86・汽船85・装甲艦105・弩級戦艦123 | `order_g = CloseRate_b×(A*_g − A_g)⁺ + decay_g×A_g` |

```
decay_g = ArmsWearRate
        + ArmsObsolescenceRate × Clamp((TechFrontier−TechLevel)/TechFrontier, 0, 1)   ← Diplomacy.cs:419 の既存の正規化技術差を再利用
        + ArmsWearRate × (warMult × mobilize − 1)                                      ← 戦闘消耗（下記）
```

**戦闘消耗が `MilitaryWarMult = 9.0` の行き場である。** 現行は `MilitaryScale` に9倍（内戦は18倍）を掛けて需要を作るが、新設計ではその9倍を「戦闘で装備が壊れる」に読み替える。定常状態の戦時発注は現行と厳密に同額（`9×ArmsWearRate×A* = 9×MilitaryScale×rate`）になり、違いは**過渡だけ**＝在庫が食い潰されて Fill が遅れて深く落ちる＝1914年の砲弾・装備不足がここで初めて表現される。加えて負けた軍は装備を失う（一方向ラチェットにならない）。

`(A*−A)⁺` は「負の小銃は発注できない」という物理であって二機構の切替ではない。既存の送電網発注 `GridBuildRate × Max(0, LastElecWant − GridCapacity) + GridReplaceRate × GridCapacity`（EconomyStep.cs:559 / 1249-1257）と**完全に同型**である。

### 2-10. 充足率（Fill）の意味を純化する — ★二重計上を作らない要

```
G_land^equip = Σ_{陸耐久} A_g·RefPrice_g / Σ_{陸耐久} u_g·RefPrice_g        … 装備できる兵数
G_sea        = Σ_{海耐久} A_g·RefPrice_g / Σ_{海耐久} v_g·RefPrice_g        … 実在する艦隊ゲージ
MilitaryEquipFill = Clamp( (G_land^equip / N_land^actual) × 消耗品の充足 , 0, 1)
MilitaryQualityFill / MilitaryTier3Fill / MilitaryAirFill = Clamp(該当世代のストック / 該当世代の原単位×実軍 , 0, 1)
```

**分母は「実際の軍が必要とする量」であって理想ではない。** 理想を分母にすると「軍が小さいこと」が二度罰される（`Power.Military` は既に兵数を含む）。理想は**発注**と**不足信号**だけを駆動し、`Power.Military` には一切入らない。

この定義の副産物が重要である：`A > A^req`（実軍の必要量を超える在庫）は Fill 上は報われないが、**徴兵で `N_land^actual` が跳ね上がった瞬間に Fill を支える**＝動員予備そのものになる。予備を積んだ国は動員即戦力、積まなかった国は装備なき群衆になる。案4が壊れた「e*>1 に報酬がない」問題は、ここで**動員のオプション価値**として解決する。

RefPrice（定数データ）で加重するので、市場価格の振れがゲージを揺らさない＝決定論と較正の安定に効く。

## 3. 兵科／陸海空の優先度の内生化

### 3-1. 陸と海

優先度レバーは置かない。`Need_land + Need_internal : Need_sea` の比がそのまま予算・発注・兵員配分になる。地理と経済の実データ（陸塊・距離・海路・港取扱高・植民地価値・緊張）だけで決まり、国別データも倍率も無い。

* 内陸国：`Projection` が陸続きで高い／`V_sea` が小さい → 陸偏重。
* 島嶼帝国：陸の到達に `SeaControl` が掛かって薄く、`V_sea` が世界最大 → 海偏重。
* 日本：開国前は誰の注意配分も届かず（緊張0＝φ止まり・距離減衰大）小さい。黒船＝緊張と海盆プレゼンスの発生で海の任務が立ち上がる。**台本なしで開国が軍の形を変える。**

### 3-2. 海軍シェアを実ストックから導出（断線③の根治）

```
G_land^gauge = N_land^actual / SoldiersPerMilitary
Power.NavalShare = G_sea / (G_land^gauge + G_sea)
```

* 現行 `navalTarget = Clamp(NavalShareBase + (外洋なら OceanBonus) + ColonyWeight×ColonyMass + EmphasisWeight×(NavalEmphasis−0.5), Min, Max)`（Diplomacy.cs:424）は**撤去**。`oceanOpen > 1e-9 ? Bonus : 0` という閾値分岐と Clamp の2つの折れ点が同時に消える。
* `NavalBuildRate = 0.3` の EMA（建艦の時間遅れ）は `ArmsCloseRateSea`（起工〜就役のリードタイム）が引き継ぐ＝**同じ物理を二重に持たない**ので `NavalBuildRate` は撤去。
* 艦隊摩耗（Diplomacy.cs:429-438）は `NavalShare` を削るのをやめ、**`A_sea` を削る**。削れた分は §2-9 の差分埋めが自動で発注する＝`NavalRepairUnits` / `NavalRepairPerLoss` は機構ごと撤去（同じ需要を二度立てない）。`NavalShareMin` の床も不要になる。
* `NavalEmphasis`（Government.cs:106・プレイヤーもAIも同じ入口）は**理想の枝按分への傾斜**として残す：`Need_sea ×= (0.5+NavalEmphasis)/(1.5−NavalEmphasis)` ではなく、按分側で `NavalEmphasisWeight×(NavalEmphasis−0.5)` を枝シェアに加えて再正規化する（正の量の比なので構成上 (0,1)＝クランプ不要）。**海軍偏重を上げれば軍艦が実際に発注される。**

### 3-3. 兵科（世代）の優先度＝残余カスケードの廃止

**⚠ 明言：既存の残余予算カスケード（EconomyStep.cs:592-621 の「基本→上位→tier3→空を前段の残余で買う」入れ子）は廃止する。**

理由は二つ。(a) それは作者が手で書いた固定優先順位＝**現行エンジンに残る最も明白な台本**であり設計①に反する。(b) 大軍国は基本段で予算を使い切り上位段が構造的にゼロ＝「軍拡すると近代化が退行する」という反史実を作る。

置換は**新しい優先度規則を書かない**方法で行う：

> **全発注ラインを同時に立て、予算が足りなければ一律比例で削る（`afford = Min(1, MilitaryBudget / 総発注額)`）。**

これで十分に史実の順序が出る。なぜなら発注量は**ギャップ駆動**だからである。基本装備が空の国は基本装備に巨大なギャップ発注を立て（rate 1.0/0.4）、機関銃・弩級戦艦のギャップは原単位が2桁小さい（rate 0.04/0.015）。基本が満たされれば基本の発注は置換分だけに縮み、上位段へ自然に金が回る。**カスケードの挙動が、優先度リストなしで発注則から創発する。** 新しい係数（CES の置換弾力性 σ 等）は一つも要らない。

## 4. モノ・ヒト・カネの需要がどう生まれるか（既存経路への流し込み先）

新しい市場も新しい財も新しい決済経路も作らない。

### モノ

* 耐久品の `order_g` と消耗品のフローを、既存の `militaryDemand[g]`（EconomyStep.cs:579-621 の代入先）へ積む。以降 `ration[] → clearPrice → revenue[gi] → region.StateSpent → World.Treasury -= r.StateSpent`（Simulation.cs:1356）は**一文も触らない**＝貨幣保存の既存証明がそのまま通る。
* 買えた分だけ `Region.ArmsStock[g] += got`（送電網 `GridCapacity += gridQ` と同型・EconomyStep.cs:1255）。毎月 `ArmsStock *= (1 − decay_g)`。
* 連鎖：弾薬←火薬/鉛/銅、火砲←鋼/工作、軍艦←帆布/木材/火砲。ここに**平時も消えない置換需要**と**軍拡時の差分需要**の二層が乗る。買えない分は `ration<1` として価格を押し上げ、鋼・石炭・工作機械で民需をクラウドアウトする＝「理想に届かない」ことが**物価として**表に出る（作者の設問への直答）。

### ヒト

* `Need_men` を **州の人的資源シェアで按分**して `Military.cs:63` の `desired` に入れる。
  `desired_r = Need_men × (poolSize_r + soldier_r) / Σ_r(poolSize_r + soldier_r)`
  ⚠ `Military.Step` は州ループ（Military.cs:43）であり、国家量をそのまま代入すると**軍が州数倍**になる（清22州・オスマン14州・露13州）。按分は必須。
* 徴募・除隊は既存 `DrawFromPool` / `DischargeToPool` / `MoveCohort`（Military.cs:115-223）を無改造で通す＝人口保存・「月にプールの半分」「働き盛り男性のみ」の物理上限も既存のまま。**人為的な上限（`MaxSoldierFraction`）は不要になるので撤去する。**
* 戦時徴兵 `desired = Max(desired, conscriptFrac × manpower)`（Military.cs:98）は**温存する**。ここには戦争規模スケール（外12）・国民意識ゲート・#106総動員・徴兵遺恨（`ConscriptGrievanceRate`＝清の不満が抜けると覇権化するための対称機構）がぶら下がっており、支払率の切替では代替できない（案4の当該提案は却下）。平時＝任務、戦時＝人口という二層構造を壊さない。
* 兵が抜ければ `EconomyStep.cs:324-337` の労働係数（`work/InitialWork`）が締まって産出が落ちる＝背伸びした動員が自分の経済を削る。

### カネ

* 装備：`MilitaryBudget`（Simulation.cs:1246-1252）の経路は無改造。請求は `Fiscal.cs:153-164` の `militaryClaim` に立ち、福祉・インフラの `surplus` を押す＝ guns vs butter は既存のまま。
* 給与：`SoldierPayBudget`（Simulation.cs:1319）の分子を**実兵数から理想兵数へ**変える。
  `SoldierPayBudget = Min(Max(0,Treasury), Need_men_r × civWage × SoldierPayMult)`
  現行は `mpNeed = 実兵数`（EconomyStep.cs:670）と予算がともに実兵数比例で**兵数が約分により消える**（Coefficients.cs:1305-1308 に既記録の欠陥）。理想基準にすると `payRaw ≈ Need_men / 実兵数` となり、**理想より膨れた軍は必ず食えない**＝満足度↓→即応度↓、さらに脱走で縮む。均衡を式で与えず経済との釣り合いから出す、が上限下限なしで成立する。
  ⚠ 給与は現行も `militaryClaim` の外（国庫直引き）である。**装備予算に統合しない**＝二重計上を作らない（案4の該当提案は却下）。
* 努力水準：`effort = 発注必要額 / Region.MilitaryBudgetCeiling`（**切る前の上限側**から取る。S3a 点火後 `MilitaryBudget/estCost ≤ 1` が恒真になるため実支出側から信号を取ってはならない＝配線済みの `MilitaryBudgetCeiling`（Model.cs:354-355）を使う）。
  `MilitarySpendingTarget = effort/(1+effort)`（有理飽和・クランプなし）を **Government/Policy 層に1本だけ**置き、`Government.cs:105` の `Move`（利益集団の抵抗・政体の床・5%刻み）を通す。AI（SelfPlay）もプレイヤー助言も同じ関数を呼ぶ＝設計⑤。`SelfPlay.cs:354/412` の離散ジャンプ 0.25↔0.7（＝プレイヤーには存在しない折れ点）を撤去する。

## 5. 不足したとき何が起きるか

不足は3つの別々の顔で出る。新しい罰則関数も新しいゲージも作らず、既存の下流へ流す。

| 不足 | 直接の現れ | 既存の下流 |
|---|---|---|
| **モノ**（金はあるが鋼がない） | `ration<1` → ストックが積み上がらない → Fill↓ | `MilitaryReadiness`（Military.cs:109）→ ①`Power.Military`（Diplomacy.cs:420）②圧政 `CoercionTarget`（Government.cs:101）③植民地保持（Colonial.cs:191）④`CanInvade` の兵力ゲート（World.cs:855）⑤軍の忠誠（CrownParliament.cs:55） |
| **ヒト**（人が出せない） | `DrawFromPool` の物理で届かない・低国民意識で動員が浅い | 労働供給が締まり産出↓・食料↓＝小国の背伸びが自分の経済を削る |
| **カネ**（理想に予算が届かない） | `effort` が上がり `militaryClaim` が余剰を食う → 福祉・インフラ停止 → 赤字・借入・増税 → 政治的緊張 | 既存の財政・政治経路そのまま |

連鎖の例（初めて閉じる回路）：海の任務が大きいのに買えない → `A_sea` が薄い → `NavalShare`↓ → `NavalPower`↓ → `SeaControl`↓ → 通商破壊で交易を拿捕され → 交易収入が減り財政が悪化 → さらに買えない。同時に **`Projection` の `SeaControl` 経由で自国への陸の脅威が上がる**＝制海権を失った島国は本土に大陸軍を要する（英の「青天の霹靂」論争）。

> ⚠ 既知の性質として明記する：`Projection` は海越え時に `SeaControl(j,i)=NavalPower_j/(NavalPower_j+NavalPower_i)` を掛ける（Diplomacy.cs:1944）ため、**海の枝についてのみ自国の力が Need に間接的に入る**。これは値域が (0,1) に有界なので発散はしないが、島国が「大海軍・小陸軍」と「無海軍・大陸軍」の二安定になりうる。通商保護項（自国の海軍を参照しない外生アンカー）が正しい basin へ引く設計になっているが、**段3・段4の測定項目に英の海軍シェア時系列を必ず含める**。陸の枝と兵員の枝は自国の力を一切参照しない（死のスパイラルの禁止則は陸で厳密に守る）。

## 7. 既定0での厳密恒等の証明手順

### 7-1. 構文レベル

## 10. 未決（作者裁定が要る点）

1. **段6（`Power.Military` の枝合成）を実施するか。** 実施しないと「艦を買っても強くならない」（`Military` は兵数駆動・`NavalPower = Military × NavalShare`）が残り、英の大海軍が戦力として意味を持たない。実施すると `ThreatExcess` / `RankOf` / `CanInvade` / 押し合い / `SelfPlay` の生存効用 / 忠実度の帯に同時に波及する。**血の量が最大の一手。**
2. **給与予算を歳入シェアの独立ラインにするか。** 本設計は「理想兵数 × civWage」を国庫からの直引きのまま採る（最小改修で約分バグを解消）。真の予算線（`SoldierPayShare × LastRevenue`）にすると `Fiscal` の請求構造を作り替える必要があり、係数が1本増える。
3. **脱走（`SoldierDesertionRate`）を入れるか。** 入れると均衡兵数が「予算/賃金」に滑らかに着地する（クランプなしの負帰還）が、兵力の時系列に新しい動学が入る。
4. **忠実度ハーネスに軍の軸を足すか。** 現行 `HistoricalReference.cs` の6次元（政体・法・人口成長・列強・GDP順位・領土）は**兵力も海軍も装備も測らない**。本改修が狙う4つの史実（英の小陸軍・大海軍／露の装備不足／普の動員／清の非変換）は現行の帯では検証不能で、`armyshape` プローブの目視だけが担保になる。軸を足すか、プローブを恒久の合否条件にするか。
5. **`NavalEmphasis` スライダーを残すか。** 枝配分が任務から自動で決まるため、UI最小主義（自動化できるレバーは置かない）に従えば撤去候補。残す場合は「理想からの意図的な偏差」という位置づけになる。
6. **内的秩序項と圧政（`CoercionTarget = 兵数 × 即応度 × CoercionPerSoldier`・Government.cs:101）の関係。** 本設計の判断は「二重計上ではない」（不穏 → 守備任務 → 兵数 → 圧政、という一本の因果の各段）だが、`CoercionPerSoldier` は現行の兵数水準の下で較正された値であり、兵数の由来が人口から任務へ変わる以上、**再較正が要る**。
7. **既存タスク #9「徴兵法を3値化（志願制／選抜徴兵／国民皆兵）」との実施順。** 本設計は戦時徴兵経路を温存するので衝突しないが、`conscriptFrac` の意味を触るため、どちらを先に点火するかの指定が要る。

## 11. ⚠ 明言事項（設問への直答）

### 11-1. 残余予算カスケードは **廃止する**

`EconomyStep.cs:592-621` の入れ子（基本→上位→tier3→空を前段の残余で買う）を撤去し、全発注ラインを同時に立てて予算不足時は一律比例で削る。優先順位のリストは書かない。史実の順序（貧国は小銃、富国は機関銃と弩級艦）は**発注量がギャップ駆動であること**から創発する（§3-3）。

### 11-2. `MilitaryBudgetNeedCapped = 1`（予算＝min(上限, 必要額)）と **両立する**

両立の条件は「**必要額が予算に依存しないこと**」であり、本設計の発注則はそれを満たす：

```
必要額 = Σ_g [ CloseRate_b × (A*_g − A_g)⁺ + decay_g × A_g ] × Price_g   +   消耗品コスト
```

* `A*` は理想（他国の力・自国の人口・海上価値・技術から決まる）、`A` は前月末のストック、`CloseRate` は建造リードタイムの物理。**どこにも予算が入らない**ので `min(上限, 必要額)` は自己参照にならず、S3a はそのまま生きる。
* 「余裕があれば増やす」型の信号が S3a 下で死ぬ問題は、**信号を上限側から取る**ことで回避する：`ArmsEffort = 必要額 / Region.MilitaryBudgetCeiling`（切る前の額・Model.cs:354-355 に配線済み）。実支出側（`MilitaryBudget/estCost ≤ 1` が恒真）からは取らない。
* `Fiscal.cs:158-164` の `militaryClaim` も**同じ新定義の必要額**で切る（`EconomyStep.MilitaryProcurementNeed` の中身だけを差し替え、呼び出し2箇所＝`Simulation.cs:1251` と `Fiscal.cs:162` が**必ず同じ分岐を取ることを静的に確認**する。片方だけ新定義になると請求と実支出がずれ、理由なく福祉が削られる＝S3a のときと同じ罠）。

### 11-3. 接いだ部品が折れ点・二重計上を生まないことの確認

| 接いだ部品 | 折れ点の確認 | 二重計上の確認 |
