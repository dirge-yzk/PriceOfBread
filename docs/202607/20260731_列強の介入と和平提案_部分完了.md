## 検証で見つかった問題

【総括】器（S1〜S7）と恒等性の論証は概ね正しい。docの前提が古い5点（stalemate第3経路・MinTruceYears=4・SideStrengthの非実在・ConcertReparationRestraint・行番号ずれ）の指摘も全て現物と一致した。しかし**点火1・点火2の中核の2式が数学的に背反**しており、仕様どおり実装すると機構が発火しない（発火経路が開いた場合は和平が一度も成立しない）。よって sound=false。

━━━━━━━━━━━━━━━━━━━━
■ 致命1：ExpansionWill ゲートが構造的に閉じている（点火0の Probe が必ず 0 を返す）
━━━━━━━━━━━━━━━━━━━━
仕様の `InterventionWillCost` ＝ `Math.Max(ColonizeWillCost(g, war.A, c), ColonizeWillCost(g, war.B, c))`。現物の中身（Diplomacy.cs:1303-1312）は

  willCost = InvadeWillBase(8.0) + InvadeWillPerMilitary(2.0) × target.Military
  willCost /= 1.0 + ColonizeWillSuperiorityDiscount(1.0) × max(0, ColonizeForce/(ColonizeSubmitRatio(3.0)×target.Military) − 1)

一方 `World.ExpansionWill` の上限は **ExpansionWillCap = 10.0**（Coefficients.cs:763）。

割引が効かないことは証明できる：
 ・`ColonizeForce = great.LandPower × Math.Max(0.05, Projection) × ExpeditionLift`（Diplomacy.cs:1296-1297）
 ・`LandPower = Military × (1 − NavalShare) ≤ Military`（Diplomacy.cs:18）
 ・`Projection` は `decay = 1/(1+…) ≤ 1` に `SeaControl ≤ 1` を掛けるだけ（Diplomacy.cs:1983-1986）＝ **≤ 1.0**
 ・`ExpeditionLift ≤ 1.0`（Diplomacy.cs:1290-1293）
 ⇒ `ColonizeForce(g, X) ≤ g.Military`。
 ここで仕様の動機ゲートは `SideMilitary(winner, g) ≥ 1.0 × SideMilitary(g, winner)`、同盟なしなら `winner.Military ≥ g.Military ≥ ColonizeForce(g, winner)`。
 ⇒ `ColonizeForce/(3×winner.Military) ≤ 1/3 < 1` ⇒ **割引は厳密に 0**。

したがって勝勢側に対する代価は常に `8 + 2 × winner.Military`。上限10を超えないのは `winner.Military ≤ 1.0` のときだけ。さらに仕様は2国の **max** を取るのでもっと厳しい。

現物の裏付け：Coefficients.cs:1302 のコメントが「**willCost=8+2M が ExpansionWillCap=10 とほぼ同額＝標的軍M>1の実国が恒久不能だった**」と明記しており、割引はまさにその救済として入れられたもの。その割引が動機ゲートによって恒久的に殺される。world.json の初期軍もこれを裏付ける（英4.5／普3.6／墺2.6／露2.0／西2.0／仏1.8／オスマン1.5／日1.2）。

⇒ **動機ゲート（強い勝者を選ぶ）と代価ゲート（強い勝者を弾く）が背反**。点火0の `InterventionChances` は事実上 0 になる。しかも新設8係数のどれも代価に触れないので、仕様が用意した調整ノブ（WarMinMonths／CooldownYears／MotiveRatio）では**回復不能**。MotiveRatio を 0 にしても代価ゲートだけで死ぬ。

付随：割引が恒等的に 0 になるということは、実効コストは `8 + 2×max(M)` ＝ **軍規模のみの関数で、距離が1ミリも入らない**。doc §3-2 の「代価は距離と相手の規模の関数にする」という要件を、仕様の式は満たしていない（距離は割引経由でしか入らないため）。

━━━━━━━━━━━━━━━━━━━━
■ 致命2：応諾式が動機式と背反する（「両方応諾」＝白紙講和が原理的に起きない）
━━━━━━━━━━━━━━━━━━━━
仕様の応諾： `SideMilitary(g, X, c) >= InterventionSubmitRatio(3.0) × X.Military`
仕様の動機： `SideMilitary(winner, g, c) >= InterventionMotiveRatio(1.0) × SideMilitary(g, winner, c)`

同盟がない一般ケース（`SideMilitary` は Diplomacy.cs:843-853、同盟がなければ自軍のみ）：
 動機 ⇒ M_winner ≥ M_g
 勝者の応諾 ⇒ M_g ≥ 3 × M_winner ≥ 3 × M_g ⇒ M_g ≤ 0 ＝ **矛盾**

⇒ 勝勢側は決して応じない。仕様の決着表で「両方応諾→ConcludeWar」は到達不能枝、常に「片方拒否」に落ちる。
 ・点火1（RefusalWar=0）＝ 戦争は1本も止まらず、`ExpansionWill` 消費と `InterventionRivalTension` だけが残る純粋な浪費。仕様の bandRisk 予測「戦争が短くなる→exact/near が下がる」は**符号ごと外れる**（実際は植民地化原資が枯れ、列強間緊張が上がる＝戦争が増える方向）。
 ・点火2（RefusalWar=1）＝ **毎回必ず**「自分より強い勝勢側へ StartWar」。`WarChainMaxDepth=2`（Coefficients.cs:979・live）で連鎖するので、硬性ゲート（破綻・デッドロック）直撃の最悪配置になる。
