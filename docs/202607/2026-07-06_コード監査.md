## A. 輸出利潤経路（財15）— 有効化ブロッカー（休眠既定＝現行ビルドは無害）

> 共通原因：`PayExportToProducers` が **保存則が監視するフィールド**（`Market.LastSold` と生産者pop `Savings`）を、対応する台帳更新なしに書き換える。既定 `ExportRevenueToProducers = 0.0` では全額が `netFlow` 経由になり現行と厳密一致するため潜在化している（`Coefficients.cs:941`）。**3件は1回の修正でまとめて解消する。**

### A-1 【crash / high・CONFIRMED】輸出数量が `LastSold` と `LastExport` に二重計上され GoodsBalance が throw
- 箇所: `Successor.SimCore/InternationalMarket.cs:224`（=328）／単国版 `Successor.SimCore/Trade.cs:78–81`（=`:144`）
- 内容: 輸出で `m.Stock -= q; m.LastExport += q` と一度だけ在庫を減らすが、係数>0時に `PayExportToProducers` が**同じ q** を `m.LastSold += q` する。`GoodsBalance`（`Invariants.cs:108`）は `stock == prevStock + produced + import − sold − export` を要求するため、q が「販売」と「輸出」で二重に引かれ、在庫は一度しか減っていないので許容 `1e-6` を超えて `InvariantViolationException`。
- 再現: `Coefficients.ExportRevenueToProducers = 0.05`（>1e-12なら何でも）にし、国内生産者（有効な `OwnerPopIndex`）を持つ財を輸出する任意シナリオ。純輸出が発生した最初の月次検査でthrow。
- 修正案: 輸出数量を `LastSold` に足さない。輸出産業の採算（`SmoothedMargin`）へは GoodsBalance恒等式に使われない専用フィールド（例 `LastExportSold` / `s.LastRevenue`）で反映するか、`m.LastSold += qty` 行自体を撤去。`InternationalMarket.cs:328` と `Trade.cs:144` の両方に適用。

### A-2 【correctness / high・CONFIRMED】輸出→生産者の金が `CumulativeTradeFlow` に記録されず MoneyConservation が throw（多国版）
- 箇所: `Successor.SimCore/InternationalMarket.cs:227`（配分は `:325`、`Apply` は `:385`）
- 内容: 輸出で `toProducers` の**新規対外マネー**を生産者popの `Savings` に加える（`:325`）一方、`netFlow` には `revenue − toProducers` しか積まない（`:231`）。`Apply` は `w.CumulativeTradeFlow += netFlow`（`:385`）。結果 `BaseMoney` は満額 `revenue` 増える一方、台帳は `revenue − toProducers` しか増えず、`MoneyConservation`（`Invariants.cs:32`）が `toProducers` ぶん過少で throw。
- 再現: 多国＋`ExportRevenueToProducers > 0`。純輸出する国が未追跡マネーを蓄積 → `MultiNationTests.cs:57/154` の保存テストが落ち、稼働中の月次不変条件も throw。
- 修正案: pop配分の分割とは独立に**満額の対外流入を台帳へ**。国別 `flowLedger[i] += revenue`（満額）を `CumulativeTradeFlow` に、`Apply` へは `flowLedger[i] − toProducersTotal[i]` のみ渡す。

### A-3 【correctness / high・CONFIRMED】同上の単国版（Trade.cs）
- 箇所: `Successor.SimCore/Trade.cs:79`（配分は `:142`、台帳は `:88`）
- 内容: A-2 と同型。`PayExportToProducers` が `toProducers` を pop貯蓄へ直接加算（`:142`）するが、`netFlow += revenue − toProducers`（`:82`）→ `CumulativeTradeFlow += netFlow`（`:88`）。`BaseMoney` は満額 `revenue` 増、台帳は `revenue − toProducers` 増で、差 `toProducers` ぶん `MoneyConservation` が throw。コメント「生産者へ直接渡した分を差し引く＝保存」は誤り：pop配分から差し引くのは正しいが、**台帳は満額 revenue を対外流入として記録すべき**。
- 再現: 単国・`TradeEnabled`・`ExportRevenueToProducers = 0.5`。revenue=100→生産者50・netFlow+50・台帳+50だが `BaseMoney`+100 → 「基礎貨幣が想定…へ乖離」で throw。
- 修正案: `flowLedger += revenue`（満額）を台帳へ、`ApplyNet` へは `revenue − toProducers` のみ。

## C. Runner CLI 衛生

### C-1 【crash+resource-io / low・CONFIRMED（2件統合）】throwする culture依存の引数パース
- 箇所: `Successor.Runner/Program.cs:1458`（`double.Parse`）ほか多数の `int.Parse`/`ulong.Parse`（1484/1457/788、wages/jobs/services/civilwar/score、hangtest/deadend/test8/monitor、trace-prod）
- 内容: (1) `selfplay-batch` の金利上書きが ambient `CurrentCulture` の `double.Parse(args[2])`。csproj に `<InvariantGlobalization>` 無し・起動時に `CultureInfo` 未設定のため、de-DE/fr-FR等では `double.Parse("0.05")` が `FormatException`（try/catch無し）または誤パース。加えて全レポート整形（F2/P0/N0補間）がロケール依存の区切りを出すため、**シミュは決定論なのに chronicle/selfplay 出力がロケール間でバイト非再現**。(2) 上記多数の `Parse` が throw版で、タイプミスで生スタックトレース。一方 chronicle(61)/britcw(230)/integration(320)/landprobe(399)/pricelevel(442) は `TryParse`+既定値で正しく、これらは見落とし。
- 再現: de-DE/fr-FR で `selfplay-batch 30 0.05` → 未処理 `FormatException`。`selfplay xyz` → `ulong.Parse("xyz")` で throw（`chronicle xyz` は既定へフォールバックするのに）。`chronicle` の出力が `,` 小数になり en-US 参照との diff 再現が壊れる。
- 修正案: `Program.cs` 冒頭で `CultureInfo.CurrentCulture/DefaultThreadCurrentCulture = InvariantCulture`（または csproj に `<InvariantGlobalization>true</InvariantGlobalization>`）。throw版 `Parse` を chronicle/integration と同じ `TryParse`+既定へ統一し、レポート整形にも `InvariantCulture`/`NumberStyles` を渡す。

## D. 決定性 / 数値の潜在ハザード

### D-1 【determinism / low・PLAUSIBLE】Power-rank ソートのタイブレーク欠落 → 同点で列強/中堅がランタイム依存で入れ替わり
- 箇所: `Successor.SimCore/Diplomacy.cs:165`
- 内容: `real.Sort((a,b) => b.S.CompareTo(a.S))` は `NationalScore` のみで並べ、index で `PowerRank` を付与。`List<T>.Sort` は**不安定** introsort。ランク境界（`GreatPowerCount-1` と `GreatPowerCount`）を跨いで同点があると、どちらが列強/中堅かがソートのタイ処理次第＝決定的キー不在。`PowerRank` は `RankOf` 経由で敵対/侮辱/同盟（DiplomacyAI 699/709/726）や `TryAiColonize` の対象選定を左右するため、入れ替わると戦争・同盟・植民地化の履歴が変わる。同一バイナリでは再現するが、**将来の.NETランタイムでタイ順が変わると同一シードで別履歴＝selfplay再現/較正が壊れる**。コードは他所で同種のタイブレークを既に付けている（`Diplomacy.cs:1023` `CompareOrdinal`）のにここだけ欠落。
- 修正案: `real.Sort((a,b) => { int c = b.S.CompareTo(a.S); return c != 0 ? c : a.P.Id.CompareTo(b.P.Id); });`

### D-2 【crash / low・PLAUSIBLE】無銀行シナリオの負貯蓄バックストップが `Savings < 0` を残し NonNegativeBounds が throw
- 箇所: `Successor.SimCore/Simulation.cs:1461`（`BackstopNegativeSavings` の pre-modern/no-Bank枝）
- 内容: no-Bank枝は各負貯蓄popを**最も裕福な他pop1つ**だけで補填し `cover = Math.Min(-p.Savings, rich.Savings)`。赤字が最富peerの全 `Savings` を超えると `cover` は頭打ちで、ループ後も `p.Savings` は負のまま。直後の `CheckInvariants` → `NonNegativeBounds`（`Invariants.cs:84–90`）が `Savings<0` で throw。Bank枝（popを0にし不足を貸出計上、`BaseMoney`保存）と違い、no-Bank枝には非負保証のフォールバックが無い。**到達は `CreditEnabled=false`（テスト/前近代）世界のみ**、実 Nation ゲームは安全な Bank枝。
- 修正案: 最富peer移転後の残り負を 0 でクランプし計上（全正貯蓄popから比例徴収して補填、または最終 `Math.Max(0, p.Savings)` 床＋不足を診断台帳へ）。

## E. 性能 / デッドコード

### E-1 【performance / low・CONFIRMED】MonthSettle が有効地域ごとに `dip.Wars.Any(closure)` を再評価しデリゲート+列挙子を毎回確保
- 箇所: `Successor.SimCore/Simulation.cs:1048`（同型が `:1159` にも）
- 内容: `MonthSettle` の有効地域ループ内で `atWar = dip.Wars.Any(war => war.A == sp || war.B == sp)`。ラムダが `sp` を捕捉するため評価ごとにクロージャ＋List列挙子を確保、しかも `sp`(=`World.SelfPower`)依存で `r` 非依存＝同一国の全地域で同じ結果。**国スコープなのでループ前に一度だけ算出して使い回すべき**。
- 修正案: ループ前に `bool atWarNation = ... dip.Wars.Any(w => w.A==sp||w.B==sp)`（デリゲート回避なら素の for）を一度算出し、ループ内は `r.AtWar = atWarNation`。`:1159` でも再利用。

### E-2 【dead-incomplete / low・CONFIRMED】現職バイアスが恒久デッド：`Winner()` 読取直前に `QuartersSinceElection` を0リセット
- 箇所: `Successor.SimCore/Parliament.cs:29`
- 内容: 選挙tickで `w.QuartersSinceElection = 0;`（`:29`）の直後に `Winner(w)`（`:30`）。`Winner()` は `bias = IncumbencyBias * Math.Min(1.0, QuartersSinceElection / Max(1, ElectionIntervalQuarters))`（`:96`）。直前に0化されるため `Min()` 項が常に0＝`bias` 恒常0で `IncumbencyBias` は完全に無効。`Winner()` はここからしか呼ばれず、現職バイアス機能は非機能デッドコード。
- 修正案: リセット前に勝者算出（`w.GoverningParty = (int)Winner(w); w.QuartersSinceElection = 0;` の順）、または経過数を `Winner()` へ引数で渡す。

### E-3 【dead-incomplete / low・CONFIRMED】`RefreshProduction` の未使用 `activeRegions` ループ
- 箇所: `Successor.App/ViewModels/GameViewModel.Production.cs:238`
- 内容: `int activeRegions = 0; foreach (var rg in _player.Regions) if (rg.State == RegionState.Active) activeRegions++;` を算出するが以後どこでも未読。削除ロジックの残骸で、生産グラフ再構築のたびに全地域を1周無駄に走査。
- 修正案: 宣言とループを削除。
