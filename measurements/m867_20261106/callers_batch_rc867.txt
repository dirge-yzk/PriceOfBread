■ (867) 追記
- rc=1 は prep の失敗：ident.sh の腕 a・b は `prep && run` の形で、prep が失敗すると run まで行かず、印には prep の rc（1 など）が `rc=1 …` として残るか、印が書かれない。新しい batch.sh の run は 1 を返さない（0・2・3・4 だけ）ので、印の rc=1 は run の物ではなく prep の失敗か旧の木の基準（ハーネス不合格を 1 で返した (860) の前の batch.sh）。ident_check.py の受け入れ `^rc=(0|1|2) ` は 1 を通すが、prep の失敗なら出力が欠けて、下の突き合わせ（成績表の有無・SOURCE-HASH）で未了に落ちる。ident_check.py:588〜589 の注はこの意味に直した（注だけ・AST は直す前と同一）。
- measure.sh の BATCHFAIL の後の残り物（記録だけ・直さない）：ビルドの失敗で終わった走りは、measure.sh が先に書いた .manifest が新しく、前の走りの .cost が古いまま残る（成績表は batch.sh が走る前に消すので無い）。合流や担当が .manifest と .cost を組で読むときは、成績表の有無（BATCHFAIL の行・ms_<腕>.log の〈measure rc=…〉）を先に見る。
