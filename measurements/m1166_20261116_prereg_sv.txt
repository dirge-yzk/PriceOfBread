■ 指示から外した所（3 つ・理由つき）
1. 所得の読みの時点：指示の〈RecruitWage(r,c,last:false)〉ではなく **last:true** を使う。理由＝兵の給与は月の決済（Simulation.MonthSettle :1753）で、その月の EconomyStep.Run が EarnedPerMonth を 0 に戻す前（:772 で LastEarnedPerMonth へ写す前）の値＝前の月の所得から組まれる。社会移動（QuarterEnd :1613）は四半期の最後の月の Run の後に走る＝その時点の LastEarnedPerMonth が、最後の月に大きさ＞0 の兵が受け取った給与の入力そのもの。last:false はその月の所得＝1 か月ずれる。徴兵の国は :1754 と同じく keep（頭数あたり）を使う（w.ConscriptionLaw ≧ Selective）。
2. 上の門：指示の〈志願の国の兵の総数÷定員（admrule_s soldierK÷seatsK）の種ごとの最大 ≦ ヌル腕の最大×(1＋2×(幅−1))〉は判別の力が無い（紙・下）：M 13.69・N1 13.18・N2 67.25（keep_1150 のヌル腕）＝幅 5.10＝上限 約 619。清の志願の兵が既に定員の 8〜13 倍（定員の下がりを平時の復員がゆっくり追う）＝植民地の州の 0 からの埋まりはこの比を動かさない＝何もしない実装も間違った実装も通る。→ 記録へ下げ、上の門は〈形に固有の誤り＝州の空きを超えて募る量〉を新しい計器 soldiervac_s で読む（G2）。
3. 働いた門の母集合：空きが立ちえない行（州の届き nowRuleDelivery＝0 か表に無い・国の定員 seatsK＝0）は旗 1 でも 0 が正しい＝旗 0 と旗 1 の両方から同じ定義で除く（旗 0 の 34,673 のうち 4,015 行）。除かないと床 4,015 が 1/10＝3,467 を超え、正しい実装でも落ちる門になる。除く前の数は記録。
